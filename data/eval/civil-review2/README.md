# PATCH-014 — 민법 DEV35 검색 평가 기준 v1

## 자료와 상태

2026-09-10 리뷰2 수정본을 바탕으로 확정한 **공개 개발용 조 단위 검색 진단 기준**이다. 법적 답변 채점, 독립 평가, 검색 순위 강제 규칙이 아니다. 구현 담당이 기존 코드·실패 결과를 본 뒤 작성한 질문이며 독립성을 주장하지 않는다.

- [검토 자료 안내](review/00_검토결과_안내.md): 수령한 문서 5개와 JSON 1개. 문항·법적 검토 내용은 변경하지 않았다.
- [검색 목표표](retrieval-targets.md), [구조화 검색 기준](retrieval-plan.json): 필수 조문 목표와 조건부·보조 근거를 분리한 파생 자료.
- [해시 목록](manifest.json): 수령 바이트와 공유 사본 해시를 구분한다. 공유 사본은 UTF-8/LF 및 작성자 장비의 절대 경로를 상대 경로로만 정리했다. 원본 바이트와 같다고 주장하지 않는다. 외부 수령 파일은 수정하지 않았다.
- [원래 질문 초안](../civil-selection-review-draft.json)은 바이트와 pending 주석을 그대로 보존한다. 유효한 검토 결과는 공유 사본의 `review2`이며 `original`의 pending을 새 검토 상태로 오인하지 않는다.

리뷰1 원문은 이번 수령 묶음에 없다. 리뷰1 대비 변경 내용은 리뷰2 작성자의 기록이며, 이번 패치가 리뷰1 원문까지 독립 대조한 것은 아니다. 리뷰2의 법령 판본·판례 검증 기록을 수용하되 법률 전체를 다시 독립 검증한 것으로 표현하지 않는다. Lawbot 검색 실행 및 제품 검색 측정은 수행하지 않았다.

## 입력과 집계 대상

입력은 `question + "\n\n" + context` 그대로다. 정답, 근거 ID, 포커스 조문, 제안 역할은 검색기에 전달하지 않는다. 질문 단독 실행은 탐색 기록으로만 남기며 이 정답으로 채점하지 않는다. 기존 DEV200 입력·정답·분모는 별도 유지한다.

| 집계 | n | 처리 |
|---|---:|---|
| required_law | 29 | 기본 조문 검색 점수의 고정 모집단. 사실 부족으로 조건 설명이 필요한 문항도 포함 |
| scope_provisional | 1 | CIV-DRAFT-020. 주차장 지원 범위 미확정. 동일한 검색 진단을 따로 보고하되 29문항 점수에 합산하지 않음 |
| diagnostic_only | 5 | CIV-DRAFT-003·011·024·029·032. 현재 필수 법령 목표 없음. 검색 결과만 보존하며 성공·실패·검색 금지로 자동 판정하지 않음 |

35문항 전체 목록을 항상 보고한다. 범위 미확정 1건과 목표 없는 5건을 누락시키거나, 29문항 점수를 35문항 전체 성능으로 표현하지 않는다. 기기 질문의 지원 여부도 미확정이다. 지원 범위가 정해지면 기준을 새 버전으로 만들고 기존 결과를 보존한다.

## 근거에서 검색 목표로 변환

`category=필수`, `activation_condition=항상`이며 `input_only`가 아닌 그룹만 기본 목표다. 리뷰2의 조건부·보조 그룹은 그대로 보존하며 기본 점수에는 넣지 않는다. LLM이 더 긴 설명을 했다는 이유로 검색 평가 분모나 목표를 사후 변경하지 않는다.

- 008: 제626조 제2항의 기본 상환 요건만 필수. 제380조와 법원 상환기간 설명은 조건부.
- 015: 제629조 관련 명제 필수. 제618조는 조건부이며 두 조문의 AND 검색을 요구하지 않는다.
- 028: 민법 제640조와 상가법 제2조·제10조의8 모두 목표. 상가를 범위 밖으로 처리하지 않는다.
- 033: 제626조·제627조 모두 목표. 하나만 찾으면 전체 충족이 아니다.
- 034: 제626조의 두 항이 근거지만 조 단위에서는 같은 조문 하나다. 한 번 검색했다고 두 항의 명제 충족을 입증한 것은 아니다.

조문 목표는 출처의 법령명과 조번호 전체를 사용한다. 비교 시 Unicode NFC와 공백 제거만 허용하고 조의 가지번호는 보존한다. 예: `상가건물 임대차보호법-제10조의8`과 공백 없는 동일 법령명을 일치시킬 수 있지만 민법 제114조와 형법 제114조는 다르다. 부분 문자열이나 숫자만으로 비교하지 않는다.

## PATCH-015에서 적용할 계산식

각 문항 i의 모든 필수 그룹에서 얻은 **고유 조문 집합 T_i**와, 반환된 법령 결과의 상위 k개 위치에 있는 조문 집합 R_i(k)를 비교한다(k=3,5). 법령 채널의 반환 순서를 그대로 사용하며 필터링·재정렬·중복 제거로 뒤의 문서를 당기지 않는다. 메타데이터에서 식별하지 못하는 결과는 불일치로 남기고 원문을 보존한다.

- `AnyHit@k(i) = 1[T_i ∩ R_i(k) ≠ ∅]`: 필수 조문 중 하나라도 찾음.
- `AllRequired@k(i) = 1[T_i ⊆ R_i(k)]`: 필수 조문을 모두 찾음. **기본 보고 지표**.
- 전체 29문항 지표 = 각 문항 값의 합 / 29. 필요한 조문이 DB에 없어도 이 분모에는 포함한다.
- 검색기 자체 진단은 **모든 목표 조문을 보유한 문항 집합 B**에 대해 별도로 합 / |B|를 보고한다. |B|=0이면 N/A. 보유 여부는 검색 결과가 아닌 실행 코퍼스의 실제 조문 목록으로 확인한다. 조문 내용·시행판본의 충분성은 별도 한계로 남긴다.
- 범위 미확정 020은 위 계산을 n=1로 별도 표시한다. 목표가 없는 5개에는 빈 집합의 부분집합 성질을 이용한 자동 성공을 부여하지 않는다.

동일 입력·순위에서 AnyHit@3 ≤ AnyHit@5, AllRequired@3 ≤ AllRequired@5, AllRequired@k ≤ AnyHit@k여야 한다. 새 검색 실행으로 얻은 TOP3와 TOP5를 섞지 않고 같은 저장 순위에서 자른다. 점수는 조문 ID 대리 지표이며 답변 정확성·항호목 충족·판례 검색 점수가 아니다.

대체 공식 근거 수용은 법적 검토 정책에 남아 있으나 현재 조문 ID 기준에서 자동 OR 처리하지 않는다. 다른 근거가 적절해 보이면 `대체 근거 검토 필요`로 기록하고 원래 점수를 보존한다. 동등성 확인 후 새 기준 버전에서 재계산하며 결과에 맞춰 조용히 정답을 바꾸지 않는다.

## 실행 시 남길 진단

문항별 필수 목표 보유 목록, 최종 법령 순위, AnyHit/AllRequired, 미검색 조문을 남긴다. 후보 단계가 계측된 경우에만 후보 누락과 최종 선택 탈락을 구분한다. 계측하지 못하면 `후보 단계 미확인`으로 쓰며 최종 실패만으로 후보 실패를 추정하지 않는다. 일부 데이터 부족과 일부 검색 실패가 함께 있으면 모두 기록한다.

PATCH-015는 실행 직전 코드 SHA·dirty 상태·코퍼스 파일 해시·모델·검색 설정·환경·이 기준 및 검토 자료 해시를 고정한다. 기존 DEV200과 신규 35문항 결과는 따로 보고한다. 실측 전에 합격선·개선률을 만들어 넣지 않는다. 이번 기준은 진단용이며 제품 변경 승인 기준이 아니다.

## 검증 범위

35개 고유 ID, 초안과 original 전체 필드 일치, 필수 그룹 활성 조건, 출처 참조, 출처 전체 조문명과 목표 일치, 29/1/5 분류, 자료 해시와 내부 링크를 확인한다. 전체 제품 테스트·검색·LLM 평가는 자료만 변경하는 PATCH-014에서 실행하지 않는다.
