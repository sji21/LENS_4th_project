# 개발용 100문항 v2 — 기본 법령 조 단위 진단

기존 질문·제공 문맥·두 검색 입력은 [v1](../dev100/README.md)과 동일하다. 리뷰2와 최소 보완을 반영한 **공개 개발용 정답 근거 후보**이며 독립 평가셋이 아니다. 법적 평가 기준일은 2026-09-08, 검토일은 2026-09-10이다. 모든 시점·조건·출처를 검증 완료한 정답집이나 최종 문항별 합격식으로 사용하지 않는다.

## 구성과 우선순위

- `raw/01`~`04` 및 `검토진행.md`: 제공된 리뷰2 원문 바이트 보존. `raw/05`는 지정한 명제·출처 상태만 덮어쓰는 최소 보완, `raw/06`은 그 확인 기록이다. 원문에 남은 도구 내부 참조 ID는 독립 열람 가능한 증빙이 아니다.
- `questions.json`: v1의 질문·제공 상황과 `question_only`/`context_diagnostic` 입력 200개를 바이트 그대로 보존한다.
- `requirements.json`: 원래 v2의 역할·조건·보류와 문항별 보완 명제를 함께 보존한다. **충돌하면 해당 명제에 한해 `claim_overrides`가 우선**한다. `original_v2`의 과거 보류 상태만 읽어 최신 상태로 사용하지 않는다.
- `source-registry.json`: 원래 출처 상태와 보완 후 `effective_status`, 명제별 시점·보류를 구분한다. `article_number_from_source`는 `제49조의2` 같은 가지조를 보존한다. 검토본이 확인했다고 보고한 상태이지 이 패치에서 모든 법령을 독립 검증한 결과가 아니다.
- `supplement-claims.json`: 28문항에 연결된 55개 보완 명제. 새 조건부 출처 2개를 포함한다. 같은 명제를 지지하는 근거만 대체 가능하며 서로 다른 명제를 전역 OR로 합치지 않는다.
- `changes-v1-v2.json`: 기존 유효 근거와 리뷰2의 변경 이유를 보존한다. 후속 최소 보완은 `supplement-claims.json`이 우선한다.
- `diagnostic-plan.json`: 검색 결과/LLM 답변과 독립적으로 고정한 **기본 필수 법령 조문 목표**. 조건부·보조를 모두 필수로 합치지 않았다. DEV-060의 C390, DEV-071의 C654+C615 및 기관 미지정 문항의 조정을 명시한다.
- `reference-run.json`: PATCH-010 저장 결과에서 뽑은 문항/입력 해시·순위·청크 ID·본문 해시와 법령 140개 목록. 운영 DB·벡터·법령 본문을 포함하지 않는다. 원래 저장 결과 파일 해시와 14입력 재현의 코드 해시를 남겼다. 원래 200건 실행의 정확한 커밋은 기록되지 않아 `null`이며, 14건 재현 커밋을 원래 실행 커밋으로 대신하지 않는다.
- `expected/`: 위 자료를 재대조한 결과. `manifest.json`은 입력·근거·저장 결과와 기대 결과의 해시를 묶는다. 해시는 무결성 검증이며 법률 정답의 정확성을 보증하지 않는다.

`formal_whole_item_score_ready=false`를 유지한다. INPUT·SCOPE, 개인 보증서·당시 약관의 미제공을 공통 법령 DB 누락으로 자동 판정하지 않는다. 판례·기관 안내는 목표/반환을 보존하지만 이 도구로 정확도를 계산하지 않는다.

## 재현

원문 7개는 필수 파일이다. 파일과 manifest 항목을 함께 제거해도 검증에 실패한다.
조 번호가 있는 법령 출처의 `law_name_normalized`와 `article_anchor_from_source`는
출처 제목·조 번호에서 정리한 법령명과 전체 조문 식별자다. 목표는 출처의 전체 식별자와
일치해야 하므로, 번호가 같아도 법령명이 다르면 거부한다.

저장소 루트, Python 3.11 기준. 아래 재대조에는 모델 다운로드·API 키·운영 DB·Chroma가 필요 없다. 저장된 실행이 필요한 근거를 반환했는지 조 번호 단위로 다시 계산하는 작업이다.

```powershell
.venv/Scripts/python scripts/dev100_v2/report.py --check
.venv/Scripts/python scripts/dev100_v2/report.py --out tmp/dev100-v2-report
```

별도 폴더로 복사한 데이터도 `--dataset 경로`로 지정할 수 있다. 새 출력 폴더만 허용하고 데이터 폴더 내부·상위에는 쓰지 않는다. 입력 해시·중복 ID·200입력 완전성·본문 해시·가지조를 검증한다. `--check`는 결과 3개가 공개된 기대 결과와 같은지도 확인한다.

현재 코드를 새로 검색 평가하려면 [v1 캡처 절차](../dev100/README.md)의 코퍼스·모델 준비와 별도 실행 기록이 필요하다. **이 재대조 도구를 실행했다고 현재 앱의 검색 성능을 새로 측정한 것은 아니다.** 다른 코퍼스/새 실행을 평가하려면 별도 버전으로 내보내고 질문·코드·데이터·설정을 고정해야 한다.

미보유 기본 필수 조문은 중복 제외 35개다. 이는 조건부/위임 조문·부칙·기관 안내까지 포함한 최종 적재량이 아니다. 법령이 없다는 것은 이번 스냅샷에 없다는 뜻이다.

TOP3/5 반환은 기본 법령 조문 적중일 뿐 전체 답변의 정답이나 모든 근거 충족이 아니다. 일부 미보유 문항에서도 보유 조문의 검색 누락이 병존할 수 있어 상세 결과에 두 원인을 함께 남긴다. 목표가 없는 23개를 자동 성공·서비스 범위 밖으로 세지 않는다. 과거 사건 2개는 현행 같은 조 번호만으로 성공 처리하지 않는다.

v1의 35/29/28/8은 조건부·대체·보조까지 포함한 인용 보유 집계여서 위 결과와 성능 향상으로 비교할 수 없다. 질문 단독 입력에 숨겨진 제공 문맥을 적용해 조건부 근거를 강제하지 않으며, 최종 조건별 완전성·적용 판본·항호 의미 충족은 별도 평가한다.
