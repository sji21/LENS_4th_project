# PATCH-018 — 일반 법령과 민법 결과 분리 실험

## 결론

**결과 자리 분리는 일반 법령의 밀림을 막지만, 민법 TOP2 선택과 0개 반환 문제는 해결하지 못했다. 운영 적용은 보류한다.** 일반 법령은 같은 모델·필터로 TOP5를 다시 검색했고 235입력 모두 기존 일반 법령의 순서를 보존했다. 기존 민법 선택을 그대로 분리하면 근거 손실이 없지만 신규29는 16건 그대로다. 민법 RRF TOP2로 교체하면 신규29는 최대 28건이 되지만, 기존 DEV 10입력에서 원래 찾던 필수 **민법**을 잃는다.

오늘은 사전 고정한 세 방식의 비교로 종료한다. 추가 가중치·임계값·모델·문항별 예외를 도입하지 않는다. 다음에 검토할 대상은 결과 자리 경쟁보다 **민법 내부 선택 및 필요 없는 경우의 미제공 판단**이다. 기존 규칙의 좋은 결과를 보존하면서 누락을 보완할 방법은 아직 검증되지 않았다.

## 비교 조건

- 코드 기준: PATCH-017 병합 main `d863a47`. [사전 계획](../data/eval/patch018-separate/plan.json).
- 동일 DEV100 질문 단독/문맥 200입력과 CIV35 문맥 포함 35입력, 총 235입력.
- 운영 자료 해시·설정·KURE-v1 모델 캐시를 PATCH-015와 대조한 뒤 **복사 인덱스에서 일반 법령 TOP5를 실제 재검색**했다. 일반 법령은 기존 상가 라우팅을 유지하고 민법을 제외한다.
- 민법은 검증된 PATCH-016 후보 RRF 순위를 재사용한다. 새 민법 검색·모델 교체·LLM 생성은 없다. 판례·안내는 이번에 재실행하지 않았고 제품 코드를 변경하지 않았다.
- 세 비교: `split_original`(기존 민법 선택 유지), `split_gated_top2`(기존 주제 감지 시 RRF TOP2), `split_all_top2`(모든 입력에 RRF TOP2). 모두 일반 TOP5와 민법 0~2개를 별도 목록으로 보존한다.
- 기존 결과는 법령 총5개, 분리 결과는 최대7개다. 아래 지표는 **두 목록의 합집합에 모든 필수 조문이 포함된 문항 수**다. 같은 TOP5 조건의 성능 향상이나 Hit@5라고 부르지 않는다. 별도 두 목록의 LLM 전달 순서·영향은 평가하지 않았다.

## 필수 근거 확보

| 방식 | CIV 기본29 | DEV 질문 단독 필수 목표75 | DEV 문맥 필수 목표75 | 기존 필수 근거 손실 입력 |
|---|---:|---:|---:|---:|
| 기존 총5개 | 16/29 | 20/75 | 23/75 | 기준선 |
| 일반5 + 기존 민법 선택 | 16/29 | 20/75 | 23/75 | 0 |
| 일반5 + 기존 감지 시 민법 TOP2 | 20/29 | 17/75 | 17/75 | 10 |
| 일반5 + 항상 민법 TOP2 | 28/29 | 19/75 | 18/75 | 10 |

DEV의 75문항 중 45문항은 필수 법령 일부 또는 전부가 DB에 없는 고정 평가 모집단이다. 목표 없는 23문항과 과거 시점 2문항은 각 모드에서 별도로 보고한다. CIV의 범위 보류1은 별도 1/1이며 관찰5는 정답 점수에 넣지 않는다. 10입력은 질문 단독4 + 문맥6으로, 6개 질문 ID에 해당한다. 세트 간 비율을 합산하지 않는다.

민법 TOP2 방식의 손실은 DEV-004·055·056의 제623조, DEV-006 문맥의 제626조, DEV-061의 제629조·제632조, DEV-062 문맥의 제629조다. **일반 법령 손실은 없고 민법 선택 교체의 손실**이다. 새 CIV에서 남은 한 문항은 CIV-DRAFT-028의 상가건물 임대차보호법 제2조가 일반 TOP5에 없기 때문이다. 필요한 민법의 후보 확보와 전체 필수 법령 확보를 구분한다.

## 민법을 0개로 반환하는 문제

기존 주제 감지를 유지하면 CIV 기본29 중 9문항은 민법0개다. 이를 우회하면 전부2개를 제공한다. 따라서 분리 자체가 미제공 기준을 만들어 주지는 않는다.

비과거 DEV98 중 **필수 민법 목표가 없는 문항은 각 모드66개**다. 기존 선택/기존 감지 방식은 그중 각1입력에 민법을 제공하지만, 무조건 TOP2는 66개 모두에 제공한다. CIV 관찰5도 무조건 TOP2에서는 모두 민법을 받는다. 이는 **추가 검토해야 할 노출량**이지 66건이 법적으로 무관하다는 판정이 아니다. 필수 목록 외에도 조건부·보조 근거가 가능하며 현재 gold에는 모든 조문의 불필요 여부가 라벨링되어 있지 않다. 거짓 양성률이나 민법 제공 정확도는 산출하지 않는다.

기존 선택 분리의 평균 법령 수는 DEV 질문 단독5.14개, 문맥5.15개, CIV 기본5.97개다. 무조건 TOP2는 모두7개다. 토큰 수와 답변 품질은 측정하지 않았다. 신규29에서 높은 후보 확보율만으로 운영 적용을 결정하지 않는다.

## 검증·재현

- 관련 테스트 **40개 통과**, 기존 환경의 `DJANGO_SETTINGS_MODULE` 미인식 경고1개.
- 운영 데이터 전체 전후 해시 동일. 235입력의 기존 일반 법령 순서 및 기존 주제 감지 결과 일치.
- 저장 자료의 필수 파일·해시·감사 기록·질의 연결을 확인하고 공유본 재집계 결과를 대조한다.
- [집계](../data/eval/patch018-separate/report/summary.json), [입력별 근거·손실](../data/eval/patch018-separate/report/details.json), [수집 기록](../data/eval/patch018-separate/capture/manifest.json), [전후 감사](../data/eval/patch018-separate/capture/audit.json).
- 전체 앱 테스트, 법적 정답 재검토, 독립 평가, LLM 답변 평가는 수행하지 않았다. 조문 단위 평가는 항·호·목 수준의 충분성을 증명하지 않는다.

공유본 재집계(모델·운영 DB 불필요):

```powershell
.venv/Scripts/python -m scripts.patch018_separate --replay data/eval/patch018-separate/capture --out tmp/patch018-replay
.venv/Scripts/python -m pytest tests/test_patch018_separate.py tests/test_patch017_selection.py tests/test_patch016_candidates.py tests/test_patch015_baseline.py -q
```

같은 운영 자료·모델이 있는 환경에서 새 수집 및 로컬 재집계:

```powershell
.venv/Scripts/python -m scripts.patch018_separate --out tmp/patch018-new
.venv/Scripts/python -m scripts.patch018_separate --replay tmp/patch018-new/capture --local-capture --out tmp/patch018-new-report
```

`--local-capture`는 미공유 수집에만 사용한다. 공유 manifest가 있으면 해시 검증을 생략하지 않는다. 원래 수집 당시 실행기·입력 해시와 미커밋 상태를 그대로 보존하며 새 실행으로 원본을 덮어쓰지 않는다.
