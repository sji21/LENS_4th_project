# PATCH-034 조건부 의미 검증 Dev 평가

## 목적

단순 법령 답변은 결정론적 검증으로 끝내고, 판례·기관 안내·복수 출처·숫자·시점·
조건·예외 또는 법적 행동·효력을 묻는 답변에만 Qwen 의미 검증을 실행했을 때의
응답 상태와 시간을 확인했다.

평가 사용자는 법률 지식이 적고 부동산 계약을 앞둔 사회 초년생을 전제로 한다.
따라서 빠른 오답은 성능 개선으로 인정하지 않고, 잘못된 법적 행동을 안내할 가능성이
확인되면 의미 검증 대상으로 되돌렸다.

## 환경과 방법

- 평가셋: `data/eval/dev.jsonl` 27문항
- 검색: KURE-v1 + BM25 + RRF
- 생성·검증: 로컬 Ollama `qwen3:8b-q4_K_M`
- 메인 생성 상한: 256토큰
- 의미 검증 상한: 160토큰
- KURE-v1 초기 로딩은 문항 타이머 전에 완료
- 시간은 `answer_question()` 전체 실행 시간이며 Streamlit 브라우저 렌더링 시간은 제외
- temperature 0.0, 같은 컴퓨터에서 순차 실행

첫 27문항 실행 후, 결정론적 빠른 경로에서 잘못된 임차권등기명령 신청 요건이
통과한 것을 수동 검토로 확인했다. `언제·어떻게·누가·효력·권리·요건·신청·부담`
등의 법적 행동·효력 질문을 의미 검증 대상으로 보수적으로 조정하고 영향받은 5문항을
같은 환경에서 재실행했다. 아래 표는 해당 문항의 재실행 결과로 교체한 최종 결과다.

## 실패 분석

### dev-006

메인 Qwen이 법 제3조의3의 직접 근거인 `임대차가 끝난 후 보증금이 반환되지 아니한
경우`를 사용하지 않고, 확정일자가 신청 요건인 것처럼 잘못 답했다. 초기 빠른 경로에서는
이 답변이 통과했으나 보수적 조건부 정책으로 바꾼 뒤 의미 검증이 FAIL로 판정해 보류했다.
초보 사용자에게 오정보가 전달되는 것보다 보류가 안전하지만, 생성 프롬프트가 검색 1위의
직접 문장을 우선 사용하도록 개선해야 한다.

### dev-008

질문의 `1년`을 답변이 반복했는데, 값 검증기가 검색 근거에 있는 값만 허용해 사용자 질문에
이미 있던 기간까지 근거 밖 숫자로 판정했다. 모델이 새로 만든 값과 질문을 그대로 반복한
값을 구분하도록 값 검증기를 보완해야 한다.

### dev-021

출처 검증 정규식이 일반 명사 `조정위원`을 기관명으로 잘못 인식해 검색되지 않은 출처로
판정했다. `대법원`을 기관 안내로 오인했던 문제와 같은 유형으로, 기관명 허용 목록 또는
법원·일반 명사 제외 규칙이 필요하다.

## 결론

조건부 의미 검증 자체는 동작하지만, 최종 보수 정책에서는 25개 답변 가능 질문 중
22개가 의미 검증 대상이었다. 법률 질문 대부분이 조건·효력·기간·금액을 포함하기 때문에
검증 생략만으로는 전체 속도를 크게 줄이기 어렵다. 특히 가장 느린 dev-022~024는 메인
Qwen 생성만 약 30초가 걸려 의미 검증보다 메인 프롬프트·출력 길이가 주 병목이다.

다음 속도 실험은 안전 검증을 제거하기보다 실제 인용 근거만 의미 검증기에 전달하고,
비교·지역별 금액 질문의 메인 컨텍스트와 출력 형식을 줄이는 방향이 적합하다. 초보 사용자를
위해서는 전문 용어의 즉시 풀이와 `결론 → 지금 할 일 → 확인할 곳` 구조가 실제 출력에서
지켜지는지도 별도 답변 품질 평가 항목으로 측정해야 한다.
