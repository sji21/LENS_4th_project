# PATCH-032 · 대화 판단의 실행 연결

`CHAT_CONVERSATION_ENABLED=false`가 기본값이다. `true`인 웹 요청만 새 실행 분기를 사용한다. 설정을 false로 되돌리고 서버를 재시작하면 기존 질문 해석·RAG 경로로 복귀한다. .env의 실제 비밀값은 변경하거나 커밋하지 않는다.

새 경로는 사용자 원문의 입력 보호를 판단·문서 질문 변환 전에 적용한다. 명시적인 공격과 범위 밖 요청을 고정 거절로 처리하며 필요한 경우 기존 의미 기반 공격 검사를 사용한다. 모델이 공격 내용을 검색문에서 삭제해 검사를 피하지 못하도록 원문을 먼저 검사한다.

허용 행동은 `social`, `clarify`, `rag`, `refuse`다. 인사와 확인 질문은 코드의 안내 문구로만 표현하며 모델의 임의 질문·본문을 공개하지 않는다. 인사·확인은 법률 검증 완료를 뜻하는 answered 상태로 기록하지 않는다. 법률 답변은 기존 검색 그래프와 최종 검증을 통과한 공개 본문만 사용한다.

상태 복사본에서 실행하고 성공했을 때 사실·메시지를 한 번 반영한다. 판단 출력 오류는 같은 원문으로 기존 경로를 실행하며 잘못된 진술은 저장하지 않는다. 이미 시작한 RAG의 오류를 잡아 다시 RAG를 실행하지 않는다. 웹의 기존 요청 ID 중복 처리, 잠금, CSRF와 세션 소유권 검사를 그대로 사용한다.

이 단계의 확인 질문은 고정 안내만 제공한다. 필드별 질문·응답 연결·반복 상한은 PATCH-033, 문서 연속 상담은 PATCH-034, 화면 표현은 PATCH-035에서 순서대로 검증한다. 운영 기본 활성화와 전체 대화 품질 승인은 PATCH-037의 통합 결과와 구분한다.

## 검증

전체 자동 검사 1,325개와 137개 subtest 통과. 선택적 외부 추적 2개·개인 PDF 1개는 미실행이다. [실제 모델 표본](../data/eval/chatting/results/routing-dev-sample.json) 3턴은 인사 1회 호출, 법률 질문과 단답 연결 각각 3회 호출로 완료됐다. 인사는 social, 두 법률 답변은 기존 검증 후 answered였으며 실행 중 코드·모델·검색 데이터가 동일했다. 각 지연은 3.940초, 32.352초, 45.127초다. 표본 실행을 전체 수용평가나 법률 정확도로 해석하지 않는다.
