# PATCH-025 민법 TOP3 순위 분석과 개선

## 결론

기존 민법 TOP2를 유지하고, 세 번째 후보를 선택할 때만 dense(의미 검색) 비중을
2배로 높이는 안을 채택했다. DB·색인·모델·질의 사전·일반 법령·판례·안내는 변경하지 않는다.
전체 민법 가중치를 바꾸는 방식과 달리 기존 첫 번째·두 번째 후보의 순서를 보존한다.
이미 구한 후보 순위를 재사용하므로 추가 검색·임베딩 요청은 없다. 민법 반환은 최대 3개다.

DEV 문맥 입력의 필수 근거 완전 확보는 29→30/100이며 질문 단독은 28/100 그대로다.
고정된 필수 근거 손실은 235입력에서 0건이다. **세 번째 후보가 바뀐 입력은 72개**다.
이 중 DEV-012 문맥에서 제114조를 새로 확보했다. 나머지 후보의 법적 적합성이나 LLM
답변 품질까지 좋아졌다고 주장하지 않는다. 작은 개발셋 개선이며 독립 평가가 아니다.

## 원인 분석

최신 main `0502025` 및 PATCH-024 데이터로 기존 235입력을 재현하고, 민법 10개의
BM25·dense·RRF 순위와 규칙에 따른 우선 선택을 기록했다.
기존 미확보 민법 근거 22건(문항×입력 방식×조문 기준)은 다음과 같다.

- 21건: RRF 후보에는 있지만 4위 이하. 추가한 제105조 12건·제114조 7건·제357조 2건.
- 1건: RRF 3위지만 기존 선택에 밀림. DEV-059 문맥의 제626조이며 이번에도 미해결.
- 결합 후보 자체에서 빠진 근거는 없었다. BM25 단독에는 일부 미진입 사례가 있었다.

제105조는 dense에서 주로 8~10위라 단순 가중치 변경만으로 해결되지 않는다.
제114조도 질문에 따라 BM25와 dense 순위가 엇갈린다. 예를 들어 DEV-012 문맥은
BM25 6위·dense 2위·RRF 4위였고, 채택안에서는 세 번째 후보가 된다.

탐색 실험이다. 결과를 본 뒤 만든 안까지 사전 등록 실험처럼 표현하지 않는다.

계속 비중을 탐색하거나 문항별 조건을 추가하지 않았다.

## 검증과 증거

- 후보 수집: `23ad5bb`, 실행 전후 clean. 최초 실패한 수집은 최종 증거로 쓰지 않았다.
- 실제 적용 검증: `0ee906e`, 실행 전후 clean. 235입력 모두 저장된 채택안과 일치.
- 일반 법령·판례·안내는 235입력 모두 기존과 동일하며 DB·청크와 색인 내용도 보존했다.
- 적용 후 전체 테스트: 855 passed, 3 skipped, 124 subtests passed.
- 스킵: 비활성 LangSmith 2개, 실물 등기 PDF 미지정 1개.
- 증거 포장 후 관련 9개 테스트 통과(신규 재집계·누락 차단·부동소수점 검사 3개 포함).

Chroma 저장 파일 일부는 PATCH-024 기록 및 이번 실행 전후와 바이트가 다르다.
이를 동일 해시로 취급하지 않았다. 전후 파일 해시와 차이를 보존하고, 모든 색인의
문서·메타데이터가 청크와 일치하는지, 실행 전후 문서·메타데이터·벡터의 정규화
해시가 같은지 검사했다. KURE 모델 파일 해시도 과거 기록과 대조했다.
과거 파일의 바이트 차이 자체의 원인을 확정한 것은 아니며, 바이트 단위 동일 재현을 주장하지 않는다.
