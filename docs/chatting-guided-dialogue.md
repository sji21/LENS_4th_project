# PATCH-038 안내와 확인 질문을 함께 제공하는 상담

2026-09-14 · `feat/patch-038-guided-dialogue` · 구현 커밋 `876e19f` · 품질 리뷰 중

사용자가 문제를 제시하면 근거 기반 답변을 먼저 생성하고, 중요한 미확인 사실 하나를 이어서 묻는다. 답변 전에 모든 정보를 채우도록 강제하지 않는다. 예를 들어 보증금 반환 상담에 현재 확인할 일을 안내한 뒤 계약 종료일을 묻고, “다음 달 말”이라는 답을 종료일로 저장해 원래 상담을 이어간다.

## 구현 경계

- 기존 의도 판단 모델이 `rag`와 `clarify_field`를 함께 선택한다. 새 모델 호출은 추가하지 않았다.
- 검색 질문은 저장된 사용자 사실과 원래 상담 요청으로 구성한다. 원래 요청은 같은 사건·주제·문서의 후속 답변에만 재사용한다.
- 생성 전에 `consult` 표현 지침을 적용한다. 현재 확인할 일, 근거, 미확인 조건을 구분하도록 요청한다. 검색·법률 검증 로직은 변경하지 않는다.
- 검증된 답변 본문은 그대로 보존하고 `followup_question`을 별도 표시한다. 답변 보류를 성공으로 바꾸지 않으며 거절된 요청에는 질문을 붙이지 않는다.
- 확인 질문에 답하는 대신 요약을 요청할 수 있다. 이미 답한 필드와 모른다고 한 필드는 다시 묻지 않는다. 확인 질문은 한 번에 하나씩 제공한다.
- “끝나간다”를 이미 종료된 것으로 해석하지 않으며 “갱신하지 않겠다고 알렸다”의 부정 표현을 통지하지 않은 것으로 오인하지 않도록 검사한다.

## 검증

- Python 전체: 1,433개 통과, 137개 subtest 통과, 3개 건너뜀. 건너뜀은 LangSmith 비활성 2개, 등기 PDF 미지정 1개다.
- JavaScript 요청 식별 회귀 5개, JavaScript 구문 검사, Django 시스템 검사 통과.
- Django API에서 답변·후속 질문 공개, 원래 요청 비공개, `reply_to`를 통한 종료일 답변 연결을 검증했다.
- 실제 로컬 Qwen 대화 계층 4턴: 첫 안내와 종료일 질문, 상대 날짜와 통지 사실 반영, 중간 요약, 일반 정의 질문을 확인했다. `patch038-guided-verified.json`의 6개 검사 통과. 법률 생성은 고정한 평가이므로 법률 답변 품질의 통과로 해석하지 않는다.

재현: 저장소 루트에서 `PYTHONPATH=. .venv/bin/python scripts/evaluate_guided_dialogue.py --output /tmp/guided-new.json`을 실행한다. 로컬 Ollama와 프로젝트 환경 설정이 필요하다. 기존 결과 파일은 덮어쓰지 않는다.

## 실패 기록과 해석

`data/eval/chatting/results/patch038-guided-live.json`은 첫 질문 누락, `patch038-guided-live-02.json`은 부정 인용문 안의 통지 사실 검사 실패를 기록한다. `patch038-guided-live-final.json`도 최종 통과 자료가 아니다. 당시 요약 검사 조건이 너무 느슨해서 복구 질문을 성공으로 잘못 집계했다. 원시 응답에는 실패가 남아 있다. 검사 조건을 `rag`·`explain`·확인 질문 없음으로 강화한 뒤 `patch038-guided-verified.json`에서 재검증했다. 이 사례들은 개발 회귀이며 독립적인 미공개 수용평가는 아니다.

실제 Django 전체 RAG의 첫 실행 `patch038-guided-http.json`은 HTTP 200, 답변과 종료일 질문 연결을 확인했으나 47.36초가 걸렸고 답변은 여전히 조문 설명에 치우쳤다. 이에 현재 확인할 일을 목록으로 작성하도록 사용자 프롬프트에도 표현 지침을 추가했다. 검색 근거의 관련성, 구체적인 법률 대응의 정확성 및 전체 지연은 별도 개선 과제다. 사용자가 제시한 모든 대응 절차를 근거 없이 고정 문구로 넣지는 않는다.

원격 최신화는 네트워크 시간 초과로 실패했다. 확인 가능한 캐시의 기본 브랜치는 현재 기반의 조상이며 038 중복은 없었다. 푸시·병합 전 원격을 다시 확인해야 한다. 커밋·푸시·main 병합은 수행하지 않았다.

최종 형식을 적용한 전체 RAG 재실행 `patch038-guided-http-02.json`은 HTTP 200으로 “지금 확인할 일” 목록과 종료일 후속 질문을 함께 반환했다. 74.67초가 소요됐으며 동시 브라우저 요청이 있었으므로 단독 성능 측정은 아니다. 내용은 여전히 계약 기간과 반환 조건 확인에 치우쳤다. 요청한 구체적인 대응 절차 전부가 나오는 수준의 품질 완료로 판단하지 않는다. 동시 브라우저 요청은 오류를 반환해 단독으로 재시도했다.

별도 `http://localhost:8000/` 브라우저 세션의 단독 재시도는 53.2초에 답변, 안내 목록, “계약 종료일을 알려주시겠어요?”, 모름 선택지와 자유 입력을 표시했다. 기존 `127.0.0.1` 대화는 보존했다. 질문 패널로 대화 영역 높이가 바뀐 다음 마지막 메시지로 이동하도록 스크롤 순서도 조정했다.

## 월세 갱신 후속 질문 보정

“지금 사는 월세집에서 계속살고 싶은데 계약 갱신은 어떻게 해?” 뒤 “그럼 문자로 연장한다고 해도 괜찮아?”에서 `invalid_decision:unstated_contract_type`을 재현했다. 월세·계약갱신 맥락은 저장돼 있었지만 모델이 “문자로 연장한다고 해도”를 월세 및 계약 미종료의 새 근거로 제출했다. 검증기는 이를 거절했다.

의도 판단 지침에 방법·허용 여부 질문은 행동 완료나 계약 상태 진술이 아니라는 규칙과 별도의 카톡 갱신 예시를 추가했다. 기존 사실은 서버가 유지하며 후속 질문의 새 사실 목록은 비어 있어도 된다. 사실 검증을 완화하거나 틀린 모델 출력을 정상으로 처리하지 않는다.

`patch038-renewal-followup.json`에 수정 전 원시 출력과 수정 후 결과를 기록했다. 실제 모델에서 원래 질문, 복구 질문이 남은 상태의 재질문, 종료일 확인 중 카톡 방법 질문 모두 `followup`·`rag`·새 사실 없음으로 처리했다. 기존 사용자 대화는 변경하지 않았다. Python 전체 1,436개 및 137개 subtest 통과, 3개 환경 의존 검사 건너뜀, Django 시스템 검사 통과.

기존 안내·날짜 답변·요약·일반 정의의 실제 모델 4턴 회귀도 `patch038-guided-renewal-regression.json`의 6개 검사를 통과했다. 서버 재시작 후 홈 HTTP 200을 확인했다. 이번 갱신 질문 검증은 대화 계획과 검색 질문 구성까지이며 실제 법률 답변의 품질을 재평가한 것은 아니다.

### 다른 인용 구간으로 반복된 갱신 후속 질문 실패

이후 “그럼 문자로 계약 갱신 할수 있어?”에서는 `followup`을 올바르게 판단하고도 `provenance_or_document`로 중단됐다. 모델이 기존 거주 사실을 첫 사용자 발화의 다른 구간으로 다시 인용했고, 기존 중복 제거는 저장된 인용 구간과 겹치는 경우만 허용했기 때문이다. 동일한 활성 사실·값이며 기존 근거와 새 인용 모두 그 사실의 원래 사용자 발화에 존재하고 의미 검사를 통과하면 중복 제안을 제거하도록 보정했다. 저장된 사실의 값·근거·시점은 변경하지 않으며 다른 발화의 인용은 허용하지 않는다.

Python 1,438개 및 137개 subtest 통과, 3개 환경 의존 검사 건너뜀. `patch038-renewal-source-span.json`의 실제 모델과 RAG 실행은 51.65초에 `followup`·`rag`·`used_history=true`·`answered`로 완료돼 맥락 오류 복구 화면으로 빠지는 문제를 해소했다. 다만 생성 답변은 갱신 일반론을 반복하고 문자 방식에 직접 답하지 않았다. 후속 질문 인식과 현재 질문에 대한 답변 적합성은 별개이며, 후자는 여전히 개선이 필요하다. 해당 실행 도중 normalization 파일의 설명 주석만 수정해 `source_unchanged=false`가 기록됐으며 실행 로직은 추가 변경하지 않았다.

## 현재 질문의 초점 유지

최신 실질 질문 원문을 `last_answer.request`에 별도로 저장한다. 후속 질문은 이 원문 하나를 배경으로 사용하고 현재 입력을 별도 항목으로 유지한다. 답변 후에는 최신 질문으로 기준을 갱신한다. 요약·쉬운 설명은 요약 명령 자체로 대상을 덮어쓰지 않으며, 확인 질문의 짧은 답은 연결된 원래 상담 요청을 유지한다. 새 사건·문서·사실 변경으로 기존 답변이 무효화되면 그 요청도 재사용하지 않는다. 과거 세션에 `request`가 없으면 기존 검색 질문으로 호환 처리하고 다음 답변부터 새 형식을 사용한다.

임의의 법률 용어·조건을 생성해 검색 질문에 넣는 대신 사용자 원문과 검증된 상태를 활용한다. 법률 RAG와 문서 생성 프롬프트에는 마지막 질문에 먼저 답하고, 근거가 부족하면 구체적으로 어느 항목을 확인할 수 없는지 명시하도록 지시했다. 별도의 적합성 판단 모델이나 재생성 호출은 추가하지 않았다. 현재 적합성 확인은 생성 지침과 회귀 평가 수준이며 자동 품질 보장은 아니다.

20턴 후속 질문의 검색 문자열 중첩 방지, 최신 질문 이후 요약 대상 유지, 사건 전환, 기존 생성 경로의 프롬프트 유지 검사를 추가했다. 초기 실측 `patch038-renewal-focus.json`에서 “문자로”를 통지하지 않았다는 사실로 잘못 받아들인 사례를 발견했다. 통지 행동 근거가 없는 예·아니요 진술을 검사하고, 같은 상담의 일반 질문 전체에도 통지 행동 표현이 없으면 모델의 근거 없는 통지 제안만 제거한다. 정정·새 사건·통지 여부 확인 중에는 이 제거를 적용하지 않으며 명시된 부정 진술의 모순도 그대로 거절한다.

`patch038-renewal-focus-02.json`의 전체 RAG는 53.82초에 문자 방식의 질문을 다루고 자료 부족도 명시했다. 통지하지 않았다는 사실은 추가되지 않았다. 다만 첫 문장은 여전히 갱신 일반 설명이며 답변 내부의 법률적 표현 정확성과 약 54초 지연은 남아 있다. 법률 적용·검증 담당과 연결할 항목으로 남긴다. `patch038-focus-chain.json`의 첫 연속 평가에서는 “답장이 없으면?”을 통지 사실로 오인해 실패했으며 보정 후 별도 결과로 재검증한다.

최종 `patch038-focus-chain-02.json`에서는 실제 모델로 문자 방식→답장 없음→요약의 세 턴을 `followup`·`followup`·`explain` 및 모두 `rag`로 처리했다. 검색 질문은 직전 문자 질문을 이어받고 요약은 답장 없음에 대한 질문을 유지했다. 통지 여부는 저장되지 않았다. 이 연속 평가는 법률 생성 대역을 사용한 대화 계층 검사다. 최종 Python 전체 1,447개 및 137개 subtest 통과, 환경 의존 검사 3개 건너뜀. 같은 브랜치의 미커밋 PATCH-038에 반영하고 로컬 서버를 재시작했다.

## 원격 공유 준비

사용자의 푸시 요청으로 구현 커밋과 기록 동기화 후 현재 브랜치를 공유한다. 품질 한계가 남아 있으므로 LIST의 상태는 리뷰 중으로 유지하며 main 병합은 하지 않는다. 푸시 전 재검사: Python 1,447개·137개 subtest 통과, 환경 의존 검사 3개 건너뜀, JavaScript 5개 통과.

이번 원격 갱신은 성공했으며 origin/main은 `70babac`이다. PATCH-038 번호 중복은 없다. 다만 기존 대화형 작업의 PATCH-047~028은 main의 웹 안정성·법령 확대·데이터 설정 작업과 번호가 겹친다. 병합 전 선후 관계와 공유 기록을 비교해 번호·의존성·문서 참조를 정리해야 한다. 이 공유 작업에서는 기존 구현 이력을 변경하거나 main을 병합하지 않는다.
