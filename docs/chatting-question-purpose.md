# PATCH-040 질문 목적에 맞춘 검색·답변

- 날짜: 2026-09-14
- 브랜치: `feat/patch-040-question-purpose`
- 상태: 리뷰 중, 구현 커밋 `d649504`. 갱신 안내→종료일 응답→문자 요청 질문의 실제 3턴 검증 통과. 다른 주제·표현의 품질 평가는 남아 있다.

## 변경

기존 대화 판단 한 번에서 주제와 별도로 `purpose`를 받는다. 절차, 시기,
구체적인 방법의 가능 여부, 개념, 서류, 출처, 요약을 구분한다. 고정 시나리오별
답을 만드는 방식이 아니라 LLM의 목적 판단을 검색 질문과 생성 지침에 전달한다.
목적은 계약 사실로 저장하지 않으며 다음 질문에서 다시 판단한다. 기존 결정 형식은
`general`로 호환하고 알 수 없는 값은 거절한다. 요약은 직전 질문 대상을 유지한다.

절차 답변은 언제·어떻게·확인할 사항을 짧게 안내하도록 했고, 사용자의 목표와
행동 주체를 유지하도록 지시했다. 법률 검증과 검색 데이터는 변경하지 않았다.

  같은 주제의 절차 → 방법 가능 여부 → 요약 전환을 검증한다. 모델 판단은 모의 응답이다.
- 실제 로컬 모델과 전체 RAG로 사용자가 제시한 월세 갱신 질문을 실행했다.

자동 검사 통과는 실제 법률 답변의 적합성·정확성을 보장하지 않는다. 현재 근거 검증이
통과시킨 응답에도 위 문제가 남아 있으므로 완료 처리하지 않는다. 후속 작업은 질문에
직접 답했는지 평가하는 수용 검사와, 법률 담당자와의 근거 선택·조건 검증 연계다.
첫 질문만 실제 전체 RAG로 검증했으며 후속 질문의 실제 모델 품질은 별도 확인이 필요하다.

## 2026-09-16 일반 안내 후 질문 적용

개인 갱신·반환 절차의 목적과 사용자 진술을 확인한 경우 종료일, 통지 여부 중
아직 모르는 항목 하나를 선택한다. 모델이 선택한 질문은 우선 존중하며 이미 답한 정보,
모름·거부한 정보, 질문 횟수 상한은 기존 규칙으로 처리한다. 일반 개념·요약·방법의
가능 여부 질문과 문서 내용 질문에는 자동 면담을 추가하지 않는다. LLM의 갱신 예제도
일반 안내 후 종료일을 묻는 흐름으로 수정했다.

`chat/renewal_guides.json`은 다음 공개 자료를 확인해 작성한 짧은 사실 요약이다.
발행일과 확인일은 구분하며 페이지 전체나 이미지의 복제본이 아니다.

- 문화체육관광부 국민소통실, 2020-09-01 [갱신요구권 행사 방식](https://www.korea.kr/news/policyNewsView.do?newsId=148876914): 전달 수단·증거 보존 범위만 사용한다.
- 법제처 찾기쉬운 생활법령정보 [임대차계약의 갱신](https://www.easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=4&cciNo=4&cnpClsNo=1&csmSeq=629): 2026-09-16 확인. 행사 시기·조건·묵시적 갱신과의 구분을 요약했다. 옛 계약 적용례를 현재 모든 계약의 기한으로 혼용하지 않는다.

갱신으로 판단된 공식 RAG 경로에만 `GuidedSearch`가 안내 두 건을 보충한다.
기존 법령 검색 결과·법률 검증·공용 인덱스를 변경하지 않으며 문서 전용 검색과
다른 상담 주제에는 적용하지 않는다. 실시간 웹 검색이나 모든 주제의 안내 확장은 아니다.
안내도 기존 생성·근거 검증에 전달되며 실패 답변을 성공으로 바꾸는 대체 응답은 없다.
생성 단계의 대화형 호출에만 문맥 최소 8192·출력 최소 512를 적용한다. `.env`와
기존 비대화 경로의 설정은 유지한다. 더 많은 토큰은 지연·메모리 비용을 늘릴 수 있다.

검증: 전체 Python 1467 passed, 3 skipped, 137 subtests passed. Django check 통과.
`patch040-guidance-01.json`의 실제 최초 질문은 69.84초에 `answered`와 종료일 확인 질문을
반환했다. 실제 방법 안내가 포함됐으며 기존 검증을 통과했다. 이 한 사례의 통과는
전체 법률 답변의 정확성이나 모든 표현의 성공을 보장하지 않는다. 앞선 실패 보고서는 보존한다.

`patch040-guidance-chain-01.json`에서는 날짜 저장 후 재생성한 답변이 숫자 검증에서
보류됐다. 검증을 완화하지 않고, 이미 검증된 일반 안내 뒤 순수한 정보 답변을 받으면
정보를 저장하고 다음 미확인 항목만 묻도록 수정했다. 이전 안내가 보류됐거나 새 질문의

`patch040-guidance-chain-02.json`에서 첫 안내와 종료일 질문(69.27초), 날짜 저장 후

확인했다. 네 가지 평가 조건과 실행 중 소스 일치 검사가 통과했다. 응답 지연 개선은 남아 있다.
추가 경계 회귀 2건을 포함한 대화 검사 25건도 통과했다.

실제 로컬 모델·검색·생성·검증을 실행한다. `--first-only`는 첫 질문만 실행한다.

## 수동 확인

2026-09-15 입력창 보완: 전송 직후 비우고 성공 시 새 초안을 유지한다. 실패 시
빈 입력창에만 이전 입력과 확인 질문 연결을 복원한다. 실제 submit 핸들러의 성공·실패와
새 초안 유무 조합 4건, 기존 요청 ID 검사 5건 통과.

2026-09-15 UI 수정 당시 검색 자료 확인: `src/retrieval/service.py`의 `GUIDE_TOPICS`는 보증보험·미납국세만
등록되어 있다. 갱신 절차용 공식 안내 검색은 연결되지 않았다. 법령은 요건·기한 검증에
유지하고 공식 FAQ·실무 안내를 추가 검색하는 개선이 필요하다. 자료 수집·검색·법률
검증은 별도 협업 범위이므로 이번 UI 수정에서 변경하지 않았다. 화면의 검증 보류만으로
구체적인 실패 규칙을 확정할 수는 없다.

화면 가독성 보완: `언제:`, `어떻게:`, `확인할 사항:`이 함께 있는 assistant
답변은 표시할 때 항목 사이에 빈 줄을 넣는다. 저장 원문과 사용자 메시지는 유지한다.
생성 지침에도 항목별 새 문단을 요청한다. JavaScript 구문 검사와 일반 텍스트·기존
줄바꿈·굵은 항목·일반 답변의 표시 변환 4건을 확인했다. 화면 새로고침 후 저장 답변에도 적용된다.
재확인 시 이전 스크립트가 탭에 남아 있어 정적 파일 URL에 버전을 추가하고 서버를
재시작했다. 기존 대화를 보존한 채 브라우저를 새로고침하여 세 항목 사이의 빈 줄을
접근성 트리와 실제 화면에서 확인했다.

새 대화에서 다음을 연속 입력한다.

1. 지금 사는 월세집에서 계속 살고 싶은데 계약 갱신은 어떻게 해?
2. 그럼 문자로 갱신한다고 알려도 돼?
3. 언제까지 알려야 해?
4. 짧게 정리해 줘.

각각 절차·특정 전달 방법·시기·직전 답변 요약에 직접 답하거나, 해당 근거가
없다는 점을 명시해야 통과다. 단순히 제목이나 주제만 일치하면 실패로 기록한다.
