# PATCH-027 문맥·준용 연결 검색 튜닝 결과

실행일: 2026-09-13
상태: 검토 전 결과 보존 — 리뷰 보완 후 재실행 대기, 운영 미채택
실행 커밋: `(commit: pending)`
근거: [실행 전 계획](patch027-tuning-plan.md), [직전 개념 확장 결과](patch027-concept-tuning.md)

> 아래 수치는 검토 전 미리보기 실행의 기록이다. 4단계는 당시 저장 순위 재조합이며 실제 서비스 통합 검증이 아니었다. 준용 추출·검증, 부정문과 공공임대 문맥 반례를 보완하고 최종 조합을 고정한 뒤 새 235입력 실행 결과로 갱신한다. 기존 '추가 임베딩0'과 공공임대 구분·출처 검증 완료 설명은 검증 완료 사실로 인용하지 않는다.

## 1. 결론

문맥 제한과 민법 준용 연결은 검색 지표를 개선했다. 최종 개발 후보인
`context_both + context_reference`는 미튜닝204조문 후보의 DEV 완전 확보를
질문32→43/75, 문맥34→42/75로 높였다. 민법 신규 필수9조문을 모두 해당 정답 입력의
TOP3에서 찾았고, DEV-071은 제615조와 제654조를 질문·문맥 입력 모두 함께 반환했다.

그러나 운영143조문 기준의 기존 반환 근거 손실8입력과 일반 TOP3 손실7입력이 남았다.
미튜닝204조문 결과와 비교해도 새 손실2입력(DEV-003 질문의 국세징수법 제109조,
DEV-038 질문의 주민등록법 제16조)이 있다. 따라서 사전 채택 기준은 통과하지 못했고,
운영 DB·인덱스·민법 허용 목록·제품 검색 코드는 변경하지 않는다.

이 결과는 공개 DEV100·CIV35를 사용한 개발 튜닝이다. 독립 평가 성능, 법적 정답의
개선 또는 LLM 답변 품질 개선을 뜻하지 않는다.

## 2. 고정 조건과 실행 방식

- 동일204조문 후보·민법26조문, KURE-v1, BM25+KURE+RRF를 사용했다.
- DEV100 질문·문맥200입력과 CIV35 35입력, 합계235입력을 유지했다.
- 일반5·민법3·판례5·안내0~2의 반환 제한과 기존 정답·채점 분모를 바꾸지 않았다.
- 후보 DB·청크·색인·모델 해시를 직전 전체 적재 감사와 대조했다.
- 문맥 BM25를 새로 계산하고, 문맥 KURE 질의를 실제 재임베딩해 후보 인덱스에서
  전수 검색했다. 최종 순위는 고정된 RRF·선택 규칙으로 결합했다.
- 판례·안내 결과는 기존235입력 결과를 그대로 보존했고 운영 자료를 교체하지 않았다.

## 3. 1단계 — 민법 문맥 제한

“문자·통지”만으로 의사표시 도달 개념을 붙이지 않는다. 현재 사용자 질문에서
계약 종료·해지·갱신 또는 보증금 반환 요구와 실제 전달·연락 행위가 함께 확인될 때만
확장한다. 이전 대화의 인용, 수리 일정 문자, 승소 확률 질문, 보험 사고 통지는 현재
의사표시 요청으로 취급하지 않는다.

이 제한은 직전 규칙이 의사표시로 확장한14입력에서 해당 개념을 제거했다. DEV-057의
수리 문자와 CIV-DRAFT-023의 누수 수리 통지를 제외하면서, DEV-075의 계약 종료
내용증명과 DEV-078의 보증금 반환 우편 반송은 유지했다.

| 민법 정책 | 완전 확보 질문/문맥 | Hit1·3 질문 | Hit1·3 문맥 | 신규 조문/입력 | 운영 기준 손실 | 미튜닝204 대비 새 손실 |
| --- | ---: | --- | --- | --- | ---: | ---: |
| 직전 `lexical` 대조군 | 35 / 37 | 11·20/32 | 9·18/32 | 7 / 11 | 15 | 0 |
| 문맥 제한 BM25 | 35 / 37 | 11·20/32 | 9·18/32 | 7 / 11 | 15 | 0 |
| 선택적 문맥 KURE 포함 | 38 / 38 | 19·24/32 | 14·21/32 | 8 / 16 | 15 | 0 |

문맥 제한 BM25는 보수적인 대조군의 성능과 손실0을 유지했다. 선택적 KURE는 문맥이
확인된 개념만 질의에 붙여 Hit3를 질문24/32·문맥21/32로 높였고, 미튜닝204 대비
새 반환 근거 손실은 만들지 않았다. CIV35는 완전 확보28/29·민법 Hit3 29/29를 유지했다.

## 4. 2단계 — 민법 준용 조문 1단계 연결

민법 현행 본문의 제목이 `준용규정`인 조문에서 정확히 확인되는 같은 법령의 직접 참조만
양방향 후보 연결로 사용했다. 이번26조문 범위에서 검증된 연결은 제654조가 본문에서
제615조를 준용하는 1개다. 원문 청크 SHA-256은
`b73fce1b7c7a0c6403ff14224f9da9eb3526c0ad3821116531767711cb36b7e5`다.

두 조문이 결합 후보10위 안에 있고 하나가3위 안에 있을 때만 기존 첫 번째 민법 후보와
함께 최대3칸에서 재평가했다. 질문 ID·정답 ID는 선택에 사용하지 않았고, 연결된 두
조문은 두 칸으로 계산했다.

5입력에서 연결 후보가 발동했다. DEV-071 질문·문맥에서는 제615조와 제654조가 모두
TOP3에 들어왔으며 기존 필수 근거의 새 손실은 없었다. 최종 민법 결과는 완전 확보
39/75·39/75, 신규 필수9/9조문·16입력, CIV35 완전 확보28/29·Hit3 29/29다.

## 5. 3단계 — 일반 법령 문맥·결합 비교

세금은 체납·미납 맥락, 확정일자는 절차와 효력, 전입은 주소 이전 표현, 공공·민간임대는
현재 질문의 명시적 유형을 구분했다. 공공임대 문맥의 일반적인 “임대사업자” 표현만으로
등록민간임대 개념을 붙이지 않았다. 첫 전수 실행 뒤 남은 회귀 중 DEV-005·050의
“확정일자는 언제/다시 챙겨야 하는가”가 효력으로 분류된 공통 원인을 확인해, 계획의
허용 범위대로 절차 문맥 수정1회를 적용했다. 추가 반복 탐색은 하지 않았다.

| 일반 정책 | 완전 확보 질문/문맥 | Hit1·3·5 질문 | Hit1·3·5 문맥 | 운영 기준 TOP3 손실 | 운영 기준 반환 손실 | 미튜닝204 대비 새 손실 |
| --- | ---: | --- | --- | --- | ---: | ---: | ---: |
| 미튜닝204 | 32 / 34 | 16·28·33/47 | 16·28·32/47 | 13 | 16 | 0 |
| `context_both` | 36 / 37 | 17·34·36/47 | 17·33·39/47 | 7 | 9 | 2 |
| `context_blend` | 36 / 36 | 16·32·36/47 | 17·31·35/47 | 7 | 11 | 2 |

`context_both`가 같은 TOP3 손실7에서 완전 확보와 반환 손실이 더 나아 일반 법령
최종 후보가 됐다. 다만 손실0에는 도달하지 못했다. 확장이 없는 혼합 주택·상가 질문과
전체204조문 자체의 순위 경쟁에서 생긴 회귀도 남아 문맥 규칙만 계속 추가하지 않았다.

## 6. 4단계 — 최종 조합과 채택 판정

각 단계에서 남긴 `context_both + context_reference` 조합을235입력으로 새로 실행했다.
채널별 최고 수치를 합산하지 않고 실제 조합 결과만 아래에 적는다.

| 항목 | 결과 |
| --- | --- |
| DEV 완전 확보 | 질문43/75·문맥42/75 |
| 신규 필수 조문 | 일반·민법 합계26개, 민법9/9조문 |
| 운영143 대비 기존 반환 근거 손실 | 8입력 |
| 운영143 대비 일반 TOP3 손실 | 7입력 |
| 미튜닝204 대비 새 반환 근거 손실 | 2입력 |
| CIV35 | 완전 확보28/29, 민법 Hit3 29/29 |
| 판례·안내 | 235입력 보존 |
| 질의 임베딩 | 채널당 기존1회 유지, 추가 호출0 |
| 문맥 KURE 적용 | 일반+민법 합계141 채널 입력 |
| 준용 후보 발동 | 5입력, 입력당 최대2조문 |

통과한 기준은 DEV 완전 확보, CIV35 완전 확보와 Hit3, 반환 개수·출처·채널 보존이다.
실패한 기준은 운영143 대비 기존 반환 근거 손실0과 일반 TOP3 손실0이다. 점수 향상만으로
채택하지 않는다는 계획을 유지해 최종안은 **개발 개선 후보, 운영 미채택**으로 판정한다.

남은 운영 기준 손실8입력은 다음과 같다.

- DEV-005 문맥: 주택임대차보호법 제3조의6
- DEV-009 질문·문맥: 상가건물임대차보호법 제2조 / 주택임대차보호법 제2조
- DEV-010 질문: 주택임대차보호법 제3조의3
- DEV-012 질문: 민법 제114조
- DEV-015 문맥: 주택임대차보호법 제3조
- DEV-059 질문: 민법 제626조
- DEV-099 문맥: 주택임대차보호법 제3조의6

## 7. 검증과 범위

- 문맥·준용 규칙, 기존 개념 튜닝, 직전 전체 순위 비교를 묶은 관련 테스트46개가
  통과했다. 사용자명 인코딩 때문에 프로젝트 내부 임시 경로를 pytest 기준 경로로
  지정했으며 제품 동작에는 영향이 없다.
- 보존 결과의 해시·입력235건·정답·후보 데이터·KURE 모델·Chroma 인덱스·직전
  BM25 순위 일치를 검사한다. 허위 채택 판정과 자료/입력/채널 오염 거부 테스트를 포함한다.
- 전체 테스트는 **945 passed, 3 skipped, 124 subtests passed**다. LangSmith 추적
  비활성2개와 로컬 등기 PDF 미지정1개만 스킵됐다.
- clean 커밋 기반 공유 묶음 재수집은 구현 커밋 승인 후 기록한다.
- 운영 검색·데이터·인덱스는 변경하지 않았고, 푸시·PR·병합도 수행하지 않았다.

## 8. 결정

PATCH-027은 자료 공백을 제거하고 개발 검색 성능을 크게 높였지만, 사전 손실0 기준을
끝내 통과하지 못했다. 계획의 중단 조건에 따라 이 계열의 문맥 규칙·가중치 탐색을 더
반복하지 않는다. 결과와 미채택 사유를 보존하고, 운영 반영은 별도의 합의된 후속 범위가
생기기 전까지 보류한다.
