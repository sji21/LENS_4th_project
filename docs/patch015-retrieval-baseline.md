# PATCH-015 — 최신 main 검색 기준선

## 결과

PATCH-014 병합 main `697b895e461bb7dc373e5ed9556ce85af16f045a`의 검색 코드를 변경하지 않고 DEV200 및 민법35를 실제 실행했다. 235입력 모두 완료했고 운영 DB·청크·인덱스의 전후 해시가 일치했다. LLM·OCR·앱 대화 재작성은 실행하지 않았다.

|---|---:|---:|

기존 저장본과 법령·판례·안내 각각 **200입력 순위 변경 0건**이며 법령 코퍼스 140개 ID·본문 해시·판본 메타데이터도 같다. 기존 고정 목표 조문을 모두 가진 30문항에서 문맥 포함 TOP3는 21/30, TOP5는 23/30이다. 이것을 전체 서비스 정답률로 표현하지 않는다. 미보유 기본 조문은 기존과 같은 35종이다.

기본 29개 중 16개는 모두 반환, 2개는 일부만 반환, 11개는 필수 조문을 하나도 반환하지 않았다. 주차장 1개와 관찰 5개를 합쳐 35개 성공률을 만들지 않는다. TOP3와 TOP5는 **동일한 TOP5 저장 순위의 앞부분**에서 계산했다. 신규35는 민법 개선을 위한 공개 개발 자료이며 기존 DEV100보다 점수가 낮다는 사실로 성능이 퇴보했다고 결론 내리지 않는다.

## 실패 단계

민법 누락 13문항은 001·005·008·009·010·012·022·026·028·031·033·034·035이다. 해당 필수 민법 조문에 대한 검색 호출이 없었다. 005·031·034는 제623조만, 033은 제627조만 민법 검색 호출이 있었고, 나머지는 민법 호출 자체가 없었다. 일반 법령 필터는 민법을 제외한다. **보유한 민법 조문이 라우팅/필터 단계에서 후보로 들어가지 않은 사실**을 관측한 것이다. 임베딩이 그 조문을 순위 밖으로 밀었다고 해석하지 않는다.

028은 민법 제640조의 후보 누락과 함께, 상가법 제2조가 BM25/dense 후보에는 있으나 최종 TOP5에서 탈락한 현상도 있다. 실패 원인 집계는 겹치므로 후보 누락 13 + 최종 탈락 1을 14문항으로 합산하지 않는다.

다음 개선 후보는 민법 후보 진입 조건과 최종 선택의 분리다. 이번 측정만으로 전체 민법 상시 우선이나 모델 교체를 채택하지 않는다. 조건부 근거를 추가 적재·필수 검색으로 승격하지 않으며, 기존 DEV200의 별도 데이터 공백은 신규 민법29의 전부 보유와 혼동하지 않는다. PATCH-012 미채택 코드는 이관하지 않았다.

Python 3.11.9, CPU PyTorch 2.14.0+cpu, KURE-v1 로컬 스냅샷 `4ed4540949c70b7da2c74004a915e1f2d5e46e4f`. 모델 가중치·설정 해시와 의존성 버전은 manifest에 있다. 172개 인덱스 문서·메타데이터를 청크와 대조하고 DB 무결성·외래키 및 140개 조문 목록 일치를 확인했다. 원문 텍스트 대신 본문 해시·출처·순위·검색 후보를 공유한다.

실행 시 LIST와 새 수집 스크립트는 미커밋 상태였다. 정확한 main SHA, dirty 상태, 실제 실행 수집 스크립트 해시, 검색 코드 파일 해시를 기록했으며 커밋만으로 실행기가 포함돼 있었다고 주장하지 않는다. 후속 집계 스크립트는 별도 해시로 식별한다.

기존 `RetrievalService`를 상속해 `_search_one`의 원래 호출 후 `last_member_hits()`와 필터를 복사 기록했다. 검색 요청이나 반환 순위를 바꾸지 않았으며 운영 소스는 수정하지 않았다. 후보 누락은 **실제로 호출된 경로에서의 미관측**이다. 다른 경로/필터였다면 검색됐을지는 이 실험으로 판단하지 않는다.

## 재현

이 수집기는 PATCH-015 당시의 `_search_one()` 후보 추적 계약만 기록한다. 따라서 새 검색 경로가 추가된 최신 코드에서는 실행을 거부한다. 수집을 다시 실행하려면 `2841e0444060b92cb54ece1d459b75b3b1f57e5b`의 별도 체크아웃에서, 기존 준비 절차에 따라 동일한 청크·DB·두 인덱스와 로컬 모델을 준비한다. 가상환경 의존성은 프로젝트 requirements를 따른다. 운영 파일은 직접 검색하지 않고 새 출력 폴더 아래 복사본에서 사용한다.

```powershell
.venv/Scripts/python scripts/patch015_baseline.py --out tmp/patch015-new-run
.venv/Scripts/python -m scripts.patch015_report --run tmp/patch015-new-run --out tmp/patch015-new-report
```

공유 저장 결과만 다시 집계할 때는 모델·DB가 필요 없다.

```powershell
.venv/Scripts/python -m scripts.patch015_report --run data/eval/patch015-baseline/capture --out tmp/patch015-replay
.venv/Scripts/python -m pytest tests/test_patch015_baseline.py tests/test_dev100_v2.py -q
```

관련 테스트 33개 통과. 현재 로컬 가상환경에서 `DJANGO_SETTINGS_MODULE` 옵션 미인식 경고 1개가 있었다. 해당 테스트는 Django를 쓰지 않는다. 전체 제품 테스트·앱 기동은 이 측정 패치에서 수행하지 않았으므로 웹 환경 검증으로 해석하지 않는다.

조문 ID 일치는 법적 답변·필수 항호목·예외 명제 충족의 대리 지표일 뿐이다. 판례·안내 순위는 보존했지만 정확도는 채점하지 않았다. 35문항의 서비스 범위·정답 한계는 PATCH-014 기준을 그대로 따른다.
