# PATCH-012 재설계 실험 — 운영 교체 보류

## 판단

후속 [분리·통합 후보 예산 비교](patch012-candidate-sweep.md)에서는 기존 일반 법령 순위를 보존하는 14개 비교안을 추가 검증했다. 아래는 첫 통합/Qwen 실험의 기록이다.

표현별 예외를 추가하는 작업을 중단하고 **후보 검색 → 관련성 재정렬 → 출력 검증**을 분리한 시제품을 만들었다. 앱의 `RetrievalService` 기본 동작에는 연결하지 않았다. 기존 PR의 격식체 부정문 P2 두 건은 아직 남아 있으며 이 실험으로 해결됐다고 주장하지 않는다. PATCH-012는 병합 보류다.

현재 제약에서 단순 통합 검색과 설치된 Qwen 재정렬 모두 즉시 운영 교체 기준을 충족하지 못했다. 새 방식의 구현 기반과 실패 증거를 공유하고, 최종 재정렬 모델·정책의 검증을 선행한다.

## 구조 차이

| 단계 | 기존 | 실험 |
|---|---|---|
| 후보 선택 | 질문 표현으로 특정 민법 조 번호를 지정 | 민법 포함 법령 140개에서 후보 검색 |
| 순위 | 감지된 민법을 앞에 배치하고 기본 법령 자리를 줄임 | 통합 BM25와 동일 모델의 코사인 점수 통합 순위를 RRF로 합침 |
| 의도·부정 처리 | 주체·표현·예외 정규식이 조문 선택에 직접 영향 | 후보 조문 원문과 질문을 비교하는 별도 선택 단계 |
| 출력 | 선택된 민법이 바로 최종 근거 | 후보 ID·중복·질문 원문 인용을 검증, 오류는 성공적인 보류와 구분 |

조 번호별 질문 규칙·민법 고정 슬롯은 새 경로에 없다. 현행 판본·문서 종류 및 기존 상가 범위 필터는 유지한다. BM25 IDF는 민법을 포함해 다시 계산하므로 기존 일반 법령 순위도 달라질 수 있다. 물리 DB·벡터·원문 재적재는 하지 않았다.

출력 형식과 원문 인용 검증은 의미적 정확성의 보증이 아니다. 질의 분석을 LLM에게 맡겨도 잘못된 선택은 남을 수 있다.

## 고정한 실험과 결과

기존 개발셋의 정확한 200입력에 후보 TOP12를 수집했다. 후보 깊이 20, RRF k=5와 기존 BM25 설정을 사용하고 결과에 맞춰 가중치를 조정하지 않았다. 이 실험은 독립 평가가 아니다.

문맥 포함 100문항 중 기본 필수 법령을 모두 보유한 30문항 기준:

- 후보 TOP12 안에 필요한 조문이 모두 있는 문항: **26/30**.
- 후보 순위를 그대로 최종 순위로 쓰면 TOP3 모두 반환 **15개**, 누적 TOP5 **18개**.
- 현 PATCH-012의 대응 수치는 TOP3 **24개**, 누적 TOP5 **26개**. 재정렬 없이 교체하면 감소한다.
- 후보 검색 시간의 중앙값은 이 환경에서 **0.375초**였다. 모델 로딩 시간은 제외했다.

별도 [대조 입력 24개](../data/eval/civil-candidate-probes.json)를 먼저 고정하고 설치된 `qwen3:8b-q4_K_M`으로 후보 선택을 시험했다. **3개 완료 후 중단**, 나머지 21개는 중단된 호출을 포함해 완료 결과가 없다. 부정된 물 사용불능에도 제627조를 선택했고 한 입력이 약 36~63초 걸려, 이 모델·프롬프트·환경 조합은 운영 채택하지 않았다. 24개 또는 200개 재정렬을 완료한 것처럼 보고하지 않는다. 예열·캐시 효과를 통제한 지연 벤치마크도 아니다.

모델이 고른 다른 조문들의 정답 적합성은 독립 검증하지 않았다. 알려진 부정문 반례를 여전히 실패했다는 사실만으로도 지금 기본값으로 채택할 근거는 부족하다. 결과와 원시 자료 해시는 [실험 집계](patch012-redesign-experiment.json)에 보존한다.

## 실행 방법

실험 모듈은 `scripts/retrieval_experiments/candidate_pipeline.py`, 실행기는 `run_candidates.py`다. 새 의존성·모델 다운로드·외부 API 전송 없이 기존 KURE 인덱스와 로컬 Ollama만 사용했다. Ollama 호출 형식은 [공식 Chat API](https://docs.ollama.com/api/chat)를 따랐다.

```powershell
# 후보 검색만. snapshot에는 기존 capture 산출물의 data/ 디렉터리가 있어야 한다.
.venv/Scripts/python scripts/retrieval_experiments/run_candidates.py --snapshot tmp/patch012-review2-after/snapshot --queries data/eval/civil-candidate-probes.json --out tmp/candidate-probes-new
# 로컬 모델 선택 실험은 위 명령에 --rerank를 명시한 경우만 실행한다.
.venv/Scripts/python -m pytest tests/test_candidate_pipeline.py -q
```

실행기는 소스 스냅샷을 복사하고 전후 해시를 확인한다. 새 출력 폴더를 요구하며 기존 결과를 덮어쓰지 않는다. 질의 JSON은 `id`, `query`를 읽으며 평가용 `require`, `forbid`, `targets`는 검색·모델 입력에 넣지 않는다. 200입력 재현 시 기존 questions.json의 각 modes.query를 이 형식으로 펼친 파일을 제공한다. `--rerank`는 느린 실험 경로이며 운영 사용을 권장하지 않는다.

## 다음 단계의 수용 기준

1. 후보 단계에서 모든 필수 근거를 포함하는지 먼저 확인한다. 후보에 없는 조문은 재정렬기가 복구할 수 없다.
2. 최종 선택 단계는 행위자·반환 방향·부정·가정·대화 연결의 대조군으로 평가한다. 격식체 한 단어를 추가하는 방식으로 대체하지 않는다.
3. 별도 재정렬 모델 또는 구조화된 검색 질의 입력 방식을 비교한다. 모델을 쓰는 것 자체를 해결로 간주하지 않는다.
4. 기존 공개 회귀와 전체 200입력에서 후보/최종 지표·오분류·지연을 분리해 검증한 후에만 앱의 기본 경로를 바꾼다. 이번에는 최종 재정렬 200입력이나 새 경로의 공개 회귀를 완료하지 않았다.

7개의 계약 테스트는 코퍼스별 고정 순위가 없는 점수 통합, 잘못된 모델 출력 거부 등을 확인한다. 법률 의미 정확도 테스트를 대신하지 않는다.
