# PATCH-037 대화 계층 보정과 회귀 검증

2026-09-14 사용자가 법률 적용·검증은 다른 팀원이 담당하고 그 앞단의 대화 기능을 개선하도록 범위를 지정했다. 이 보고서의 완료 범위는 의도·상태·정정·후속 질문·문서 선택·오류 복구와 기존 RAG 인터페이스다. 법률 적용 정확도, 실제 최종 답변의 자연스러움과 전체 답변 지연의 수용 승인은 포함하지 않는다.

## 구현 결과

- 잘못 추출한 상담 대상·역할·건물 종류는 제외하고 나머지 판단을 엄격한 계약으로 다시 검사한다. 새 사건 전환을 놓쳤을 가능성이 있는 부가 정보 오류는 확인 질문으로 돌린다.
- 동일한 사실 제안은 완전히 같은 항목일 때만 중복 제거한다. 서로 다른 값·인용을 가진 중복이나 잘못된 금액·날짜·긍정/부정 조건은 그대로 거절한다.
- 비어 있는 항목의 미진술 모름·계약 유형 추측은 저장하지 않는다. 기존 값이나 답변 대기 항목을 잘못 바꾸려는 제안에는 이 예외를 적용하지 않는다.
- 과거 사실의 재인용은 저장된 원래 인용 또는 같은 source_turn의 원본 사용자 발언과 대조한다. 원래 출처·턴은 보존하고 다른 턴·임의 문구는 허용하지 않는다.
- 판단 거절 시 기존 기억을 보존하고 이전 상담/새 상담을 확인한다. 확인 전에는 RAG를 실행하지 않는다. 새 상담 선택은 모델 호출 전에 이전 사실·문서를 제거하며, 선택 메시지에는 원래 질문을 함께 넣어 정보가 사라지지 않게 한다.
- 모델 연결 실패는 상태 변경 없는 503으로 처리한다. 기존 웹 재시도·요청 ID·오래된 선택지 보호를 사용한다.
- 후속 질문·재설명은 직전 검증 답변의 질문 대상을 유지한다. 사실·주제·문서 변경 때는 오래된 질문 캐시를 무효화한다.

## 최종 실제 모델 회귀

실제 Qwen의 판단, 원문 입력 검사, 대화 라우터, 상태 저장과 문서 선택을 실행했다. 기존 RAG 호출 지점만 고정 테스트 응답으로 분리했다. 따라서 answered 표시는 평가용 응답이며 법률 검증 통과나 실제 답변 품질을 뜻하지 않는다. 두 결과의 소스 해시는 현재 코드와 같고 모델 identity도 동일하다.

## 남은 오차와 해석

- ACC-006 / 2의 일반적인 갱신 조건 설명 요청은 followup 기대값과 달리 explain으로 분류됐다. RAG 분기와 전세·갱신 문맥은 유지됐지만 의도 오차는 실패로 집계했다.
- DEV-004 / 2·3과 ACC-003 / 2의 검색 제외 문자열 실패는 원래 정정문 또는 이전 질문에 담긴 부정 표현이다. 활성 사실은 월세 또는 계약 미종료로 올바르게 유지됐다. 원래 사용자 문장을 보존하며 자동 실패 수치를 임의로 수정하지 않았다.
- 기존 acceptance 사례는 실패 분석에 이미 사용했으므로 이제 공개 회귀 자료다. 새로운 미공개 대화에 대한 독립 평가로 주장하지 않는다.
- 처음의 전체 RAG 수용평가 실패 결과는 [기존 보고서](chatting-acceptance.md)에 보존했다. 이 변경이 전체 답변 지연·법률 정확도까지 해결했다고 주장하지 않는다.
- 새 확인 UI는 기존 선택지 렌더러를 그대로 사용한다. 이번에는 상태·라우터·Django API·중복 요청·원자적 복구를 자동 검증했으며 새 브라우저 수동 검사를 수행하지 않았다.

## 검사와 재현

Python 1,411개 및 subtest 137개, JavaScript 5개와 Django system check가 통과했다. LangSmith 미활성 2개와 비공개 PDF 미제공 1개는 미실행이다. 이번 수정에서 src/generation·src/retrieval의 법률 생성·검증·검색 구현은 변경하지 않았다.

중간 실험인 planner-recovery-dev-01, dialogue-recovery-dev-01/02와 dialogue-recovery-acceptance-01도 보존한다. 표의 최종 두 결과만 현재 코드의 판정 근거로 사용한다.
