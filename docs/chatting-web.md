# PATCH-035 · 대화 표현과 Django 화면

새 대화 경로의 standard/simple/brief 표현은 기존 생성 프롬프트의 근거·인용 규칙을 유지한 상태에서 적용한다. 기존 호출에서 스타일을 생략하면 기존 프롬프트가 그대로 사용된다. 생성된 법률 본문은 기존 grounding과 최종 법률 검증을 통과해야 공개되며, 검증 뒤에 본문을 다시 쓰는 모델 호출은 없다.

확인 질문은 예·아니요·모르겠어요와 문서 선택 버튼을 제공한다. 자유 입력도 그대로 사용할 수 있다. 현재 확인 질문의 메시지 ID를 전송하므로 다른 질문으로 바뀐 뒤 과거 선택지를 누르면 HTTP 409로 안내한다. 중복 요청 ID의 기존 처리는 유지한다.

화면은 대화 안내·추가 정보 확인·관련 근거 부족·검증 보류·생성 실패를 구분하고, 최근 확인 문서와 쉬운 설명·요약 요청을 제공한다. 모델 HTML을 삽입하지 않고 기존 textContent 기반 렌더링을 유지한다. 공개 상태에는 필요한 질문·선택지·문서 ID만 추가하며 사실 출처와 내부 판단 자료는 보내지 않는다.

## 실제 브라우저 검증 (2026-09-13)

localhost:8000의 별도 합성 상담으로 연속 입력, 응답 대기 중 버튼 잠금, 답변·검증 보류 표시, 새로고침 후 이력 복원을 확인했다. 앞선 410은 서버 기록상 13:58→23:17 사이 9시간이 경과한 정상 만료였으며 세션 유지 결함으로 재현되지 않았다.

실제 Qwen은 보증금 상담 요청을 인사로 오분류한 사례와 확인 질문 요청을 RAG로 보낸 사례가 있었다. 일반 보증금 미반환 질문에 초과 지급 보증금 조항을 제시한 답변도 관찰했다. 검증 통과 표시가 해당 상황에 적절한 답변임을 보장하지 않는다. 이 사례들은 모델 품질 한계로 남기며 PATCH-037에서 평가한다.

확인 질문 UI는 해당 합성 대화에 서버 상태 fixture를 주입하여 별도로 검증했다. 이 방법은 화면·API 연결 검사이며 실제 모델의 확인 질문 생성 성공으로 세지 않는다. 예·아니요·모르겠어요가 표시되고 선택 시 원래 질문의 ID와 함께 제출된다.

아니요 선택 후 pending이 해제되고 실제 RAG 응답과 이전 대화 반영 표시가 나타났다. 쉽게 설명 버튼은 요청 문구를 입력창에 채웠다. 390×844 화면에서 입력창과 버튼이 겹치지 않는 것을 확인하고 뷰포트를 원복했다. 이때 계약 미종료인데 반환 의무를 바로 단정하는 부적절한 생성 문장도 검증을 통과했다. UI 전송 성공과 법률 답변 적절성은 별개이며, 이 사례 역시 최종 반영 차단 사유로 검토해야 한다.
