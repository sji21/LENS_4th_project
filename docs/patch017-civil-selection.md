# PATCH-017 — 기존 결과와 민법 후보의 최종 순위 재조합

## 결론

**비교한 고정 비중 혼합 3안 모두 비채택. 기존 운영 검색을 유지한다.** 민법 비중을 0.5로 두면 회귀가 없지만 신규 기본29의 개선도 없다. 1.0·1.5는 신규 문항을 개선하면서 기존 필수 근거를 밀어낸다. 이번 패치 안에서 비중을 더 추가하거나 정답을 바꾸지 않는다.

새 민법 후보에 유용한 조문이 있다는 사실과, 질문별 필요성을 판단하지 않고 모든 질문에 같은 비중으로 노출해도 된다는 주장은 다르다. 후속 판단이 필요하다면 질문별 민법 채택 여부를 검토해야 한다. 이 결과만으로 특정 분류기·모델·임계값의 효과까지 입증한 것은 아니다.

## 비교 방법과 고정 조건

PATCH-016 병합 main `8678c42`에서, 검증된 PATCH-015 최종 법령 TOP5와 PATCH-016 민법 RRF TOP7의 동일 235입력을 재조합했다. **새 검색 실행·새 모델 호출이 아닌 저장 순위의 오프라인 비교**다. 원래 일반 법령 후보 전체를 재검색하거나 판례·안내 순위를 바꾸지 않았다.

[사전 비교 계획](../data/eval/patch017-selection/plan.json)에 세 비중 0.5/1.0/1.5, RRF 상수 5, 동점 처리와 판단 조건을 정한 뒤 실행했다. 기존 결과와 민법 후보의 합집합을 만들고 각 조문 점수를 다음처럼 계산한다.

`1 / (5 + 기존 순위) + 민법 비중 / (5 + 민법 후보 순위)`

한 목록에 없으면 그 목록의 기여는 0이다. 같은 조문은 한 번만 반환하며 두 목록의 점수를 합산한다. 동점은 기존 순위 우선, 이후 정규화한 법령·조문 식별자 순이다. 출력 TOP5의 앞 3개로 TOP3를 계산한다. 조문 정답·질문 ID는 순위 계산에 사용하지 않는다. 기존 근거는 후보 풀에 남지만 최종 TOP3·TOP5에 반드시 유지되는 것은 아니므로 회귀를 별도 확인한다.

판단 조건은 (1) 비과거 DEV 및 신규 기본29에서 기존에 반환하던 **필수 조문 각각**이 TOP3·TOP5에서 빠지지 않을 것, (2) 신규 기본29의 전체 필수 조문 반환 수가 TOP3·TOP5 모두 개선될 것이다. 평균 정답 수가 유지되어도 문항별 근거가 빠지면 회귀로 센다. 통과했더라도 별도 실행·경계 검토 전 운영 승인은 아니다.

## 결과

아래는 **민법 부분만이 아니라 고정된 필수 법령 조문 전체**의 반환 수다. 신규29에서 상가법 등도 포함하므로 PATCH-016의 민법 후보 부분 지표와 다르다.

| 방식 | 신규 기본29 TOP3 | 신규 기본29 TOP5 | 기존 DEV 질문 단독 TOP3 / TOP5 | 기존 DEV 문맥 TOP3 / TOP5 | 근거 회귀 입력 수 |
|---|---:|---:|---:|---:|---:|
| 기존 결과 | 16 | 16 | 19 / 20 | 21 / 23 | 0 |
| 민법 비중 0.5 | 16 | 16 | 19 / 20 | 21 / 23 | 0 |
| 민법 비중 1.0 | 27 | 28 | 19 / 22 | 19 / 23 | 16 |
| 민법 비중 1.5 | 28 | 28 | 10 / 19 | 9 / 17 | 52 |

회귀 입력 수는 TOP3 또는 TOP5에서 필수 조문을 잃은 입력을 합집합으로 세며, 질문 단독/문맥을 서로 다른 입력으로 본다. 비중1.0의 16입력은 기존 DEV에서 발생했다. 비중1.5의 52에는 신규 기본 문항 1개도 포함된다. 회귀 개수와 신규 개선 개수를 합산해 서비스 성능 점수로 만들지 않는다.

기존 DEV의 비과거·필수 목표가 있는 문항은 입력별 75개이고, 이 중 45개는 필수 조문 일부 또는 전부 미보유다. 표의 기존 DEV 수치는 이 고정 모집단에서 전체 필수 조문을 반환한 건수이며 100문항 정답률이 아니다. 목표가 없는 23문항·과거 시점 2문항도 각각 별도 기록한다. 신규 범위 보류 1문항과 관찰 5문항은 기본29에 합산하지 않는다.

비중1.0에서 문맥 입력 DEV-005의 주택임대차보호법 제3조의6, DEV-009의 같은 법 제2조, DEV-010의 제3조의3 등이 TOP3 밖으로 밀린다. 이미 다른 필수 조문이 없어 전체 문항 점수가 0이던 경우에도, 가지고 있던 부분 근거의 손실을 숨기지 않는다. 그래서 질문 단독의 TOP5 전체 충족 건수가 20→22로 늘었다는 이유만으로 채택하지 않는다.

비중1.0·1.5는 비과거 DEV 각 입력 98개에서 순위를 바꾼다. 여기에는 목표 없는 문항도 있으므로 그 변경 전부를 오류라고 부르지는 않는다. 다만 민법 필요성을 판단하는 절차 없이 광범위하게 순위가 변한다는 점을 기록한다.

관련 테스트 30개 통과. 로컬의 `DJANGO_SETTINGS_MODULE` 미인식 경고 1개는 기존 환경 경고다. 전체 제품·앱 테스트는 실행하지 않았다. 본 비교는 실제 앱 대화 재작성, 실시간 후보 확보, 최종 답변 및 관련 없는 민법 노출의 법적 정확성을 평가하지 않는다. 따라서 세 안의 비채택 판단을 모든 후보 결합 방법의 불가능성으로 일반화하지 않는다.

```powershell
.venv/Scripts/python -m scripts.patch017_selection --out tmp/patch017-replay
.venv/Scripts/python -m pytest tests/test_patch017_selection.py tests/test_patch016_candidates.py tests/test_patch015_baseline.py -q
```

재집계는 저장 자료만 사용하며 모델·운영 DB가 필요 없다. 출력은 새 tmp 하위 경로를 사용한다. 실측 후보와 원래 결과를 가져오는 방식이므로 데이터나 검색 코드가 바뀌면 새 기준선이 필요하다.

## PR 리뷰 보완 — 줄바꿈 호환성

PATCH-015의 원본 코드 해시는 파일별 LF/CRLF가 혼재된 작업 트리에서 수집되었다. 재현 실행은 각 파일의 원본 바이트, LF 변환, CRLF 변환 해시를 원래 기록과 대조해 줄바꿈 차이만 허용한다. 실제 코드 내용 변경은 계속 거부하며 데이터·정책 파일의 해시 검증은 그대로 유지한다. 원래 캡처와 결과 파일은 수정하지 않는다. 수정된 실행기로 재집계한 집계·입력별 결과·판단은 기존 기록과 일치한다.
