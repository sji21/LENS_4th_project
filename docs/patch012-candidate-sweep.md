# 후보 검색 비교 — 분리 예산 8개와 통합 대조군 5개

## 결론

현재 140개 법령 조문과 DEV v2에서는 **일반 10 + 민법 5**, **일반 13 + 민법 7**을 다음 재정렬 실험의 비교안으로 남긴다. 최종 검색 경로로 채택한 것은 아니다. 정답에 필요한 근거를 후보로 확보하는 단계의 결과이며, 부정·행위자 판정이나 최종 TOP3/5 성공률이 아니다.

## 고정한 조건

- 기존 개발 질문 100개 × 질문 단독/제공 문맥 = 200입력. 별도 대조 입력 24개도 후보 수집을 완료했다.
- 일반 법령 BM25·KURE 검색과 인덱스·설정은 그대로 사용하고, 민법 7개를 별도 검색한다. 질문으로 민법 조 번호를 지정하거나 앞순위에 고정하지 않는다.
- 일반 TOP20, 민법 TOP7을 각각 한 번 검색한 뒤 사전에 고정한 예산별 후보 집합을 만든다. 서로 다른 코퍼스의 BM25/RRF 점수끼리 비교하지 않는다. 결과의 배열 순서는 최종 우선순위가 아니다.
- 통합 대조군은 앞선 통합 BM25 + 두 인덱스의 동일 임베딩 모델 코사인 점수 통합을 사용한다. RRF 내부 후보 깊이는 모든 실행에서 20이다.
- 일반/민법 후보 크기와 같은 통합 대조군을 포함해 단순히 후보가 많아서 얻은 효과를 구분한다. 27개 분리안은 넓은 후보 상한 확인용이며 같은 크기의 통합 대조군은 없다.
- 코퍼스 원문 140개 해시를 고정된 reference와 대조하고 소스 스냅샷을 복사해 실행했다. 원본 스냅샷의 전후 해시가 일치했다.

일반 13 + 민법 7은 현재 민법 코퍼스 7개를 전부 포함한다. 따라서 이를 민법 순위 모델의 성능 향상으로 해석해서는 안 된다. 민법이 확대되면 같은 예산이 충분한지 재평가해야 한다.

## 비용과 남는 누락

- 문맥 포함 입력의 후보 원문 총 글자 수 중앙값은 일반 10 + 민법 5에서 **6,729.5자**, 일반 13 + 민법 7에서 **8,438자**, 일반 20 + 민법 7에서 **11,224.5자**다. 토큰 수나 최종 재정렬 지연으로 환산하지 않았다.
- 큰 풀을 확보한 검색 시간 중앙값은 분리(일반20+민법7) **약 0.375초**, 통합20 **약 0.367초**다. 예산별로 모델을 재실행한 시간은 아니다. 고정 순서로 측정했고 예열·캐시를 통제한 성능 벤치마크도 아니다.
- 문맥 포함에서 일반 10 + 민법 5는 DEV-061·089를 놓친다. 민법을 전부 포함한 일반 13 + 민법 7 및 일반 20 + 민법 7에서는 DEV-089가 남는다.
- DEV-089는 필요한 상가건물 임대차보호법 제2조가 일반 법령 TOP20에 없다. 후보 확보 단계에서 빠진 것으로, 이 풀만 사용하는 재정렬로는 복구할 수 없다.
- 별도 부정문·주체 대조군 24개는 후보만 수집했다. 부정된 요청의 조문이 후보에 존재하는 것 자체를 오분류로 채점하지 않았다. 최종 선택의 오분류 검증은 아직 별도 과제다.

## 검증과 재현

200입력 전부에서 기존 PATCH-012가 반환하던 일반 법령들의 순서가 이번 일반 후보 풀의 앞부분과 일치했다. 통합 TOP12도 앞선 실험의 200입력 순위와 일치했다. 새로운 계약 테스트 9개와 기존 실험 테스트 7개, 총 **16 passed**. 앱 코드·기존 평가셋·운영 DB는 변경하지 않았으며 제품 전체 테스트는 이번에 재실행하지 않았다.

```powershell
.venv/Scripts/python scripts/retrieval_experiments/candidate_sweep.py --snapshot tmp/patch012-review2-after/snapshot --out tmp/candidate-sweep-new --probes data/eval/civil-candidate-probes.json
.venv/Scripts/python -m pytest tests/test_candidate_pipeline.py tests/test_candidate_sweep.py -q
```

snapshot은 기존 캡처의 로컬 산출물이며 새 클론에 포함되지 않는다. 준비 절차는 [공유 질문셋 설명](../data/eval/dev100/README.md)을 따른다. 새 출력 폴더를 사용한다. 실행 전에 예산·입력 해시를 protocol에 기록하고, 검색 이후에만 gold를 대조한다. [집계·해시·누락 목록](patch012-candidate-sweep.json)에 결과를 공유하며 원시 후보 풀은 `tmp/patch012-candidate-sweep/`에 보존했다.

PATCH-012는 여전히 초안·병합 보류다. 다음 단계에서는 위 두 후보안을 동일한 최종 선택 방법으로 비교하고, 후보 누락 DEV-089의 원인을 별도로 검토한다. 최종 검색 개선이나 격식체 부정문 P2 해결로 보고하지 않는다.
