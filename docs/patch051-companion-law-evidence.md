# PATCH-051 — 대항력·우선변제 복수 근거 전달

## 질문과 법적 기준

- 대상: 기존 공개 DEV `dev-001` — “전입신고만 하고 확정일자를 안 받으면 어떻게 되나요?”
- 고정 정답: `주택임대차보호법-제3조`, `주택임대차보호법-제3조의2` 모두 필요(AND).
- 정확한 세부 근거는 **제3조 제1항 + 제3조의2 제2항**이다. 제3조 제2항과 구분한다.
- 제3조 제1항은 주택 인도와 주민등록을 갖춘 다음 날부터의 대항력을 규정한다. 전입신고만으로 요건이 모두 충족되었다고 단정하지 않는다.
- 제3조의2 제2항은 대항요건과 확정일자를 갖춘 임차인의 경매·공매 우선변제를 규정한다. 확정일자가 없다는 사실을 계약 자체의 무효와 연결하지 않는다.
- 소액임차인의 별도 보호 등까지 모두 부정하는 결론을 내리지 않는다. 이 문항의 고정 정답은 두 조문이며 새 정답을 임의 추가하지 않았다.

공식 확인(2026-09-16): [제3조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031734053), [제3조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1031734157), [생활법령정보 대항력·우선변제권](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=2&cciNo=3&cnpClsNo=1&csmSeq=629&menuType=cnpcls&popMenu=ov). 저장 DB의 적용 법령 버전은 법률 제21065호, 시행일 2026-01-02다.

## 관측 범위와 생성 담당 전달 사항

첨부 화면에는 일반 법령으로 거래신고법 제6조의5, 주택임대차보호법 제3조, 확정일자 규칙 제9조가 보이고 민법 세 조문이 별도로 표시된다. 화면만으로 당시 코드·DB·질문 가공·모델 설정은 확정할 수 없다. 이 패치는 최신 main `42c71a1`과 재구축 DB를 고정해 재현한다.

조문 번호가 답변에 없다는 사실만으로 검색 실패라고 판정하지 않는다. 검색 결과, 실제 모델 요청에 담긴 본문, 생성된 설명은 각각 확인해야 한다.

코드 확인:

1. 웹의 legacy/dialogue 경로는 생성 graph로 들어가며 일반 법령 기본 반환 수는 3이다.
2. 단계 검색의 일반 법령 충분성은 한 건 이상 존재 여부다. 질문의 모든 필수 조문을 자동 판정하는 장치는 아니다.
3. 검색 결과의 법령 본문은 프롬프트와 native Ollama 요청 직렬화에서 유지된다.
4. 현 DB의 제3조의2는 단일 청크이며 제2항을 포함한다. 조문 제목만 있는 불완전한 청크는 모델 전달 과정에서 복원되지 않는다.
5. 가짜 HTTP 응답을 사용한 전달 테스트는 실제 graph/LCEL/요청 직렬화를 통과한다. 실제 LLM의 법률 설명 정확도나 서버 문맥 한도 내 수용을 입증하지는 않는다.

LLM 담당 후속 확인: 수정된 검색 결과를 사용하는 배포인지, 요청 본문에 제3조의2 제2항이 들어 있는지 확인한 뒤 실제 답변에서 대항력의 인도·시점 요건과 확정일자 우선변제를 구분하는지 평가한다. “확정일자 미취득 → 계약 효력이 보장되지 않음”이라는 첨부 답변의 비약은 별도로 확인한다. 이 문서는 전달용 정리이며 외부 메시지는 발송하지 않았다.

### 적용 환경 확인

이 보완은 `ExpandedLawRetrievalService`에 적용한다. 이번 실측은 재구축 DB의 `expanded-laws-record-v1` 프로필을 명시적으로 사용했다. 로컬 기본 checkout의 `data/index/retrieval-profile.json`에도 같은 정책이 있고 현재 셸/로컬 `.env`의 `LENS_CASE_RETRIEVAL_PROFILE` 지정은 확인되지 않았다. 첨부 화면을 만든 실행 프로세스의 환경은 별도다.

- `lens-case-internal-v1`은 PATCH-043 내부 실험용으로 보관됐으며 제품 로더는 명시적으로 거부한다. 이 과거 선택 경로는 현재 적용 대상이 아니다.
- 구형 봉인 bundle `lens-case-retrieval-v1`은 별도 기본 법령 서비스를 직접 생성하므로 이 변경이 적용되지 않는다. 해당 팀원 프로필은 변경하지 않았다.
- expanded manifest가 없는 구형 설치에도 적용되지 않는다. 기존 설치 절차로 프로필·자료를 확인해야 한다.
- 웹 서비스는 검색 객체를 캐시한다. 코드 반영 뒤 프로세스를 재시작하고 실제 활성 서비스/프로필과 모델 요청을 확인한다. 이 작업에서 운영 앱 재시작·배포는 하지 않았다.

## 재현과 평가 계약

### 구현 범위

`src/retrieval/companion_evidence.py`에서 현재 질문의 권리 효과를 판별한다. 법령명의 “보호”, 발급 장소·수수료의 “차이”, 인용·이전 대화가 조건으로 잘못 쓰이지 않도록 분리한다. 확정일자가 언급되지 않은 경우에는 전입신고만으로 보증금 보호에 충분한지 묻는 제한된 조건을 쓴다. 주소 이전 후 권리 유지 질문까지 확대하지 않는다.

선택할 두 조문은 같은 법령명·판본·시행일의 현행 법률이어야 한다. 대항력 본문과 우선변제의 긍정적인 권리 문장, 조·항의 직접 참조관계가 맞아야 한다. 제목·교차참조 단어만으로 근거로 인정하지 않는다. 질문 ID나 고정 정답 조문 번호로 결과를 끼워 넣지 않는다.

`expanded.py`에서 기존 BM25·KURE 결합 후보20 안의 연결된 두 근거를 앞3건에 배치한다. 1위는 유지하고 남는 자리는 원래 순위로 채운다. 후보 밖의 조문을 추가하지 않으며, 원문·검색 점수·모델 호출·기존 세금 선택·민법 채널을 변경하지 않는다. 1~2건 예산과 메타데이터가 불완전한 구형 자료에는 이 보완을 적용하지 않는다.

이 정책은 모든 법령의 복수 근거 문제를 해결하는 일반 엔진이 아니다. 현재 법령 본문의 주택 대항력·확정일자 우선변제 관계에 한정하며, 새로운 표현·법령 개정·후보 밖 누락은 별도 검증이 필요하다.

### 측정 조건

`scripts/patch051_companion_eval.py`로 수정 전/후 각각 같은 실제 BM25+KURE 검색을 수행한다.

- 고정 DEV100 v2 질문/문맥 200입력 + 민법35 = 235입력.
- 공개 회귀: 기존 법령 DEV24, HOLDOUT18, 민법15, 판례 DEV13·외부표현8 = 78문항. 이미 공개·튜닝에 노출된 자료이며 독립 평가가 아니다.
- 법령 반환은 **3건과 5건을 각각 실제 호출**하고 민법은 별도 최대3건, 판례 최대5건, 안내 최대2건이다. 판례는 법령 예산3일 때에도 판례5건이다.
- DEV100은 모드별 채점 대상75, 민법35 중 필수29만 주 지표에 포함한다. 나머지는 진단·보류로 보존한다.
- 단일 채널 Hit는 하나 이상, 완전 확보는 모든 고정 정답의 포함 여부다. 조 단위 평가와 제2항 본문 전달 검증을 구분한다.
- 변경된 순위와 기존 정답 손실은 각 입력·법령 예산별로 비교한다. 일반·민법을 합쳐 단일 순위를 만들지 않는다.
- 코드·자료·논리 인덱스·모델·정답·설정의 해시와 실행 전후 동일성을 기록한다. 생성 모델은 호출하지 않는다.
- 과거 gold가 현 코퍼스에 없는 판례 legacy20은 이번78에 포함하지 않는다. 과거 제외를 통과로 바꾸지 않는다.

실행 예(저장소 루트, UTF-8 Python):
