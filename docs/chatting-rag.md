# PATCH-034 · 문맥 검색과 문서 연속 상담

현재 사용자 원문 전체와 출처가 확인된 활성 진술로 검색 질문을 구성한다. 금액·날짜는 원문 값을 그대로 쓰며 정정 후에는 새 값을 활성 진술로 사용한다. 이전 계약 종류가 부정문 안에 등장하는 원문은 지우지 않는다. 가정 질문을 사실로 바꾸거나 숫자를 새로 계산하지 않는다.

소유 문서 ID, 파일명, 업로드 순서와 문서 종류로 대상을 좁힌다. 문서가 여러 개이고 대상이 불분명하면 모델이나 검색이 임의로 하나를 고르기 전에 선택을 요청한다. 계약서와 등기의 값은 검색 근거로 유지하고 사용자 진술 항목으로 복사하지 않는다. 선택 문서의 후속 질문은 이어가되, 새 일반 법률 질문은 문서 검색과 분리한다.

문서 질문에서 모델의 사실 제안이 거절되더라도, 입력·소유권 검사를 통과한 선택 자체는 기존 문서 RAG 경로에서 사용할 수 있다. 답변이 성공하면 해당 문서를 다음 질문의 활성 문서로 저장한다. 잘못된 금액·날짜 제안은 저장하지 않는다. 문서 삭제 시 기존 규칙대로 메시지와 파생 대화 상태를 함께 비운다.

일반 법령·민법·판례·기관 안내와 업로드 문서의 자료형, 기존 검색 결과 채널과 법률 최종 검증은 유지한다. 선택한 문서의 근거만 전달하는 API 테스트, 정정·가정·원문 금액 보존, 문서 종류·순서·모호함·외부 ID 거절을 검증한다. 전체 수용평가에서 질문 원문·활성 진술·실제 검색문을 함께 대조한다.

[실제 문서 표본](../data/eval/chatting/results/document-dev-sample.json) 2턴은 같은 계약서의 금액·수리 특약 질문을 answered로 완료했다. 호출은 3회·2회, 지연은 19.593초·14.258초였다. 실행 중 코드·모델·검색 데이터는 동일했으며 사용자 금액 진술을 만들어 저장하지 않았다. 이후 일반적인 계약서 작성 질문을 문서 선택으로 가로채지 않는 참조 구분을 단위 검사로 추가 확인했다. 전체 최종 소스의 실제 수용평가는 PATCH-037에서 수행한다.

두 실제 턴 모두 판단 제안의 출처·모름 오류로 `legacy_fallback`을 사용했다. 행동·문서 검색은 통과했지만 의도는 두 턴 모두 관측되지 않았으므로 모델 의도 성공률로 세지 않는다. 전체 자동 검사 1,368개와 137개 subtest 통과, 선택적 외부 추적 2개·개인 PDF 1개 미실행.
