# PATCH-033 · 확인 질문과 상담 재개

확인할 항목은 대화 모델이 고르고, 사용자에게 보여줄 질문은 코드가 작성한다. 계약 종료·거주·퇴거·보증금 수령 질문은 긍정형으로 통일해 예/아니요의 의미가 뒤집히지 않게 한다. 한 번에 한 항목만 확인한다.

제공한 선택지의 정확한 값(예·아니요·모르겠어요, 계약 종류)은 대기 중인 항목에 연결한다. 자유로운 표현, 답변 거부, 중간의 새 질문은 기존 Qwen 판단을 사용한다. 모름은 부정이나 금액·날짜로 바꾸지 않고 미확인 상태로 저장한다. 확인 질문 자체가 없는 단답을 임의의 사실에 붙이지 않는다.

알려진 값과 모름은 다시 묻지 않는다. 같은 상담에서 항목별로 최대 두 번 확인하고, 이후에는 사용자 원문과 알려진 정보로 RAG를 실행한다. 답하지 않은 항목을 자동으로 채우지 않는다. 확인 횟수·대기 질문·출처는 기존 Django JSON 상태에 저장하며 주제가 바뀌면 새 상담의 횟수를 사용한다.

API는 확인 질문에 `reason=needs_information`과 선택지를 제공한다. RAG 결과는 `no_evidence`, `validation_failed`, `generation_failed`로 구분하며 기존 공개 본문을 유지한다. 처리 예외는 기존 HTTP 503으로 보고하고 상태를 반영하지 않는다. 기존 경로로 복귀한 답변은 기존 상태 표기를 유지하며 세부 실패 원인을 추측하지 않는다.

자동 검사 1,354개 및 137개 subtest 통과. 선택적 외부 추적 2개·개인 PDF 1개는 미실행이다. DB 저장 후 새로고침·다음 HTTP 요청에서 단답 연결, 중복 요청, 반복 상한과 보류된 답변의 사용자 진술 보존을 검증했다. 선택지는 PATCH-035의 화면에서 연결한다.

[실제 개발 표본](../data/eval/chatting/results/clarification-dev-sample.json) 2턴은 모두 기존 법률 검증 후 answered로 종료됐다. 모름 상태를 유지하고 행동·의도·필수 사실 검사를 통과했다. 호출은 턴당 3회, 지연은 32.370초와 35.205초였으며 코드·모델·검색 데이터는 실행 중 동일했다. 전체 수용평가와 구분한다.
