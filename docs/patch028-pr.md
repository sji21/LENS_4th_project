# PR 본문

## 목적과 결과

여러 준비·검증·백업·적재 명령을 따로 실행하던 로컬 DB 적용을 인자 없는 `manage-data.ps1` 실행의 DB 체크→필요한 데이터 적용→확인 흐름으로 묶었습니다. 검증된 확대 묶음을 메인 작업 폴더에 실제 적용해 일반 법령178·민법26조문을 사용하며, 사전·사후235입력 모두 기존 최종 검색 결과와 일치했습니다.

## 주요 변경

- 3단계 진행 표시·필요할 때만 원본 폴더 입력·상세 로그 파일 보존.
- `setup_data.py`로 Python 가상환경·필요 모듈 설치·KURE 모델 준비 후 DB 실행. 데이터 폴더의 의미·전달 파일 구성·맥 명령을 간편 실행 안내에 포함.
- DB가 없는 새 작업 폴더에 검증된 묶음 최초 설치. 사후 실패 시 이번에 설치한 파일만 보존 폴더로 옮기고 저장소 평가 자료 유지.
- 전체 파일·프로필·Chroma 내용과 조문/청크 중복 검사. 같은 데이터 재실행은 적재·백업 없이 종료.
- 상태 검사는 임시 사본에서 수행해 Chroma의 내부 재저장이 실제 파일에 영향을 주지 않음.
- 동시 적용/복구 차단, 사전 확인·자동 백업·사후 확인·실패 시 원본 복구 연결.
- 실제 메인 DB 적용 기록과 팀원용 실행·복구 문서 제공.

## 검증

- 메인 적용 전후 각각235/235입력, KURE각375호출, 네 채널 순위·본문·출처 일치.
- 적용 완료 뒤 반복 명령에서 전체 데이터 바이트 동일·새 백업0개.
- 메인 적용 후 전체1,135통과·3건너뜀·172subtests. 이후 한 번 실행하는 화면 흐름·로그 보존까지 포함한 관련24통과.
- DB·청크·프로필·인덱스 중복/불일치, 동시 실행, 사후·완료 기록 실패 복구 테스트.
