# PR 제목

feat(data): 원천 기반 서버 DB 구축·Django 관리 명령과 중복 방지 (PATCH-028)

# PR 본문

## 목적과 결과

팀원이 완성된 DB ZIP을 받아야 했던 설치 경로를 원천 기반 서버 구축으로 바꿉니다. 기본 `setup_data.py` 실행이 가상환경·필요 모듈·KURE 모델을 준비한 뒤 승인 원천 파싱→SQLite 저장→일반/민법 인덱스 구축→검증·적용을 수행합니다. Django와 로컬/RunPod 개발 환경이 같은 관리 명령을 사용하며, 웹 이용자에게 데이터 설치를 요구하지 않습니다.

## 주요 구현

- `python manage.py prepare_retrieval` 제공. 웹 요청·앱 시작마다 무거운 구축을 실행하지 않음.
- 승인 원천 스냅샷에서 일반 법령178·민법26·판례26·안내6청크 구성. DB·기존 벡터 없이 최초 구축 가능.
- 원천·코드·모델이 같으면 재구축 생략. 변경 청크만 임베딩하고 같은 본문의 메타데이터 수정은 벡터 재사용.
- 별도 작업 폴더에서 구축·검증 후 기존 데이터 백업·교체. 실패 시 복구하며 Django 계정·대화 DB는 유지.
- 원천 해시·판본·조문 중복·SQLite 무결성·인덱스 내용/채널·기본 검색 연결 검사. 원천/대상이 구축 중 변경되면 적용 중단.
- 초기 ZIP 설치 도구·235입력 재현 자료는 `--validation-bundle` 검증 경로로 유지. 일반 설치의 기본 경로가 아님.
- README에서 간편 설치를 먼저 안내하고, RunPod 영구 데이터·HF_HOME 캐시 설정과 수동 재생성 절차를 구분.
- `--venv-dir`로 RunPod 가상환경을 내부 디스크에 배치하고 모든 준비/구축 하위 프로세스에 같은 Python 사용. 기본 Windows·Mac `.venv` 유지, 기존 환경 자동 이동/삭제 없음.

- 구축·검증 하위 프로세스의 진행·경고를 터미널과 로그 파일에 동시에 출력. 출력 중단 시 하위 프로세스를 종료한 뒤 설치 잠금을 해제.

- 일반/판례/안내210개 + 민법26개 벡터 최초 생성. 명시적 재구축 시236개 모두 재사용, 문서 재임베딩0.
- 일반 재실행: 원천·코드·모델 동일 판정, 전체 적재 파일 바이트 동일, 새 구축 폴더0.
- 기존 법령204·판례26·안내6청크와 본문·논리 조문 범위 일치. 예전 순번을 사용한 법령 내부 청크 ID129개는 현재 적재 형식으로 변경됨. 기본 법령/민법 출처 URL은 정확한 판본·조·가지번호로 생성.
- 전체1,168 passed·3 skipped·172 subtests passed (`9e50649`). 이후 진단 로그·출처 URL 보완 포함 관련55 passed.
- Django `config.settings` 시스템 검사 통과: 로컬 키가 없어 프로세스 임시 키를 사용했고 `.env`는 수정하지 않음.
- 가상환경 경로 보완 후 관련64 passed: 외부/공백 경로, 기본·검사·준비 전용·검증 묶음의 인터프리터 일관성, 기존 환경 보존, 설치 실패 중단 검증. 기존 Windows 환경을 명시한 실제 `--check`도 통과. 사용자/팀원의 Mac 기본 실행 성공 보고를 별도 표시.

- 실시간 로그 보완 후 관련68 passed. 실제 짧은 하위 프로세스의 stdout/stderr 동시 보존, 종료 전 진행 출력, 실패 로그 보존, 출력 오류/중단 시 프로세스 정리를 검증.

## 범위와 한계

PATCH-027 의존, 관련 이슈 없음. 검색 정책·LLM 동작은 변경하지 않습니다. 기본 입력은 승인 원천 스냅샷이며 최신 법령을 자동 수집·채택하지 않습니다. 기존 판례26건 시드와 기관 안내 수집 레코드를 재사용합니다.

실측은 준비된 Windows 가상환경·KURE 캐시에서 수행했습니다. Mac 기본 실행은 사용자/팀원 성공 보고이며 세부 단계·검색 수치를 독립 검증하지 않았습니다. RunPod 네트워크 볼륨의 패키지 설치 지연을 보고받아 내부 디스크 가상환경 옵션을 추가했으나, 해당 옵션의 실제 설치 시간·GPU·LLM 기동은 아직 검증하지 않았습니다. 내부 디스크 소실 시 패키지 재설치가 필요하며 DB·모델은 별도 영구 볼륨에 유지합니다. 일반 구축은 기본 검색 연결 검사이며 전체235문항 순위·LLM 답변 평가를 설치마다 수행하지 않습니다. 재생성한 내부 청크 ID·벡터 파일 해시가 기존 고정 평가와 같다고 주장하지 않습니다.

기존 메인 DB는 이번 서버 구축 검증에서 교체하지 않았습니다. 다른 방식으로 만든 DB의 전환은 `--rebuild`로 명시하며, 프로젝트 data/tmp는 같은 파일시스템에 둡니다. 손상된 기존 구축 자료는 자동 수리하지 않습니다.
