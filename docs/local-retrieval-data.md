# 로컬 검색 데이터 적용

검증된 PATCH-027 데이터 묶음을 기본143조문(일반133·민법10)에서204조문(일반178·민법26)으로 전환합니다. SQLite·청크·기본/민법 Chroma 인덱스·검색 프로필을 함께 적용합니다. 데이터는 Git에 포함되지 않으므로 팀원마다 검증된 확대 데이터 폴더를 준비해야 합니다.

## 실행

프로젝트의 `.venv`와 KURE 모델을 준비하고 앱을 종료한 뒤 저장소 루트에서 실행합니다.

```powershell
.\manage-data.ps1
```

화면에는 **[1/3] DB 체크 → [2/3] DB 적용 → [3/3] 결과 확인** 순서로 표시합니다. 같은 데이터가 있으면 추가 불필요·변경 없음으로 종료합니다. 적용이 필요한 경우에만 검증된 확대 데이터 폴더를 입력받습니다. 원본이 없는 상태에서 자동으로 임의의 법령을 수집하거나 선택하지 않습니다.

자동 실행 환경에서는 `.\manage-data.ps1 -Source '<검증된 데이터 폴더>'`로 원본을 지정합니다. 입력을 받을 수 없는데 원본도 없으면 대기하지 않고 오류로 종료합니다. 단계별 상세 로그와 백업 경로는 실행 폴더에 남깁니다.

상태만 보려면 `.\manage-data.ps1 status`, 복구하려면 `.\manage-data.ps1 restore -Backup '<안내된 백업 폴더>'`를 사용합니다. PowerShell 대신 `.venv/Scripts/python -X utf8 -m scripts.manage_retrieval_data`도 인자 없이 같은 흐름을 실행합니다. 실행 오류는 종료 코드1, 인자 오류는2입니다.

## 중복·손상 방지

- 동일 프로필 이름만 보지 않고6개 파일의 SHA-256과 두 Chroma 인덱스의 문서·메타데이터·벡터를 검증합니다. 이미 같은 묶음이면 재적재·백업·검색 재실행 없이 종료합니다.
- 파일 내 청크 ID, 법령명·조문·판본, SQLite 조문 키 중복을 검사합니다. 전체 법령 파일에 민법이 포함되고 민법 전용 파일에도 같은 자료가 있는 것은 의도된 구성으로, 두 사본의 내용이 정확히 같은지 검사합니다.
- 상태·중복 검사는 임시 사본에서 실행합니다. Chroma가 읽기 중 내부 파일을 재저장하더라도 실제 데이터에는 영향을 주지 않으며, 별도 검증 프로세스가 종료된 다음 사본을 정리합니다. 상태 확인·적용·복구 명령은 같은 OS 잠금을 사용하며 프로세스 종료 시 잠금은 해제됩니다.
- 기존143조문과 다른 데이터나 부분 적재 상태는 자동으로 덮어쓰지 않습니다. 새 클론의 최초 기본 데이터 생성은 README6.4~6.5 절차가 필요합니다. 이 도구는 승인된 확대 묶음 적용용이며 임의의 새 법령/판본을 자동 채택하지 않습니다.
- 적용 전 코드 커밋과 깨끗한 작업 트리가 필요합니다. 폴더는 `tmp/retrieval-data/<시각-고유번호>/`에 자동 생성하고 재사용하지 않습니다.
- 교체·백업 기록 실패는 기존 적재 도구가 원본을 복구합니다. 적용 후 검색 검증 또는 완료 기록 저장이 실패하면 간편 명령이 백업을 복구합니다. 복구 자체가 실패하면 오류를 반환하며 백업과 실패 자료를 보존합니다.
- 다른 초기화/직접 적재 명령이나 앱과 동시에 실행하지 않습니다. 이 잠금은 이 간편 명령 간의 동시 실행을 막습니다.

## 기록과 확인

각 실행 폴더의 `preflight/`, `postflight/`, `backup/receipt.json`, `result.json`에서 검증·백업 결과를 확인합니다. `status`의 `baseline`은 일반133·민법10, `installed`는 일반178·민법26입니다. 판례26·안내6은 그대로 유지합니다. 사후235입력 확인은 기존 최종 검색 결과와의 재현 검사이며 새로운 독립 평가나 LLM 답변 평가가 아닙니다.
