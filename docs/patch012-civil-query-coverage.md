# PATCH-012 — 민법 검색 조건 보완

기존 DB에 있는 민법 제626·627조가 질문 표현 때문에 검색 대상에서 빠지던 세 문항을 보완한다. 법령 데이터와 기본 검색 가중치·반환 건수는 유지한다.

## 변경과 한계

- 수리 완료 또는 수리비 지출에 연결된 `비용을 돌려달라`는 요청을 제626조에 연결한다.
- 수리비 지출이 이전 대화에 있고 `먼저 낸 금액은 누구에게` 묻는 후속 표현도 인식한다. 다른 금전 목적이 있으면 새 간접 연결은 보수적으로 제외한다.
- 단수·배관 공사와 물 사용불능이 같은 문장에 명시된 경우 제627조를 연결한다. 공사·숙박비 언급 하나만으로 발동하지 않는다.
- 기존 PATCH-010 계약금 반환 반례, 비용을 지급하지 않은 상황, 반환 요청·사용불능을 부정하는 사례를 회귀 테스트에 포함한다.

이는 관련 조문을 검색하는 조건이다. 비용 상환·손해배상·감액이 법적으로 인정된다는 판정이 아니다. 제한된 한국어 표현 규칙이며 모든 부정문·대화 주체·복합 금전 관계를 해석하지 않는다. 기존 민법 키워드 경로의 한계도 남는다. 신규 법령 적재·항호목 검색·LLM 변경은 없다.

## 실제 검색 결과

병합 main `b6844d3`에서 수정 전 200입력을 다시 측정했다. 법령·판례·안내 순위가 PATCH-011에 보존한 순위와 모두 일치했다. 동일 원본 데이터 해시·모델·검색 설정으로 수정 후에도 200입력을 실행했다. 각 실행은 원본 대신 복사본을 사용했으며 원본 자료는 변경되지 않았다.

| 문항 | 입력 | 필요한 조문 | 변경 전 → 후 |
|---|---|---|---|
| DEV-057 | 질문 단독·문맥 포함 | 민법 제626조 | TOP5 없음 → 1위 |
| DEV-058 | 질문 단독·문맥 포함 | 민법 제627조 | TOP5 없음 → 1위 |
| DEV-059 | 문맥 포함 | 민법 제626조 | TOP5 없음 → 1위 |

법령 순위 변경은 위 5입력뿐이고 나머지 195입력은 동일하다. 판례·기관 안내 순위는 200입력 모두 동일하다. DEV-059의 질문 단독에는 수리·지출 연결 정보가 부족해 기존 결과를 유지한다.

문맥 포함 기본 필수 법령 진단은 TOP3 모두 반환 21→24문항, **누적 TOP5 모두 반환 23→26문항**이다. TOP3에서는 부족하고 TOP5까지 보면 모두 반환한 문항은 2개 그대로다. 모두 보유했으나 TOP5에서 놓친 문항은 7→4개다. 데이터 부족 분류와 미보유 기본 조문 35개는 변하지 않았다. 전체 문항 정답률이나 독립 평가·LLM 성능으로 해석하지 않는다.

## 검증

### 두 번째 PR 리뷰 정정: 부정된 임대인 수리

`집주인이 수리를 안 해줘서 제가 보일러를 교체했어요. 비용을 돌려달라고 할 수 있나요?`와 부정·거절 변형 3개가 첫 정정의 주체 차단 조건에 걸리는 것을 재현했다. 임대인 다음의 수리 명사를 보는 대신, 임차인 주어로 전환되기 전 실제 수리 완료·지출·반환 요구 표현을 확인한다. 부정된 수리 의무와 임차인의 실제 수리를 구분하고, 임대인이 실제로 수리한 기존 반례도 유지한다.

새 양성 4개와 실제 임대인 수리 음성 1개 추가 후 관련 테스트 136 passed·86 subtests, 전체 696 passed·3 skipped·124 subtests다. 아래는 이전 단계의 검증 이력이다.

`tmp/patch012-review2-after`에서 200입력을 재실행했다. 최초 구현의 법령·판례·안내 순위가 모두 유지됐고 공개 회귀 지표·순위도 동일했다. 검증 JSON은 이 최신 정정 코드·결과 해시를 기록한다.

### PR 리뷰 정정: 임대인의 비용 요구와 구분

코덱스가 지적한 `보일러가 고장 나서 집주인이 수리했어요. 집주인이 수리비를 돌려달라고 하는데 제가 내야 하나요?`는 임차인이 지출한 비용의 반환 청구가 아니다. 수리 완료만 확인한 새 연결 조건이 이를 제626조에 연결하는 문제와 변형 3건을 재현했다.

새 간접 상환 경로에서는 임대인이 수리·비용 요구의 주체로 나타나는 문장을 제외한다. `집주인에게` 반환을 요구하는 방향과 `집주인이 연락이 안 돼서 제가` 수리한 경우는 유지한다. 임차인 주어로 전환되는 표현도 확인한다. 여러 주체의 비용이 복합적으로 얽힌 상황은 보수적으로 제외할 수 있으며, 기존 키워드 경로 전체를 의미 분석하도록 바꾼 것은 아니다.

리뷰 반례 4개와 정상 방향 사례 2개를 추가했다. 정정 후 관련 테스트 131 passed·86 subtests, 전체 691 passed·3 skipped·124 subtests다. 아래 최초 구현의 검증 기록과 구분한다.

`tmp/patch012-review-after`에 200입력을 다시 캡처해 수정 전 구현의 법령·판례·안내 순위와 전부 일치함을 확인했다. 최초 기준선 대비 5입력 개선도 유지되며 기존 공개 회귀 지표·순위는 동일하다. 검증 JSON의 수정 후 코드 해시·원시 결과 해시는 이 정정 실행 기준으로 갱신했다.

- 새 회귀 19개: 수정 전 양성 8개 실패·음성 11개 통과, 수정 후 모두 통과.
- 관련 테스트 125 passed, 86 subtests passed.
- 전체 테스트 685 passed, 3 skipped, 124 subtests passed. 스킵은 비활성 LangSmith 2개·비공개 PDF 1개다.
- 공개 법령 Dev 24문항·기존 공개 Holdout 18문항·민법 15문항의 지표와 법령 순위가 기존 회귀 기록과 일치했다. Hit@3는 각각 100%, 94.444%, 80%다.
- 코드·데이터 해시와 5입력 순위 변경, 집계는 [검증 자료](patch012-civil-query-coverage.json)에 보존한다. 평가셋 원문·정답·기존 기대 결과를 수정하지 않았다.

## 재현

프로젝트 의존성·KURE 모델·172개 인덱스 레코드(기본 165 + 별도 민법 7)가 준비된 환경에서 실행한다. 데이터 준비는 [DEV 입력 설명](../data/eval/dev100/README.md)을 따른다. 아래는 저장소 루트 기준이며 새 출력 폴더를 사용한다.

```powershell
# 수정 전 기준 코드에서 별도로 캡처
.venv/Scripts/python scripts/dev100_diagnostics/capture.py --out tmp/patch012-before
# 수정 후 코드에서 캡처
.venv/Scripts/python scripts/dev100_diagnostics/capture.py --out tmp/patch012-after
.venv/Scripts/python -m pytest -q
.venv/Scripts/python scripts/dev100_diagnostics/repair_public_regression.py --run-dir tmp/patch012-after --baseline-report tmp/patch008/regression-final.json
```

두 캡처 사이에는 코드 전환이 필요하다. 같은 코드에서 두 명령을 실행한 것은 전후 검증이 아니다. 캡처 manifest의 코드 파일 해시·입력/모델/설정을 함께 대조한다. 공개 회귀 명령에는 기존 로컬 PATCH-008 보고서가 필요하다. 원시 캡처에는 데이터 복사본이 포함되어 Git에 올리지 않았으며 위 검증 자료에 결과 파일 해시를 보존한다.

다음 과제는 필요한 법령 추가 적재다. 일반 법령 순위 누락 DEV-044·050·068·089는 코퍼스 확장 후 별도로 재평가한다.
