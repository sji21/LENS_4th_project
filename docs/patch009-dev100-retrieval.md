## 재현 조건

- 코드: `71a7c90` 기반 `test/patch-009-dev100-retrieval`. 실행 시 기록 변경만 있으며 `src/` 변경 없음.
- 원본: 2번 AI 검색채점 보완본을 보존한 `data-plan-v2-20260909/gold-supplement-frozen.md` 및 `effective-requirements.json`. 부록 26개 우선, 나머지 74개 원문 근거 유지.
- 입력: `dev100-20260909/results-final.json`의 수정 완료된 두 입력 문자열을 그대로 재사용. 공유 시나리오 관리 표기는 앞선 입력 정리 결과를 따르며 정답 근거는 검색 입력에 넣지 않음.
- 모델: 로컬 KURE-v1. Python 버전, 검색 설정, 코드·입력·데이터 해시는 산출물 `manifest.json`에 보존.
- 반환 건수: 법령 TOP5, 판례 TOP5, 기관 안내 최대 TOP2. 앱에서 사용하는 법령 TOP3의 통합 성능과 동일한 지표가 아님.
- DB와 두 인덱스의 복사본에서 실행. 140개 법령 청크 + 판례 26개 + 안내 6개, 총 172건의 인덱스 ID·본문·메타데이터 일치 검증. DB 무결성·외래키 검사 통과.
- 운영 DB·청크·두 인덱스 전체 파일의 실행 전후 해시 일치. 결과 100개, 입력 200개, 문항 중복 없음. 실제 결과와 각 입력은 `results.json`에 보존.

기존 민법 적재 전 결과와 비교하면 법령 TOP5 순위가 질문 단독 11건, 문맥 포함 12건에서 달라졌다. 이는 데이터 추가와 PATCH-008 코드 수정의 결합 차이이며 개선·악화 개수나 독립 정확도가 아니다.

## 조문 인용 진단의 제한

명시된 근거 역할별 조문 인용만 DB와 대조했다. 성공 기준 설명의 생략 인용을 앞의 다른 법령에 연결하지 않도록 제외했다. 진단표는 필수·조건부·대체·보조 원문을 함께 보여준다.

| 명시 인용 조문 대조 | 문항 수 |
| --- | ---: |
| 인용 조문 전부 미보유 | 28 |
| 일부 보유 | 29 |
| 모두 보유 | 35 |
| 인용 조문 없음 | 8 |

이 수치는 데이터 충족률이 아니다. 미보유 인용 조문 54종에는 조건부·대체·보조 자료도 포함된다. 약칭, 생략, “이하”의 범위는 자동으로 채우지 않았으므로 완전한 추가 적재 목록도 아니다. 보유 여부는 조문 식별자의 일치이며 평가 기준일 판본의 일치까지 보증하지 않는다.

원본 근거 상태는 검증 완료 89개, 일부 미확인 11개다. 일부 미확인을 일괄 제외하거나 조건부 문항의 사실 부족을 정답 결함으로 처리하지 않았다. 판례 원시 반환은 보존했지만 사건 적합성을 재판정하지 않았다.

항·호·목 구조는 DB에 존재해도 현재 검색이 조 단위이므로, 문항별 필수 구간·예외의 의미 충족은 별도 검토 대상으로 남긴다. 기관 안내도 제목 반환만으로 특정 약관 구간의 충족을 확정하지 않는다. 따라서 전체 정답률은 산출하지 않았다.

## 팀 공유 입력 보완

개발용 질문셋은 팀원이 공유하고 재현할 입력이므로 `data/eval/dev100/`에 100문항·200개 정확한 검색 문자열, 정답 검토 원문, 부록을 적용한 근거 목록, 기존 법령 순위와 파일 해시를 추가했다. 독립 평가셋은 포함하지 않았다. 최초 PR에서 로컬 입력을 누락했던 점을 정정한다.

정답 근거는 검색 입력과 별도 파일에 저장한다. 기존 질문·검색 문자열은 전부 동일하고 정답 검토 원문·근거 JSON은 바이트 단위로 보존했다. 플랫폼의 줄바꿈 변환으로 해시가 바뀌지 않도록 데이터 파일의 Git 속성을 지정했다. 민감정보 패턴 검사에서 탐지 없음.

공유 파일을 사용하는 새 캡처를 200개 입력 전체에 실행했다. 기존 PATCH-009 원시 결과와 질문·유효 근거, 법령·판례·안내의 순위·본문·URL이 모두 일치했다. Git 인덱스에 저장된 실제 데이터 바이트의 SHA-256도 공유 manifest와 일치했다. 원래 CRLF와 Markdown의 줄바꿈용 공백은 데이터 파일에 한해 보존한다.

## 산출물과 실행

로컬 산출물 위치: 저장소의 상위 폴더 아래 `질문제작평가/3. 구현 담당 AI — 범위 점검과 데이터 부족 분석부터/patch009-dev100-20260909/`.

- `manifest.json`, `audit.json`: 실행 조건, 해시, 운영 자료 불변 확인.
- `results.json`, `progress.jsonl`: 100문항·200입력의 원시 결과.
- `items.md`, `diagnostics.json`: 근거 역할·보유 여부·조문 순위·안내 반환.
- `missing-anchors.md`, `summary.json`: 미보유 인용과 집계.
- `snapshot/`: 실행에 사용한 DB·청크·두 인덱스.

재현 도구는 `scripts/dev100_diagnostics/capture.py`, `report.py`에 보관한다. 입력은 기본적으로 저장소의 `data/eval/dev100/`를 읽으며 기존 개인 폴더나 과거 원시 결과 파일이 필요하지 않다. `--dataset`으로 다른 버전을 지정할 수 있다. DB·청크·모델·인덱스는 별도 준비해야 한다. 캡처는 기존 출력 폴더가 있으면 중단하며 `--out`으로 새 경로를 지정한다. 보고서 재생성은 `--run-dir`의 파생 진단표만 갱신한다. 입력 파일별 해시를 확인한 후 실행한다.

```powershell
.venv/Scripts/python scripts/dev100_diagnostics/capture.py --out tmp/dev100-team-run
.venv/Scripts/python scripts/dev100_diagnostics/report.py --run-dir tmp/dev100-team-run
```

일회성 진단 도구이므로 범용 평가 CLI나 최종 AND/OR 채점기로 표현하지 않는다. 제품 테스트 전체는 재실행하지 않았으며, 실제 200개 검색 실행·자료 일치·불변 검사를 검증 근거로 삼는다.
