# PATCH-029 · 상담 상태와 출처

`chat/dialogue_state.py`가 기존 `Conversation.state` JSON 안의 `dialogue`를 관리한다.
서버 전역 기억이나 별도 DB를 만들지 않으며 Django의 기존 세션 귀속·만료·잠금을 재사용한다.
아직 판단 모델이나 실행 분기는 연결하지 않았다. PATCH-030부터 이 상태에 대한 입출력 계약을 연결한다.

| 값 | 의미와 출처 |
| --- | --- |
| `topic`, `epoch` | 현재 상담 주제와 명시적 새 상담의 구분 |
| `facts` | 사용자 진술 값·현재 입력의 직접 인용·발화 번호. 법적으로 확인된 사실이 아님 |
| `changes` | 정정 이전·이후 진술의 출처, 최근 16개. 활성 사실과 구분 |
| `history` | 현재 상담의 최근 사용자 발화 8개. 보류된 답변의 법률 본문은 포함하지 않음 |
| `pending` | 확인할 항목·질문·시도 횟수를 저장하는 자리. 질문 정책은 후속 패치에서 구현 |
| `active_document_id` | 같은 대화에 실제로 있는 문서만 선택 가능 |
| `last_answer` | 기존 답변 파이프라인을 통과한 공개 본문·출처. 법적 사실의 확정 표시가 아님 |

사용자 진술은 `source=user_statement`, `certainty=reported`로 기록한다. `모름`은
`certainty=unknown`으로 구분한다. 문서 내용은 기존 `documents[].context`에 문서·페이지
출처와 함께 남으며 사용자 진술로 자동 복사하지 않는다. 추정이나 미검증 생성문은 facts에
직접 넣을 수 없다. 검색한 법률 근거는 답변의 sources에 있고 사용자 진술과 합치지 않는다.

`apply_user_update()`는 입력 전체의 형식·문서 소유권·원문 인용을 먼저 검증하고 새 스냅샷을
한 번에 저장한다. 일부 항목만 저장된 뒤 실패하지 않는다. 같은 항목의 정정은 활성 값을
교체하고 이전 출처를 changes에 남긴다. 사용자 설명이 바뀌면 이전 답변 캐시를 무효화한다.
인용이 존재한다는 검사만으로 LLM의 의미 해석이 정확하다고 보장하지는 않는다.

명시적 상담 전환은 이전 facts·history·질문·답변·문서 선택을 초기화하고 현재 발화부터 새로
기록한다. 문서 삭제도 기존 메시지 삭제와 함께 파생 상태 전체를 지운다. 새 대화·만료 시에는
별도 기억이 없어 이전 상태가 돌아오지 않는다. 보류·거절 답변은 재사용 캐시에서 제외하지만
사용자가 알려 준 내용은 남긴다. `raw_text`와 `context_content`를 답변 캐시로 복사하지 않는다.

구 세션에 dialogue가 없으면 기본값을 제공한다. 지원하지 않는 버전이나 손상된 구조는 안전한
빈 상태로 초기화하며 기존 messages/documents는 보존한다. `public_state()`는 내부 진술·
출처·대기 상태를 그대로 공개하지 않는다. 필요한 화면용 정보는 PATCH-035에서 별도 계약으로 제공한다.

수업의 `09_llm/08_langgraph/01_langgraph_basics/04_langgraph_memory.ipynb`와
`06_langgraph_custom_state.ipynb`의 대화별 상태 복원·구조화 데이터 분리 원칙을 적용한다.
기존 Django JSON 저장이 이미 있으므로 추가 Checkpointer나 영구 사용자 기억은 도입하지 않는다.
