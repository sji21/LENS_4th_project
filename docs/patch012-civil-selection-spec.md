# 민법 선택 기준 검토안 — 구현·채점 전 초안

## 이번 작업의 범위

현재 민법 7개와 별도 인덱스를 유지한다. 새 모델을 운영에 연결하거나 정규식 예외를 추가하지 않는다. 먼저 실제 질문이 어떤 관계를 묻는지와 근거 역할을 구분한다. [35문항 초안](../data/eval/civil-selection-review-draft.json)은 구현 담당 AI가 코드·실패 결과를 본 상태에서 만든 공개 개발 자료이며, 독립 평가나 확정 정답이 아니다. 기존 DEV100·v2·24개 대조 입력의 질문과 라벨은 수정하지 않았다.

기존 대조 입력의 `forbid`도 해당 실험에서 사용한 가설적 채점 기준으로 보존한다. 예를 들어 “물을 못 쓰는 것은 아닙니다. 월세 감액 조건은 무엇인가요?”는 사용불능을 긍정해서는 안 되지만, 조건을 설명하기 위한 제627조까지 금지할지는 별도 검토가 필요하다. 이 해석 때문에 과거 점수를 소급 수정하지 않는다. 수정이 확정되면 별도 버전과 영향 비교를 남긴다.

## 단계별 역할을 나눈다

1. **질문 해석:** 누가 어떤 사건을 말하고, 무엇을 요구하는지, 확정·부정·가정·타인 주장인지 확인한다.
2. **후보 확보:** 결론을 확정할 정보가 없어도 조건·예외 설명에 필요한 조문을 후보에 둘 수 있다.
3. **우선순위 결정:** 후보 포함과 최상위 배치는 다르다. 조문별 관련성과 복합 쟁점의 필수 근거를 검토한다.
4. **답변 단계:** 법률상 적용 여부·책임·청구 가능성의 확정은 검색기가 대신하지 않는다. 필요한 조건과 확인할 사실을 근거와 함께 전달하는 구조를 검토한다.

이번에는 1~3의 기준을 작성했으며 자동 해석기나 새 순위 알고리즘을 구현하지 않았다. 기준 문서가 생겼다고 코드가 사실관계를 정확히 추출하게 되는 것은 아니다.

## 조문별 검색 범위와 확인할 사실

보유 원문은 `민법-20260317` 스냅샷의 7개 조문이다. 공식 법령·공공 안내도 확인했으나 개별 사건의 시행판본·판례·특약까지 검증한 정답은 아니다. 아래는 검색 후보 검토 범위다.

조문 확인: [국가법령정보센터 민법](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=251069). 이 링크의 판본을 이번 스냅샷과 동일하다고 주장하지 않는다. 전대·소부분 적용 맥락: [찾기쉬운 생활법령정보 전대차 제한](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=4&cciNo=3&cnpClsNo=2&csmSeq=629&popMenu=ov). 종료 사유 구분: [주택임대차계약의 종료](https://www.easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=5&cciNo=1&cnpClsNo=1&csmSeq=629&popMenu=ov). 해당 자료를 확인했다고 35문항의 법적 정답 검토가 완료된 것은 아니다.

7개만으로 모든 관련 조건이 충분하다고 가정하지 않는다. 예외 조문·특별법·판례·기관 안내가 더 필요하면 추가 근거로 표시하고, 검색 조건 보완과 추가 적재를 분리한다.

## 질문 해석에 필요한 정보

- **행위자/권리 주체:** 임차인, 임대인, 수리업체, 제3자를 구분한다. “집주인이 수리를 안 해줘서 제가 비용을 냈다”는 임대인 행위의 부정과 임차인 지출의 긍정이 함께 있다.
- **사건과 대상:** 수리와 지급이 각각 존재한다는 이유로 연결하지 않는다. 수리비·계약금·보증금·월세·관리비를 구분하고 모호한 “그 돈”은 미확정으로 둔다.
- **요청과 방향:** 누가 누구에게 비용을 달라는지, 의무 설명인지·상환인지·감액인지·통지인지·해지인지 나눈다. 복합 요청을 단일 주제로 축소하지 않는다.
- **주장의 상태:** 확정 진술, 부정, 가정, 계획, 인용된 타인 주장, 분쟁 중 사실, 불확실을 분리한다. “아직 지출하지 않았지만 필요비란 무엇인가”는 정상적인 개념 질문이다.
- **문맥/시점:** 이전 대화의 어느 사건을 가리키는지 확인한다. 정확한 사건 날짜가 없으면 만들어 넣지 않는다.
- **부족한 사실:** 법률상 결론에 부족한 사실과 검색 주제를 특정하는 데 부족한 사실을 구별한다. 전자는 조건 설명용 검색이 가능할 수 있다.

이는 미래 해석기의 목표다. 특정 표현마다 새로운 정규식을 추가하는 구현 명세가 아니다. 비용·속도·정확성을 비교한 구현 방법은 아직 선택하지 않았다.

## 35문항과 제안 역할

- 조문별 4개씩 28개: 직접 쟁점, 조건·예외, 부정 또는 적용 구분을 점검한다.
- 관계 교차 7개: 지급 대상 혼합, 부정 범위, 인용 분쟁, 대화 지시 대상, 복합 쟁점, 개념 질문, 정보 부족.
- 같은 `scenario_family`는 독립 표본으로 간주하지 않는다. 조문별 4개가 모든 법적 변형을 대표하지도 않는다.
- 문항별 원문 질문·상황·요청 발췌·명시적 인물·대상 발췌·누락 사실·초안 이유·검토용 조문을 제공한다. 별도 사건 날짜는 지정하지 않았고 임의 가정을 금지한다.

| 역할 | 의미 |
|---|---|
| direct_issue | 해당 조문의 주제를 직접 물으므로 후보로 검토. 순위·적용 결론은 미확정 |
| conditional_issue | 조건·예외를 설명하기 위해 후보로 검토. 정보 부족을 곧 검색 금지로 보지 않음 |
| not_auto_priority | 그 문맥만으로 해당 조문을 강제 우선하지 않음. 후보에 포함되면 반드시 오답이라는 뜻이 아님 |
| review_needed | 지시 대상·범위·근거 역할 또는 채점 기준 추가 검토 필요 |

모든 문항의 `legal_review_status=pending`, `expected_final_rank=null`, `absolute_retrieval_ban=false`를 유지했다. 이 단계에서 정확도·합격률을 산출하거나 테스트가 통과하도록 구현을 조정하지 않는다.

## 현재 규칙 관찰

[관찰 결과](patch012-civil-selection-observations.json)는 현 브랜치의 `detect_civil_topics`를 그대로 호출한 결과다. 실제 BM25·벡터 검색·재정렬은 실행하지 않았다. 결과는 요구사항을 확정하는 정답이 아니며 정답 검토 AI에게 전달할 입력에서도 제외한다. 기존 코드의 좁은 범위를 확인하기 위한 개발 자료다.

```powershell
.venv/Scripts/python scripts/retrieval_experiments/inspect_civil_draft.py
.venv/Scripts/python scripts/retrieval_experiments/inspect_civil_draft.py --out tmp/civil-rule-observation-new.json
```

검증기는 ID 중복, 원문 발췌 존재, 미검토 상태·순위 미정·절대 금지 없음 등 형식만 확인한다. 법적 정답성을 검증하지 않는다.

검토 후 근거 역할·필수 조문 조합·우선순위 평가 기준을 별도 버전으로 정한다. 그 다음 기존 기준선 관찰과 작은 범위 구현 비교를 진행한다. 기준이 확정되기 전에 이 초안을 기존 DEV v2에 합치거나 새 운영 규칙으로 사용하지 않는다. PATCH-012는 계속 병합 보류다.
