# PATCH-063 첨부 문서 상담

## 동작

- 현재 대화에 소유된 등기 문서를 건물 관련 질문의 기본 근거로 선택한다. 등기, 등본, 등기부등본 별칭을 동일하게 취급하되 주민등록등본·법인등기는 제외한다.
- 여러 등기가 있으면 기존 선택을 유지하거나 문서 선택 질문을 한다. 다른 대화의 ID는 거절한다.
- 계약 가능 여부 요청은 원문 입력 검사와 사실 출처 검증 후 문서 위험요소·확인사항 요청으로 정규화한다. 원문은 사용자 메시지에 보존하며 금액·조건·추가 질문을 삭제하지 않는다.
- 문서 삭제 시 기존 무효화 경로로 활성 문서·대화 상태를 초기화한다. 다른 사람/건물 질문은 이전 문서를 전달하지 않는다.
- `contract_signed`는 사용자의 명시적인 체결 전·후 진술만 저장한다. 서명된 문서처럼 보이는 OCR이나 계약서 업로드 자체는 체결 사실로 취급하지 않는다. 필요한 경우 일반 안내 후 확인 질문을 한다.
- 생성 답변이 보류돼도 등기 OCR에 기존 규칙이 감지한 표시가 있으면 고정된 제목·페이지·확인사항을 `document_review` 상태로 안내한다. 거절된 생성 내용은 재사용하지 않으며 `context_content`와 검증 답변 캐시를 채우지 않는다. 문서 표시의 현재 효력과 말소 여부는 별도 확인 대상이다. 표시가 없다고 안전 판정을 하지 않는다.

## 검증

- 대화 계층·문서 경계·상태 검증 등 Python 회귀 검사 609개, Django 웹·첨부·세션 회귀 검사 88개 통과.
- 입력창·요청 ID JavaScript 검사 9개 통과, Django 시스템 검사 통과.
- 실제 로컬 Qwen으로 등기 검토→보증금 후속 질문의 같은 문서 연결 및 계약 전→이미 체결 상태 정정 4턴 확인.
- 개인정보 없는 가상 등기로 전체 생성 경로 실행: 범위 거절 없이 문서 검색/생성에 도달했지만 기존 인용 검증에서 보류됨. 이에 문서 표시만 안내하는 분리 경로를 추가하고 실패한 생성문이 노출/캐시되지 않는 회귀 검사를 추가함.
- 보완 후 동일 가상 등기 재실행에서 `document_review` 응답과 근저당권·공동담보 표시, 1쪽 근거, 확인사항 안내를 확인함.
- 개인정보가 있는 실물 PDF의 OCR 정확도, 모든 법률 답변의 정확성, 모든 자유 발화에 대한 독립 품질 평가는 이 검사 결과에 포함되지 않는다.

## 수동 확인

1. 등기를 첨부하고 “이집 계약해도 괜찮을까?” → 위험요소/확인사항 또는 문서 표시 확인.
2. “그럼 무엇을 더 확인해야 해?” → 같은 문서 사용.
3. 문서를 삭제하고 다시 질문 → 삭제한 문서 사용 금지.
4. 계약서를 첨부하고 “아직 계약 전이야. 특약을 설명해줘” → 미체결 상태 유지.
5. “이미 계약했어. 그 특약은 어떻게 해야 해?” → 체결 상태로 정정.

## 촬영본·첨부 범위 보완 (2026-09-22)

- JPG/PNG는 기존 EXIF 회전 검증 후 명암·작은 기울기·선명도를 보정하고 긴 표 선을 제거한 대안을 만든다. 원본은 별도 후보로 유지한다. 원본 PSM 6, 보정본 PSM 6, 보정본 PSM 11을 로컬 Tesseract로 비교하고 희소 배치는 좌표 순서로 행을 정렬한다. 전체 후보 텍스트를 합치지 않는다. 인도 조항의 부분 판독에서 일치한 문구만 별도 표식으로 근거 텍스트에 추가한다.
- 기존 Pillow·NumPy만 사용한다. 후보당 25초, 전체 페이지 3회와 원본·보정본 각각 최대 3개 인도 영역 판독으로 제한한다. confidence와 필드 표식 수는 후보 선택 휴리스틱이며 정확도 보증이 아니다. 심한 원근·초점 손실·필기 복원이나 완전한 표 셀 구조 인식은 지원하지 않는다. PDF 텍스트/스캔 추출 경로는 기존 동작을 유지한다.
- OCR 방식별 금액 결과가 다르거나 판독 신뢰도가 낮으면 재촬영을 요청하고 탐지값을 확정 표시하지 않는다. 금액 일치만으로 정확성을 보장하지 않는다.
- 표의 다음 필드명을 넘어선 값으로 현재 빈 칸을 확인 처리하지 않는다. 한 장이라도 전체 계약서일 수 있어 특정 항목이 2쪽에 있다고 가정하지 않는다. 실제 업로드한 쪽수·발견 페이지를 표시하고 미탐지는 첨부 범위에서 미확인으로 안내한다.
- 질문이 요구하는 보증금·기간·주소 등의 값이 미확인일 때 해당 페이지/확대 촬영을 요청하고 답변 생성으로 불확실한 값을 넘기지 않는다. 서명·날인은 OCR로 확정하지 않는다.
- 실제 업로드 JPG를 로컬 메모리에서 재처리해 금액 후보 불일치 경고를 확인했다. 원본 개인정보/추출 본문을 평가 기록에 남기거나 외부 OCR에 전송하지 않았다. 기존 저장 분석은 자동 덮어쓰지 않았다. 새 대화에서 다시 첨부하면 새 처리가 적용된다.
- 보완 후 Python 관련 검사 720개 및 JavaScript 9개, Django 시스템 검사 통과. 실물 사진의 모든 값에 대한 정답률 개선을 주장하지 않는다.

## 첨부 삭제 접근성

문서 삭제 버튼을 접힌 문서 제목 영역으로 이동하고 확인창에 대상 파일명을 표시한다. 확인 시 선택된 ID를 고정해 다른 문서를 삭제하지 않도록 한다. 기존 문서 삭제·소유권·후속 맥락 무효화 검사 포함 Python 81개, JavaScript 9개 통과. 사용자 실제 문서는 검증 과정에서 삭제하지 않았다.

## 문서 삭제 후 대화 기록 보존

문서 삭제는 메시지를 지우지 않는다. 출처가 연결된 관련 메시지(출처 정보가 없는 과거 대화는 전체)에 `context_excluded`를 기록하고 생성용 원문 캐시를 비운다. 표시·정규화 Message 행은 유지하되 의도 판단, 기존 후속 질문, 쉬운 설명 재생성, 새 리포트·체크리스트/일정 입력에서 제외한다. 문서 자체와 추출 사실은 기존 삭제·무효화 경로를 유지한다. 기존에 삭제된 대화나 이미 만들어진 리포트를 복원/재작성하는 기능은 포함하지 않는다.

## 계약서 인도일 조회

입주일 질문은 선택된 계약서의 날짜가 붙은 인도 조항을 먼저 확인한다. 체결일·종료일을 대신 사용하지 않으며 서로 다른 인도일이나 잘못된 날짜는 확정하지 않는다. 사용자 제공 예문의 2023-02-19 인도기한/2025-02-18 종료일 구분 및 불명확한 경우 부분 재촬영 요청 검사 포함 584개 통과. 실제 입주일과 문서상 인도기한은 구분한다.

## 추가 질문 입력 통합

질문은 답변 마지막 문단에 표시하고 추천 답변과 ‘직접 입력’ 버튼은 해당 말풍선에 둔다. 추천 답변은 전송하고 ‘직접 입력’은 기존 입력창에 커서만 이동한다. 작성 중인 내용과 기본 placeholder를 보존하며 일반 입력도 현재 pending ID를 전달한다.

## 촬영 계약서 날짜 판독 보완

- 전체 OCR의 인도·존속기간 행 좌표를 이용해 주변 조항을 잘라 로컬 OCR한다. 원본과 보정본의 결과가 일치하고 각 판독 신뢰도 조건을 만족해야 날짜를 확인 처리한다. OCR confidence와 두 결과의 일치는 정확도 보증이 아니다.
- 날짜 바로 뒤의 인도 문구, 기간 문구, 잔금 지급 문구를 기준으로 역할을 구분한다. 가장 가까운 날짜를 가져오거나 인도일을 잔금일로 대체하지 않는다. 기간이 인도일로부터라는 명시적 문구가 있을 때만 시작일을 연결한다.
- 분석 결과에 날짜·역할·페이지·판독 방식·영역·확인 상태를 저장하고 첨부 점검 항목에 표시한다. 원문 근거는 내부 OCR에 보존하고 공개 분석의 원문 필드는 제거한다. 금액 불일치만으로 별도 검증된 인도 날짜를 막지 않는다.
- 실제 첨부 JPG를 메모리에서 재처리하여 인도기한/기간 시작 기준 2023-02-19, 종료일 2025-02-18이 서로 구분됨을 확인했다. 잔금일은 확정하지 않았다. 주소·금액·모든 필드의 정확도를 검증한 것은 아니다. 개인 문서 원본은 테스트 fixture나 Git에 포함하지 않는다.
- 기존 저장 문서는 자동 덮어쓰지 않는다. 같은 대화에서 기존 문서를 삭제 후 다시 첨부하거나 새 대화에 첨부해야 새 판독 결과가 저장된다. 기존 대화 기록은 삭제하지 않는다.

- 이번 날짜 보완: 관련 Python 회귀 검사 138개, Django 시스템 검사 및 diff 공백 검사 통과. 실제 첨부 JPG를 로컬 메모리에서 OCR→분석→세션 문서→대화 라우터까지 실행해 `document_date_extracted`와 인도기한 응답을 확인했다. 사용자 대화나 저장 문서의 내용은 변경하지 않았다.

## 표 구조 및 성명 판독

- JPG/PNG에서 그림자와 잉크를 구분하고 지지되는 가로·세로 선으로 셀 경계를 찾는다. 외곽선으로 작은 기울기를 보정하되 원근 변환으로 페이지를 잘라내지 않는다. 병합 셀의 행 범위를 유지하며 검출 상한은 160셀이다. 선이 없는 표, 심한 원근·종이 휨, 인장으로 가려진 경계는 완전한 인식을 보장하지 않는다.
- 셀별 국소 명암 보정 후 묶음 OCR을 수행하고 작은 항목명은 재판독한다. 세로 당사자 표시는 글자의 순서를 유지해 가로 배치한 대안으로 읽는다. 셀 좌표·페이지·판독 신뢰도를 내부 세션에 저장하고 검색 문구에는 셀 경계와 불확실한 칸을 표시한다. 좌표는 기울기를 보정한 이미지 기준이다.
- 임대인·임차인 병합 셀이 성명 행을 포함하고 성명 오른쪽 값 칸이 하나일 때만 연결한다. 성명은 두 명암 처리의 결과가 일치해야 확인 처리한다. 공동명의·중복 역할·판독 충돌은 단일 이름으로 축약하지 않는다. 현재 확정 이름 추출은 한글 2~5자에 한정되며 외국인·법인명은 확인 요청으로 남을 수 있다.
- 표 OCR의 추가 작업은 45초 후 새 호출을 중단하며 이미 실행 중인 호출의 최대 25초를 더 사용할 수 있다. 실패하면 원래 OCR을 보존하고 경고한다. 새로운 외부 OCR이나 의존성은 추가하지 않는다.
- 이름 확인 질문은 확인된 문서 값만 안내하고, 없으면 성명 표 재촬영을 요청한다. ‘누구에게 통보’, 이름 변경 등 법률 질문을 단순 성명 조회로 바꾸지 않는다. 전체 인적사항, 신원·등기상 소유자 일치 여부를 확정한 결과가 아니다.
- 실제 첨부 JPG에서 임대인 표시→성명 셀→이름 셀의 연결과 사용자 제공 이름 일치를 확인했다. 임차인 성명은 비교 판독에서 불확실하여 review로 유지했다. 개인정보 원문/이미지는 테스트 fixture 및 변경 이력에 넣지 않는다.

- 표 보완 검증: 관련 회귀 검사 151개와 세션 검색 검사 13개(총 164개), Django 시스템 검사, diff 공백 검사 통과. 실제 JPG를 새 로직으로 메모리에서 재처리해 대화 라우터에서 임대인 성명 및 인도기한 응답을 확인했다. 기존 저장 대화/문서는 변경하지 않았다.
