# PATCH-059 최종 리트리버 종합 평가·데이터·검색 개선

> 이 작업은 원래 058번으로 시작했으나, 공유 저장소에서 057번(MySQL, yoonjihwan402)과
> 058번(LLM 주장 계획, kimjeongjaeae)이 이미 선점되어 AGENTS.md 6.1에 따라 **PATCH-059**로
> 정정했다. 종합 평가도 최종적으로 PATCH-059 범위에 통합했다. 봉인된 protocol이 스크립트 경로를
> 해시에 포함하므로 산출물 경로(`docs/patch058-*`, `data/eval/patch058-regression`,
> `scripts/patch058_*`)와 실제 브랜치명은 바꾸지 않았다.

## 목적과 범위

개선 전 최초 측정에서 필수 근거의 미보유와 복수 근거 선택·판례 전달 공백을 확인했다. 이번 작업은 공식 원문 보완, 실제 검색 경계 연결, 같은 입력의 전후 비교를 수행한다. 생성 LLM은 호출하지 않는다.

최초 HO30 질문·정답·원시 결과는 보존한다. 이후 같은 문항은 **개선에 사용한 회귀셋**이며 독립 홀드아웃 성적으로 표현하지 않는다. 최초 성적은 일반법령3/민법3에서14/30, 일반법령5/민법3에서17/30이었다.

## 검색·전달 변경

1. 확정일자 기록 조회권자·정보제공, 분쟁조정 대상·조정서 집행력 요청을 본문 내용과 연결한다. 이미 확보한 검색 후보 안에서만 복수 근거를 선택한다.
2. 보증금 순위 및 열쇠 반납을 통한 인도 표현을 인식한다. 정답 ID나 평가 질문을 제품 검색 조건으로 사용하지 않는다.
3. 구체적인 권리 충돌·책임·효력 질문에서 판례를 추가한다. 단순 발급·기한·횟수나 명시적으로 제외한 판례는 일괄 추가하지 않는다.
4. 보완 판례는 기존 판례와 같은 KURE 객체로2건만 임베딩하고 cosine 점수를 합친다. BM25도 전체 합집합으로 계산한 뒤 기존 RRF·재정렬을 거친다. 두 건짜리 검색의 높은 순위를 그대로 우대하지 않는다.
5. 공공임대 금융정보 동의 요청에 공식 서식을 안내 예산 안에서 전달한다. 일반 은행 동의서 질문은 이 서식으로 연결하지 않는다. 조문 본문에 서식을 언급한 것만으로 서식 적중으로 채점하지 않는다.

운영 반환 개수는 변경하지 않았다. 일반법령3/5는 각각 실제 요청하며 민법은 최대3, 판례는 운영 최대2/진단5, 안내·서식은 합계 최대2다.

## 설치 호환성

기존 `expanded-laws-record-v1`과 민법26개 프로필은 계속 읽는다. 새 `expanded-laws-record-v2`는 민법31개 목록을 검사한다. 목록과 정책을 뒤섞은 프로필은 거절한다.

최신 코드의 기존 설치 절차를 실행하면 소스 지문 변경을 확인하고 DB·인덱스를 재구축한다. 과거 PATCH-027 재현 도구는 과거 정책·민법 목록에 고정한다. 기존 프로필을 열 수 있는 것과 새 자료가 설치된 것은 구분한다.

## 측정과 검증

- 평가 입력368개: 기존 DEV·민법·법령/판례 회귀·HO30. 최초 입력·정답 label 순서가 모두 같은지 실행 전에 검사했다.
- 새 실행은 커밋 없이 코드·데이터·모델 파일 SHA와 프로토콜 SHA로 봉인했다. 최초 평가 커밋 봉인 기록을 바꾸지 않았다.
- 구축 중 파일 변경을 감지한 첫 실행은 적용 전 중단됐다. 완성된 임베딩 산출물은 별도 작업공간에서 다시 검증했고, 고정된 코드·원천과 일치하여 재임베딩0건으로 확인됐다. 최초 평가 데이터는 수정하지 않았다.
- 서식은 기존 안내 순위를 유지해 별도 식별자로 채점한다. 첫 안내가 다른 자료이고 두 번째가 서식이면 서식 Hit@1로 승격하지 않는다.
- 실제 측정은 로컬 RTX3060 Laptop의 CUDA KURE로 진행했다. 생성 LLM은 호출하지 않았다. 전체 테스트와 일부 시간이 겹쳤으므로 지연 수치를 독립적인 성능 비교로 사용하지 않는다.

### 중간 실행과 수정

첫 개선 측정 `capture-v1`은 368입력을 정상 완료했고, HO30 완전 확보는 law3 **14→19/30**, law5 **17→22/30**이었다. 이 원시도 보존한다. 이후 독립 리뷰의 범위 부정·순수 서식 요청 오탐을 수정하고, “확정일자 받은 기록” 동의어 누락을 보완했다. 최종 수치는 다음 실행을 기준으로 한다.

두 번째 측정은 `protocol-v3`의 코드·데이터·모델 SHA로 고정한다. `protocol`은 실행하지 않은 초안, `protocol-v2`는 첫 측정의 기준이다. 번호가 다른 기록을 합쳐 최종 성적으로 사용하지 않는다.

### 최종 검색 결과

`capture-v2` 368입력을 기준으로 원시 368행·채널 지표240개를 별도 검증자가 재집계하여 모두 일치했다. 필수 근거 완전 확보는 해당 질문의 법령·민법·필수 판례·서식이 모두 실제 반환된 경우다. law3/5에서도 민법은 최대3건이다.

- HO30 필수 근거48회 중 미보유는 **15→0**, 실제 확보는 **36/48(law3), 40/48(law5)**다. 법령만 보면44회 중35/44·39/44, 법령만 완전 확보한 질문은22/30·25/30이다. 판례·서식까지 모두 확보한20/30·23/30과 혼동하지 않는다.
- 기존 법령236입력의 **확보했던 근거 손실은 law3 8입력·8근거, law5 3입력·3근거**다. HO30의 law5 손실2개(HO-005·011)를 포함하면 전체 채점307입력의 손실은 law3 8개, law5 5개다. 한 문항에서 일부 이득과 손실이 동시에 생길 수 있어 완전 확보 증감과 손실 수는 다르다.
- HO30 law5 미완전 문항은 HO-004·005·008·011·025·026·029다. 이 중 HO-004·008의 필수 판례는 보유했지만 여전히 TOP5에 없다. 데이터 보완만으로 순위·반환 누락까지 모두 해결된 것은 아니다.

### 검사 결과와 재현 자료

- 전체 검사: **2,932 passed, 15 failed, 3 errors, 3 skipped, 678 subtests passed**. 호환성 수정·임시 경로 보정 후 영향 검사 **262 passed, 3 failed, 3 errors**로 재검증했다. 같은 테스트 ID의 최종 결과를 반영하면 **2,944통과·3실패·3오류·3생략**이다. 단일 전체 재실행이 모두 통과한 것으로 표현하지 않는다.
- 남은 실패3·오류3은 PATCH-024 보고서 재생 및 PATCH-042 과거 평가 분석 항목이며 개선 전 기준선에서도 같은 항목이 실패/오류로 재현된다. 과거 평가 자료를 현재 검사와 맞추기 위한 별도 정리가 필요하다. 현재 PATCH-041의 고정 정책 별칭 수정 이후에는 일부 과거 검사가 `Evaluator source changed`로 중단되므로 실패 사유가 전부 동일하다고 주장하지 않는다. 봉인 검사를 완화하거나 과거 평가 원본을 덮어쓰지 않았다.
- 최초 전체 시도는 Streamlit 미설치로 수집2오류였다. 분리된 평가 가상환경에 설치한 뒤, 실행 계정이 다른 기존 pytest 임시 폴더 접근 문제를 새 `--basetemp`로 해결했다. 저장소 `tmp` 내부를 특별 취급하는 과거 테스트1건은 저장소 밖 새 임시 경로에서 통과했다. 제품 의존성 파일과 기존 가상환경은 변경하지 않았다.
- 실측 완료 후 `_chunks`가 없는 기본 검색 대역 호환1줄과 과거 PATCH-041의 `LEGACY_POLICY` 별칭을 수정했다. **실제 측정 서비스의 경로는 동일함을 코드 리뷰·관련 검사로 확인했고 재캡처하지 않았다.** 현재 소스 전체가 봉인 당시와 byte 단위로 동일하다는 뜻은 아니다. 변경 전 두 파일은 원래 봉인 SHA와 대조해 보존했다.

- **조문 파서:** 뒤에 제목 있는 실제 조문이 존재할 때, 현재 본문의 `제2조제1항…`·`제2조 및…` 같은 참조가 새 조문을 선점하지 않도록 수정했다. 제목 없는 첫 조문과 모든 조문에 제목이 없는 경우도 회귀 검사에 포함했다.

- **실제 자료 확인:** 승인된 원천을 다시 파싱한 216개 조문 레코드가 현재 `data/parsed/server-build/laws.jsonl`과 모두 같다. 이번 파서 보완으로 DB·임베딩 재구축은 하지 않았다.

- `capture-merged` 등 기존 실측 자료는 당시 코드의 기록으로 보존한다. 이번 수정 코드로 다시 봉인한 실측으로 표현하지 않는다. 과거 전체 검사 실패·오류가 이번 관련 검사로 해소됐다고 판단하지 않는다.
- 커밋·푸시·병합은 하지 않았다.

### 커밋·푸시 준비

사용자 요청으로 작업 브랜치를 `feat/patch-059-retrieval-coverage`로 정정했다. 평가 원시 JSONL은 동일 SHA-256으로 복원되는 gzip과 압축 확인 기록으로 공유하며, 원본은 로컬에 보존한다. 복원은 `gzip.decompress`로 같은 폴더의 `rows.jsonl`에 저장하면 된다. 기존 main 변경은 작업 트리에 통합되어 있으나 Git 병합 커밋은 아직 만들지 않았다. 남은 전체 검사 실패·오류 때문에 LIST는 완료가 아닌 리뷰 중으로 유지한다.

### PR #42 충돌 해결

`origin/main`의 `d905cf6`을 Git 병합 이력으로 연결했다. 양쪽 CHANGELOG·LIST와 MySQL 3파일 충돌은 기존 main 내용에 PATCH-059 수정이 더해진 상태임을 확인하여 보존했다. main의 로컬 MySQL 배포·모델 경로 제외 규칙을 반영하고 자동 병합으로 중복된 LFS 속성은 제거했다. 충돌 해결 전후 실행 코드·테스트 파일은 바이트가 동일하므로 테스트를 재실행하지 않았다. MySQL 충돌 해소는 독립 코드 리뷰로도 확인했다.
