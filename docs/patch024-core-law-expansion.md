# PATCH-024: 민법 3개 조문 추가 적재와 검색 평가

## 변경과 판단

민법 제105조(임의규정), 제114조(대리행위의 효력), 제357조(근저당)를 추가한다.
민법 보유 조문은 7→10개, 전체 법령 조문은 140→143개다. 민법 반환 한도는
별도 TOP3 그대로이며 검색 모델·키워드·순위 규칙은 변경하지 않았다.

복사 DB와 인덱스에서 먼저 235입력을 비교했다. 기존에 반환하던 필수 근거 손실이
0건이므로 원본을 백업한 뒤 로컬 사용 경로에 반영했다. 일반 법령·판례·안내 순위는
235입력 모두 동일했다. 이 결과는 공개 개발셋의 검색 평가이며 LLM 답변 평가가 아니다.

## DEV 100문항 결과

각 행은 동일한 100문항이다. 질문만 검색한 결과와 상황·이전 대화를 함께 제공한
진단 결과를 합쳐 200개의 서로 다른 문항처럼 계산하지 않는다.

| 입력 | 필수 근거 전부 반환 | 데이터 부족 | 보유했지만 검색 누락 | 별도 판정 |
| --- | ---: | ---: | ---: | ---: |
| 질문만 — 이전 | 23 | 45 | 7 | 25 |
| 질문만 — 추가 후 | 28 | 32 | 15 | 25 |
| 문맥 포함 — 이전 | 25 | 45 | 5 | 25 |
| 문맥 포함 — 추가 후 | 29 | 32 | 14 | 25 |

별도 판정 25개는 고정 조문 목표가 없는 23개와 과거 판본 검토 2개다.
`검색 누락` 증가는 이전 데이터 부족 문항이 보유 상태로 바뀌었기 때문이다.
기존에 찾던 필수 근거를 잃은 건은 없다. `데이터 부족`은 일부/전체 미보유를 합친
배타적 분류이며 해당 문항에도 보유 근거의 검색 누락이 함께 있을 수 있다.

민법 개발용 35문항은 핵심 29개·범위 잠정 1개·진단 5개로 나눈다. 핵심 문항의
전체 필수 법령 확보는 28/29를 유지한다. 전체 법령 확보와 민법만의 확보는 다르다.
문항별 순위·미보유·검색 누락·채널별 지표는 [평가 묶음](../data/eval/patch024-expansion/report.json)에 있다.

## 원문과 판본

기존과 같은 민법 시행일 2026-03-17, 법률 제21454호, lsiSeq 284415를 사용한다.
로컬에 보존된 전체 원문 `data/raw/law/민법-20260317.txt`에서 추출하고, 공식 조문
페이지의 제목·본문·판본 표시를 대조했다. 전체 원문을 새로 내려받았다는 뜻은 아니다.

- [민법 제105조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0105&lsiSeq=284415&urlMode=lsScJoRltInfoR)
- [민법 제114조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0114&lsiSeq=284415&urlMode=lsScJoRltInfoR)
- [민법 제357조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0357&lsiSeq=284415&urlMode=lsScJoRltInfoR)

원문 SHA-256은 `audit.json`에, 새 청크 3개는 `new-chunks.jsonl`에 보존했다.
DB 로더가 동일 판본을 교체하므로 기존 7개를 포함한 10개 레코드를 함께 적재했다.
기존 140개 조문의 DB 본문은 그대로다. 청크는 기존 파일 뒤에 새 3개만 추가했으며
민법 벡터도 새 3개만 계산했다. 기존 7개 벡터·문서·메타데이터는 그대로 유지했다.
일반 인덱스는 재생성하지 않았다.

## 실행 증거와 재현

후보 235입력 실행 커밋은 `e640d3a`이며 실행 전후 작업 트리는 clean이었다.
실제 적용 코드의 커밋은 `0056ae6`이다. `operating-verification.json`은 실제
`RetrievalService.from_index()` 경로의 후보 결과 대조 기록이다. 검증 중 보고서
파일을 추가했으므로 전체 작업 트리 상태와 검색 서비스 파일 해시를 각각 기록한다.

```powershell
# 모델·DB 없이 저장된 결과와 기존 정답으로 집계를 재계산
.venv/Scripts/python -m scripts.patch024_report

# 전체 코드 회귀 테스트
.venv/Scripts/python -m pytest -q
```

검증 결과: 제품 변경 후 전체 테스트 846 passed, 3 skipped, 124 subtests passed.
보고서 추가 후 관련 6개 테스트도 통과했다(그중 신규 재집계 테스트 3개).
스킵은 비활성 LangSmith 2개와 실물 등기 PDF 미지정 1개다.
실제 사용 경로 235입력은 후보 결과와 모두 일치했다.

후보 재실행은 PATCH-023의 데이터 해시와 일치하는 원본 DB·청크·인덱스,
기록된 KURE-v1 캐시, 보존 원문이 필요하다. 별도 체크아웃의 `e640d3a`에서:

```powershell
.venv/Scripts/python -m scripts.patch024_expand --out tmp/patch024-replay
```

이미 이번 데이터를 반영한 작업 폴더에서는 이전 데이터 해시 검사에 걸리는 것이
정상이다. DB·인덱스는 Git에 포함하지 않으므로 새 클론만으로 실검색을 재현할 수 없다.
팀원이 데이터를 재생성할 때는 [민법 적재 절차](patch006-civil-routing.md)의 분리
색인 절차를 따른다. 재생성은 기존 벡터를 보존한 이번 실행과 바이트 동일한 조건은 아니다.
현재 수집 허용 목록은 10개이며 이전 7개짜리 파일에 코드만 갱신하면 새 3개는 검색되지 않는다.

로컬 백업: `tmp/patch024-expansion/before/`. 반영 대상·전후 해시는 `adoption.json`에 있다.
백업과 후보 데이터는 Git에 올리지 않는다. 이전 코드로 전환할 때에는 같은 시점의
DB·청크·민법 인덱스도 함께 복원해야 한다.

## 남은 작업

추가 조문을 보유했지만 TOP3에서 놓치는 문항은 별도 튜닝 패치에서 다룬다.
미보유 법령의 다음 적재 묶음 선정, 과거 판본 확인, 기관 안내 데이터 보강은 남아 있다.
기존 DEV-059 문맥 누락과 불필요한 민법 후보 노출도 이번 패치의 해결 대상이 아니다.
조문 검색 성공은 항·호·목의 정확한 선택이나 법적 결론의 정답을 보증하지 않는다.
