# PATCH-007 법령 원문·세부 구조 보존

기준 코드: `a619d19c362427dfae6a583aac39f98d0c648119`.
기존 조 단위 검색 본문과 ID를 유지하면서, 이후 법령 범위 확대와 근거 단위 검토에 필요한 정보를 별도로 저장한다. 검색 순위 개선이나 DEV 정답률 향상을 입증하는 패치는 아니다.

## 저장 구조

스키마 버전 3은 기존 테이블을 유지하고 다음 테이블을 추가한다.

| 테이블 | 보존 내용 |
| --- | --- |
| `law_source_snapshots` | 판본별 수집 평문 전체, 수집 시각, 원문 URL, 원천 판본 ID, SHA-256. 수집된 부칙·삭제 표시·개정 표기도 평문에 있으면 보존 |
| `law_article_sources` | 개별 조문 레코드의 URL, 스냅샷 연결, 조문 본문 해시, 구조 파서 버전 |
| `law_article_units` | 조문 루트와 명시적인 항·호·목, 부모 키, 순서, 본문 위치, 해당 구간의 텍스트 |

스냅샷은 HTML 원본이나 공식 법령 전체의 완전성을 보증하는 자료가 아니라 **수집기가 확보한 평문 그대로**다. `source_text`, `source_document_url`, `source_version_id`는 기존 입력 형식에 추가된 선택 필드다. 같은 판본에서 평문은 한 레코드에만 제공해도 모든 해당 조문과 연결된다. 동일 판본·동일 내용은 중복 저장하지 않고 최초 수집 정보를 유지하며, 내용이 바뀌면 별도 스냅샷을 남긴다. 서로 다른 원문을 같은 입력 판본에 제공하면 적재를 거부한다.

기존 `law_code`의 식별 방식은 유지한다. 수집기의 `lsiSeq`는 별도 `source_version_id`에도 기록하지만, 법령의 영구 ID와 판본 ID를 재설계하거나 과거 판본을 수집하는 작업은 포함하지 않는다.

## 파서와 검색 경계

- 줄 시작의 원문자 항 번호, 숫자와 마침표로 된 호, 호 아래의 한글 목 표시를 인식한다. 번호가 없는 본문에 제1항을 임의로 부여하지 않는다.
- 위치는 HTML 바이트가 아닌 `law_articles.content`의 Unicode 문자 인덱스이며 끝 위치는 제외한다.
- 루트는 조문 본문 전체를 가진다. 루트 이외 노드를 순서대로 연결하면 해당 본문이 정확히 복원된다. 부모 관계는 번호 계층이며 부모의 텍스트 구간에 자식 구간이 중첩되는 형식은 아니다.
- 식별하지 못한 형식은 본문으로 보존한다. 모든 법령 형식의 의미 분석, 단서·예외의 법적 관계 판정, 본문에서 제거된 개정 표기의 복원은 하지 않는다.
- 기존 수집기의 검색용 조문 정리는 유지한다. 부칙과 삭제 조문은 스냅샷에 보존될 수 있지만 이번 변경으로 검색 대상이 되지는 않는다.
- 새 구조 JSONL은 검토용이며 Chroma 입력이 아니다. 항·호·목별 검색이나 관련 조문 확장은 후속 작업이다.

## 기존 DB 적용 및 재적재

초기화는 새 테이블과 스키마 버전만 추가한다. 기존 조문·청크와 출처를 자동으로 재작성하지 않는다. 기존 DB에 남아 있지 않은 원문과 조문별 URL도 추정해서 채우지 않는다.

실행 중인 앱을 종료한 뒤, 저장소 루트의 PowerShell에서 새 검증 디렉터리로 복사하여 확인한다. 아래 출력 경로가 이미 있으면 새 경로를 선택한다.

```powershell
New-Item -ItemType Directory tmp/patch007-review
Copy-Item data/database/knowledge.sqlite3 tmp/patch007-review/knowledge.sqlite3
.venv/Scripts/python -m src.ingestion.law_structure --database tmp/patch007-review/knowledge.sqlite3 --out tmp/patch007-review/structure.jsonl
```

DB가 사용 중이거나 WAL이 남아 있으면 단일 파일 복사 대신 SQLite backup API로 일관된 복사본을 만든다. CLI는 지정한 DB에 구조를 보완하므로 반드시 복사본을 지정한다. 구조 생성은 반복 가능하지만 기존 출력 파일은 덮어쓰지 않는다. 구 DB에서 확보할 수 없는 조문 출처는 검토 JSONL에 `source_status=unavailable`로 표시한다.

새 수집 레코드를 `load_records`로 적재하면 스냅샷·출처·구조를 함께 저장한다. 재적재는 기존과 같이 입력 판본의 조문 전체를 교체하므로 해당 판본의 전체 대상 레코드를 제공해야 한다. 실패하면 삭제와 삽입을 함께 롤백한다. 다른 테이블이 조문을 참조하여 교체가 제한되는 경우에는 참조를 임의로 삭제하지 않고 오류로 남긴다.

새로 적재한 조문의 검색 청크 출처는 개별 레코드의 URL을 사용한다. 종전에는 문서의 첫 조문 URL이 모든 조문에 사용됐다. 본문·ID가 같아도 출처 메타데이터가 바뀌므로 운영 반영 시에는 청크와 인덱스를 함께 갱신하고 검증해야 한다. 이번에는 운영 재적재·재임베딩을 수행하지 않았다.
