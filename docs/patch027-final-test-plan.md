# PATCH-027 조문 확대 반영을 위한 최종 시험

기준일: 2026-09-13. 사용자 승인: 일부 손실을 허용하되 기존보다 전체 이득이 큰지 평가하고 조문 확대 반영을 목표로 최종 시험한다. 기존 손실0 시험의 기록·판정은 바꾸지 않는다. 공개 개발셋의 이전 결과를 알고 설계한 최종 개발 시험이며 독립 평가가 아니다.

## 실행 전에 고정한 범위

- 기존 운영143조문과 후보204조문(61조문 추가, 민법10→26)을 비교한다. 정답·문항·판본·모델·채널별 반환량은 기존과 같다.
- DEV100 질문/문맥200입력과 CIV35를 실제 BM25+KURE 서비스로 모두 재실행한다. 운영 DB·인덱스 교체, LLM 평가, 푸시·PR·병합은 이번 실행에 포함하지 않는다.
- 대안은 두 개다. `verified_context`는 앞서 검증한 문맥·준용 조합 그대로다. `record_lookup`은 확정일자 기록 조회를 보호 효과로 확장하던 의도 구분만 보완한다. 민법 선택·준용·반환량을 변경하지 않는다.
- 새 가중치 탐색이나 DEV 번호·정답 조문 강제 선택을 추가하지 않는다. 문맥 전체 재작성과 민법 마지막 슬롯 변경은 이번 최종 후보에서 제외한다.

## 판단 기준

1. **데이터·실행 무결성은 필수다.** 기존 조문 원문·출처·판본·벡터 보존, 후보 파일/인덱스 전후 일치, 실측 입력/코드 고정, 근거 본문/출처 일치, 판례·안내 보존, 전체 테스트를 확인한다. 실패하면 점수와 무관하게 반영 준비를 중단한다.
2. **전체 이득을 각 모드에서 확인한다.** DEV 질문과 문맥 각각 고정75문항의 완전 확보가 운영보다 늘어야 한다. 같은 문항의 불완전→완전과 완전→불완전을 모두 공개한다. 법령 보유 부족은 분모에서 빼지 않는다.
3. **소비 범위를 별도로 확인한다.** 일반 법령3개+민법3개만 사용한다고 가정한 완전 확보를 운영과 비교해 각 모드에서 감소하지 않아야 한다. 이는 LLM이 실제로 민법을 채택했다는 평가가 아니라 근거 전달 예산의 진단이다.
4. **기존 민법 개발 범위를 유지한다.** CIV35 필수29문항 완전 확보28/29 이상·민법 Hit3 29/29를 유지하고, 신규 필수 민법 고유9조문 확보를 확인한다.
5. **손실0은 필수 조건이 아니다.** 반환 손실과 TOP3 손실은 문항별로 남기고, 원인·회복 경로·영향을 기재한다. 잘못된 출처/조문 연결은 순위 손실과 달리 무결성 실패다. 잔여 누락의 법적 심각성을 기계 점수로 확정하거나 LLM 안전성을 보장하지 않는다.
6. **비용을 공개한다.** 모델 호출 수와 같은 실행의 지연시간을 비교한다. 사전 합의된 운영 지연 예산이 없으므로 임의의 비용 합격선을 만들지 않는다. 결과서에서 증가량과 운영 검토 사항을 명시한다.

## 두 후보의 선택 규칙과 종료

무결성과 위 정량 조건을 만족하는 후보 중 DEV 두 모드 완전 확보 합계가 큰 쪽을 고른다. 합계가 같으면 기존 반환 손실 입력 수가 적은 쪽, 다시 같으면 모델 호출이 적은 쪽, 모두 같으면 기존 검증 조합을 유지한다. 질문/문맥 합계는 후보 선택용으로만 쓰고 독립150문항 성능으로 보고하지 않는다.

조건을 만족하면 **잔여 검색 실패를 공개한 조문 확대의 기술적 채택 권고**로 정리한다. 이후 제품 코드 연결·운영 적재 검증과 팀 PR 리뷰를 통해 실제 반영한다. 조건을 만족하지 못하면 부족한 항목을 정확히 남기며, 같은 턴에서 합격선을 바꾸거나 추가 튜닝을 반복하지 않는다.

실행 후 기록: 기준은 위 내용으로 유지했으며, [최종 결과](patch027-final-test-result.md)에서 `record_lookup`을 기술적 채택 권고안으로 선정했다. 실행 당시 계획 원문은 실측 커밋 `6cbc2af`에 보존돼 있다.
