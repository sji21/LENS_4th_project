# PATCH-036 · 실패 복구와 세션 보호

새 경로는 판단용 JSON을 UTF-8 12,000바이트 이하로 제한한다. 초과하면 오래된 사용자 이력을 한 항목씩 제외하고, 그래도 크면 직전 답변을 제외한다. 현재 질문·사실·문서 소유권·pending은 잘라서 조건을 바꾸지 않는다. 필수 입력만으로 넘으면 판단을 호출하지 않고 기존 경로로 복귀한다. 이 바이트 제한은 토큰 수를 정확히 계산한 값은 아니다. 모델 context 8,192와 출력 768 토큰 제한은 별도로 유지한다.

판단 호출은 최대 60초(2026-09-16 문맥 전환 지연 보완), 자동 재시도 0회다. 명확한 예/아니요 답이나 모호한 문서 선택은 판단 호출 없이 처리한다. 새 대화 요청에만 ContextVar로 180초·모델 HTTP 시도 최대 6회 예산을 적용한다. 기존 경로로의 실패 복귀도 같은 예산을 공유한다. 원격→로컬 시도도 각각 차감하며 각 HTTP timeout을 남은 시간 이내로 줄인다. 모델 응답 후와 상태 반영 직전에 기한을 재검사한다. 검색·문서 처리 자체를 강제로 중단하는 타이머는 아니므로 전체 HTTP 응답시간을 정확히 180초로 보장하지는 않는다. 기존 요청 잠금 900초보다 짧은 모델 예산이며, 기본 경로 단독 실행은 종전 설정을 유지한다.

화면은 동일한 질문·문서·확인 질문·대화 ID의 응답이 불확실하면 같은 요청 ID로 재전송한다. 서버가 이미 저장했어도 모델을 다시 호출하지 않는다. 성공 응답 확인, 새 대화, 문서 삭제 시 ID를 비운다. 문구나 대상이 바뀌면 새 ID를 사용한다. 개인정보를 localStorage에 저장하지 않으며 페이지 재접속 후에는 서버 이력을 확인한 뒤 새로 입력한다. 파일 업로드는 기존 체크섬 중복 방지를 유지한다.

거절된 입력은 구 세션에서 사용자 이력을 복원할 때도 판단 문맥에 넣지 않는다. API 외 직접 호출도 입력을 먼저 마스킹한다. 모델 전송·생성 예외는 원문/traceback 대신 오류 종류만 기록한다. 마스킹은 기존 탐지 범위이며 모든 개인정보를 제거하는 보장은 아니다.

세션 소유권·CSRF·잠금·중복 요청·만료·문서 삭제는 기존 Django 구현을 재사용한다. 상태는 전체 처리가 성공한 뒤에만 반영한다. 정상적인 답변 보류는 실패한 원문 없이 표시·저장되며, 예외로 끝난 요청은 부분 사실·답변을 저장하지 않는다. 회원 모델은 있으나 로그인/회원가입 화면은 아직 연결되지 않았다. 로그인 전후 이력 이전 정책을 이번 패치에서 가정하지 않으며 회원 담당자가 로그인 시 새 상담 생성 또는 명시적 이전 정책을 별도로 연결해야 한다.

검증: Python 전체 1,381개 및 subtest 137개, JavaScript 요청 ID 테스트 5개. 선택적 LangSmith 2개·개인 PDF 1개는 기존 조건으로 미실행이다. 모델 실제 평가와 최종 브라우저 회귀는 PATCH-037에서 수행한다.
