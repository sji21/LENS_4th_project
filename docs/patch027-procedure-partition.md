# PATCH-027 절차 법령 통계 분리·TOP5 결합

절차 법령 5조문을 추가할 때 기존 근거가 밀리는 원인을 분리하고 7개 결합 정책을
비교했다. 어휘 통계를 분리한 뒤 원점수를 같은 가중치로 합치는 `pool_equal`을
코드 후보로 구현했고, 실제 검색 235입력이 저장된 비교 결과와 전부 일치했다.

**운영 데이터 추가 적재는 보류한다.** TOP5의 기존 필수 근거 손실은 0개지만,
DEV-044 질문 입력에서 기존 근거가 3위→4위로 이동한다. 일반 법령 앞의 3개만
사용하는 생성 경로에서는 회귀가 될 수 있다. TOP5 통과를 TOP3 보존으로 보고하지 않는다.

## 범위와 기준

- PATCH-026 `683e9b7`에 이어지는 브랜치다. 작업 시작 때 main은 PATCH-025가 병합된
  `910ae38`이었으며 PATCH-026은 아직 미병합이었다.
- 기존 DB 143조문 = 기존 일반 법령 133 + 민법 10. 후보 DB는 여기에 절차 법령 5조문을 추가한 148조문.
- 추가 대상: 주민등록법 제16조, 국세징수법 제109조·동 시행령 제97조,
  지방세징수법 제6조·동 시행령 제8조. 원문·판본 검증은 PATCH-026 자료를 그대로 사용한다.
- 공개 DEV100 질문 100 + 문맥 포함 100 + 민법 개발 35 = 235입력.
  독립 평가가 아니며, 같은 문항의 질문/문맥 결과를 200개의 독립 표본으로 해석하지 않는다.
- 정답·질문·모델·기존 조문 본문·벡터는 변경하지 않았다. 법률 정답 및 LLM 답변 평가는 하지 않았다.

## 원인 분리

1. 기존 133조문만으로 BM25를 만들고 새 절차 조문을 dense 후보에서도 제외하면,
   기존 일반 법령 TOP5가 235입력 모두 동일하게 재현된다.
2. BM25 통계에는 절차 5조문을 포함하되 검색 후보에서는 제외한 대조군은
   DEV-067 질문 입력의 기존 주택임대차보호법 제4조를 잃는다. 같은 후보·dense 조건에서
   어휘 통계 변화만으로 발생한 손실이다.
3. 통계와 후보 모두에 5조문을 넣은 PATCH-026 혼합안은 6입력에서 기존 필수 근거를 잃는다.
   전체 손실을 통계 변화 하나로 설명할 수 없고 신규 후보와의 경쟁도 함께 작용한다.

## 정책 비교

사전 정의한 7개 정책과 대조군 2개를 같은 순위 추적으로 비교했다. 추가 가중치 탐색이나
문항 ID별 분기는 넣지 않았다. RRF 상수 5·후보 깊이 20·최종 일반 법령 5개를 유지했다.

| 정책 | DEV 완전 확보: 질문 / 문맥 | 기존 필수 근거 TOP5 손실 입력 |
| --- | ---: | ---: |
| 기존 DB | 28 / 30 | 0 |
| 통계만 변경 대조군 | 28 / 30 | 1 |
| 기존 방식에 5조문 혼합 | 34 / 35 | 6 |
| 별도 RRF 후 절차 비중 0.5 | 28 / 30 | 0 |
| 별도 RRF 후 절차 비중 0.75 | 32 / 33 | 6 |
| 별도 RRF 후 동일 비중 | 31 / 29 | 16 |
| 기존 TOP2 유지 + 별도 RRF 동일 비중 | 30 / 29 | 14 |
| 분리 BM25 원점수 통합, 절차 비중 0.5 | 29 / 30 | 0 |
| **분리 BM25 원점수 통합, 동일 비중 (`pool_equal`)** | **29 / 31** | **0** |
| 분리 BM25 원점수 통합, 절차 비중 2 | 34 / 34 | 1 |

완전 확보는 일반 TOP5 + 민법 TOP3에서 모든 필수 목표를 확보한 수다. DEV 각 모드의
전체 100문항 중 고정 목표 채점 대상은 75개이며, 나머지 25개는 목표 미고정/과거 판본 보류다.
후보 데이터의 미보유 문항은 32→23개지만, 자료를 보유하게 되었다고 검색 성공이 되는 것은 아니다.
질문 모드 후보 결과는 완전 확보 29, 보유 후 검색 누락 23, 데이터 부족 23, 별도 분류 25다.
문맥 모드는 각각 31, 21, 23, 25다.

### 일반 법령 순위: 고정 목표 문항 47개

| 입력 | 변경 | Hit@1 | Hit@3 | Hit@5 |
| --- | --- | ---: | ---: | ---: |
| 질문 | 기존 | 15/47 | 22/47 | 24/47 |
| 질문 | 구현 후보 | 15/47 | 26/47 | 29/47 |
| 문맥 포함 | 기존 | 13/47 | 23/47 | 27/47 |
| 문맥 포함 | 구현 후보 | 13/47 | 25/47 | 31/47 |

Hit은 필수 근거 하나 이상을 찾았는지다. 여러 필수 근거를 모두 찾았다는 뜻이 아니다.
기존 TOP1 필수 근거 손실은 0개, TOP3 손실은 DEV-044 질문 입력 1개,
TOP5 손실은 0개다. 평균 Hit@3 상승과 개별 문항 TOP3 회귀는 동시에 발생할 수 있다.

## 구현과 호환성

- 일반 법령의 어휘 검색만 기존/절차로 나눈다. 법령명으로 묶음을 결정하며 질문 ID나
  정답 조문 목록으로 질의를 분기하지 않는다.
- 두 BM25 검색의 원점수를 같은 비중으로 정렬하고, 기존 전역 dense 순위와 RRF로 결합한다.
  각 묶음에 최소 반환 슬롯을 보장하지 않는다.
- `laws` 반환 형식과 일반 TOP5, `civil_laws` 최대 3, 판례·안내 경로는 유지한다.
  dense 호출이나 모델을 추가하지 않는다. DB 스키마·Chroma 컬렉션 추가도 없다.
- 절차 법령이 없는 기존 DB에서는 기존 BM25 클래스를 사용하므로 검색 및 평가 설정 형식이 같다.
- 평가 설정에는 실제 분리 검색기의 묶음별 BM25 값과 분류 법령명을 기록한다.
- 서로 다른 코퍼스의 BM25 원점수는 보정된 확률이 아니다. 이번 자료에서 비교한 정책일 뿐,
  절차 법령이 늘어나도 같은 성능을 보장하지 않는다. 두 묶음 각각의 통계 역시 추가 적재로 변한다.

전체 235입력 중 일반 법령 순위가 달라진 것은 60입력이며, 절차 조문이 반환된 것은 26입력이다.
절차 조문 반환 수 0/1/2/3/4/5개의 입력 분포는 209/19/4/2/1/0이다.
이 수치는 노출량이며 관련성·오답률의 판정이 아니다. 나머지 민법·판례·안내 출력은 실제 검색에서 모두 동일했다.

## 반영 판단

추가하지 않았다. **일반 TOP3를 사용하는 현재 생성 경로까지 무손실이라고 볼 수 없어
