# PATCH-030 · 대화 판단 입출력 계약

판단 LLM은 다음 행동을 제안한다. `chat/dialogue_contract.py`가 그 결과를 검사하며,
실제 실행은 PATCH-032의 허용된 경로에서만 한다. JSON 형식을 통과한 결과를 사실이나 법률 판단의
정확성 보장으로 취급하지 않는다. 기존 검색·생성·법률 검증 함수의 계약은 변경하지 않았다.

## 모델 입력

`build_decision_input()`은 현재 입력, 활성 사용자 진술, 최근 사용자 발화 4개, 주제, 대기 질문,
마지막 상태, 기존 검증 경로를 통과한 공개 답변과 문서 목록만 복사한다. 구 세션에는 사용자 메시지를
이력으로 제공한다. 문서 본문, 거절·보류된 생성문, 정정 감사 이력, 요청 ID, 평가 기대값은 넣지 않는다.
문서 목록은 현재 세션의 ID·종류·표시명이며 문서 속 지시문은 판단 프롬프트로 전달되지 않는다.

## 출력 예시

```json
{
  "intent": "correction",
  "action": "social",
  "topic": "보증금반환",
  "topic_changed": false,
  "updates": {"contract_type": {"value": "월세", "evidence": "월세"}},
  "clarify_field": null,
  "question": null,
  "search_query": "",
  "document_id": null,
  "style": "standard"
}
```

위 예시의 evidence는 현재 사용자 입력에 실제로 있는 직접 인용이어야 한다. 법률 설명이나 문서에서
본 내용이 아니라 사용자가 진술한 값의 출처다. 이전 facts를 매번 출력하지 않고 변경된 값만 제안한다.

| 필드 | 허용 값과 경계 |
| --- | --- |
| `intent` | greeting / question / followup / correction / clarification_answer / explain / topic_change / document_question |
| `action` | social / clarify / rag / refuse |
| `topic_changed` | 명시적 새 상담이면 true, topic_change 의도와 일치해야 함 |
| `updates` | 허용된 사용자 진술 항목의 value·evidence. 활성 상태에 직접 적용하지 않고 검사만 함 |
| `clarify_field` | 진술 항목 또는 details / document. clarify 행동에서는 필수 |
| `question` | 최대 300자의 질문 제안. 신뢰 가능한 공개 답변이 아니며 후속 실행기는 코드가 정한 확인 문구를 사용 |
| `search_query` | 최대 2,000자. rag에서는 비어 있을 수 없음 |
| `document_id` | 현재 세션 문서 ID 또는 null |
| `style` | standard / simple / brief. 생성 단계에 적용하고 최종 법률 검증 전에 처리할 예정 |

초기 사용자 진술 항목은 계약 종류·종료·보증금 반환·거주·퇴거·통지 여부, 상담 대상·역할·물건 종류,
보증금·월세·시작일·종료일·통지일이다. 이것은 발화별 시나리오 분기표가 아니라 저장할 자료의 형식이다.
이 항목으로 판단할 수 없는 질문도 일반 RAG 또는 details 확인 경로를 제안할 수 있다.

## 거부하는 출력과 처리 경계

- 추가·누락·중복 JSON 키, 허용되지 않은 행동, 잘못된 타입, 빈 검색 질문을 거부한다.
- 현재 입력에 없는 인용, 다른 세션의 문서, 정의되지 않은 진술 항목을 거부한다.
- 숫자·단위·복합 금액의 임의 변경과 알려진 명시적 부정의 반전을 검사한다. 금액·날짜 값은 원문
  표현을 보존하며 상대 날짜를 임의의 날짜로 계산하거나 금액을 다른 단위로 바꾸지 않는다.
- social은 인사·정정 확인에만 허용한다. 법률 답변을 담는 자유 생성 필드는 출력 계약에 없다.
- 실패는 원문을 담지 않는 `DecisionError.code`로 구분하고 원래 상태는 변경하지 않는다.
  모호한 판단은 `clarify/details`를 사용할 수 있다. 잘못된 모델 출력의 실제 복귀 실행은 PATCH-032에서 연결한다.

검사는 완전한 한국어 의미 분석기가 아니다. 새 표현·복잡한 조건·인용문 속 주장·명시하지 않은 사실의
추정 등은 실제 모델 평가와 실행 경로의 최종 검증을 함께 적용해야 한다. 질문 제안은 검사를 통과해도
법률 결론을 포함할 수 있으므로 그대로 화면에 내보내는 용도로 사용하지 않는다.

## 검증

JSON·타입·문서·인용·정정·금액·부정·상태 무변경·입력 분리 테스트를 실행한다. 실제 모델 호출은
이 단계에 없으며 PATCH-031에서 같은 출력 계약을 사용해 측정한다.
