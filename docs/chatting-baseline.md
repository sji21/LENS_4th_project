# PATCH-028 · 대화 기준선과 비교 규칙

기준 입력은 PATCH-027의 개발용 12사례·23턴이다. 현재 경로를 먼저 측정하고 기능 구현 후
동일 입력을 새 경로로 실행한다. 최종 수용평가 6사례·12턴은 프롬프트 고정 후 별도로 실행한다.
이 비교는 대화 처리 동작 평가이며 검색/법률 정답률이나 사용자 전체 상황의 대응률이 아니다.

## 실행과 보존

```bash
python -m src.evaluation.chatting_run --mode legacy --split dev --output data/eval/chatting/results/baseline-dev.json
```

출력은 덮어쓰지 않는다. 원시 입력·공개 답변·출처·상태·실제 검색 질문·모델 호출·지연과
오류를 턴별로 저장한다. 예외의 내용과 비밀 환경변수는 기록하지 않는다. 실행기·제품 코드·
시나리오·로컬 청크의 SHA-256, 기준 커밋과 패키지·생성 설정을 보존한다. 미커밋 실행기 역시
파일 해시로 식별한다. 로드된 청크·저장된 벡터·본문·메타데이터·컬렉션 설정도 별도 해시로
식별한다. 종료 시 코드와 자료의 내용이 같아야 완전한 실행으로 처리한다. Chroma가 읽기
중 SQLite/HNSW 파일을 갱신할 수 있으므로 물리 파일 차이는 그대로 기록하며, 실제 벡터를
포함한 내용 동일성을 확인한 경우에만 비의미적 파일 변경으로 구분한다.
로드 시간이 포함된 검색 서비스 준비는 별도 기록하고 사례마다 새 대화를 사용한다.
가상 문서는 추출 후 단계로 주입하므로 이 평가에서 OCR을 측정하지 않는다.

초기 사용자 진술·대기 질문은 두 경로에 같은 의미로 제공한다. 기존 경로에 없는 내부 상태나
의도 출력은 관측 불가로 표시하고 0점과 구분한다. 새 경로의 필수 사실 누락은 실패다.
모델 호출·기술 오류와 실제 검증 보류를 구분한다. 실제 자료·모델 준비 실패를 품질 점수로
간주하지 않고 실행을 고친 후 새 경로에 재기록한다. 출력 라벨은 모델에 제공하지 않는다.

## 변경 전 고정한 통과 기준

- 필수 상태/분기/API 회귀와 개인정보·격리·삭제·검증 우회 방지 테스트가 모두 통과해야 한다.
- 개발용 실제 판단의 행동 일치율 85% 이상, 의도 일치율 75% 이상, 필수 사실 유지 90% 이상을 목표로 한다. 분모와 관측 불가를 함께 공개한다.
- 정정 전 값·다른 상담의 사실·명시적 부정의 반전이 활성 상태에 남는 중대한 오류는 허용하지 않는다.
- 실제 RAG 턴의 검색 질문 의미 보존은 자동 보조 검사 80% 이상과 수동 원문 대조를 함께 사용한다. 동의어로 인한 자동 실패는 원래 결과를 보존하고 별도 사유를 적는다.
- 같은 확인 항목을 반복하는 경우 최대 2회 뒤 일반 안내 또는 불확실성 안내로 전환한다. 사용자에게 같은 질문을 무한히 반복하지 않는다.
- 판단은 원칙적으로 턴당 모델 호출 1회이며 예외·재시도 한도를 명시한다. 최종 개발용 p95 지연은 동일 환경 기준선 p95 + 30초 이내를 목표로 한다. 콜드 스타트·부하 영향은 분리한다.
- 실제 공개 답변에 미검증 법률 본문을 우회 노출하지 않는다. answered 비율 증가 자체를 법률 정확도 향상으로 해석하지 않는다.
- 최종 수용평가에도 같은 규칙을 적용한다. 실패를 감추거나 기준을 낮춰 완료 처리하지 않는다. 평가 결과를 보고 조정하면 해당 재실행은 회귀 확인으로 명시한다.

## 환경과 실행 결과

로컬 실행 환경은 Python 3.11.16, Django 5.2.17, Ollama Qwen3-8B Q4, KURE-v1 1024차원이다.
상세 패키지 버전·모델 digest·임베딩 revision은 원시 결과에 기록한다.

준비 검사에서 로컬 자료가 민법 7개인 반면 최신 코드의 필수 조문은 10개임을 발견했다.
[PATCH-024 절차](patch024-core-law-expansion.md)와 보존된 3개 청크로 로컬 자료를 동기화했다.
보존 원문의 LF를 CRLF로 변환한 해시는 PATCH-024의 원문 해시와 정확히 일치했다.
복사본에서 기존 조문 본문과 민법 7개 벡터 보존, SQLite 무결성, 일반 165개·민법 10개 인덱스와
전체 175개 청크의 ID·본문·메타데이터 일치를 확인한 뒤 반영했다. 새 법령 선택이나 일반 인덱스
재임베딩은 하지 않았다. Chroma의 읽기 초기화에 따른 일반 인덱스 물리 바이트 변경은
[로컬 준비 기록](../data/eval/chatting/results/local-preparation.json)에 공개한다.
백업은 `tmp/chatting-evaluation/civil-sync-v2/before/`에 있으며 Git 제외 대상이다.

초기 sandbox 연결 실패, 계측 검토 중단, 민법 7개 상태의 부분 실행은 유효 기준선에서 제외했다.
각 부분 결과는 로컬 `tmp/chatting-evaluation/`에 이유와 함께 보존했다. 모델 연결·응답 읽기 실패,
잘못된 모델 JSON, 어휘 검색으로의 복귀, 필수 조문 누락을 정상 품질 결과로 처리하지 않는 검사를 추가했다.

실제 실행은 [baseline-dev.json](../data/eval/chatting/results/baseline-dev.json)에 보존했다.
23턴이 모두 완료됐고 실행·모델 통신 오류는 0건이다. 실행 전후 제품·평가 코드, 원문,
벡터·본문·설정, 물리 인덱스 파일, Ollama 모델 digest가 모두 같았다.

Ollama 0.33.0과 실제 모델·자료 식별은 원시 파일을 기준으로 비교한다.

### 원시 답변 검토

- DEV-001: 인사·서비스 안내 요청에도 법률 검색·검증을 거쳐 보류한다. 대화 분리의 개선 대상이다.
- DEV-003: 계약 종료 여부에 대한 사전 질문 뒤의 `네.`를 독립 질문으로 처리해 범위 밖으로 거절한다.
- DEV-004 2턴: 계약 형태의 정정을 기존 보증금 반환 상담에 연결하지 못하고 보증금의 월세 전환에
  관한 별도 질문처럼 답한다. `answered` 상태만으로 대화의 적합성을 판단할 수 없는 사례다.
- 같은 턴의 금지어 검사 실패는 `전세가 아니라 월세`의 부정 문맥에 있는 `전세`를 검출한
  문자열 검사의 거짓 실패다. 원시 8/9 점수는 보존하며, 계약 형태의 반전으로 판정하지 않는다.
- DEV-007의 쉬운 설명 요청과 DEV-010·011의 보류 후 후속 요청에서는 실제 검색 질문에서
  원래 주제를 누락했다. DEV-009의 `모름`도 대기 질문의 답으로 연결하지 못하고 거절했다.

법률 내용의 정확성은 이 대화 지표가 판정하지 않는다. 기존 검증을 통과한 답변에도 관련성·조건
설명을 별도로 확인해야 하며, 법률 검증 정책 변경은 이번 대화 관리 패치의 구현 범위에 포함하지 않는다.
