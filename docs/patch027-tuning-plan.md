# PATCH-027 리트리버 튜닝 계획서

작성일: 2026-09-13
상태: 리뷰 보완·1~4단계 개발 검증 완료, 운영 미채택 — [결과서](patch027-context-tuning-result.md)
담당: 리트리버 담당(sji21·Codex)
근거: [개념 확장 실험 결과](patch027-concept-tuning.md), [전체 적재·순위 비교](patch027-law-expansion.md)

### 리뷰 후 재실행 조건 (2026-09-13, 결과 확인 전 고정)

- 기존 43/75·42/75는 검토 전 순위 재조합 결과이며 실제 서비스 통합 완료로 표현하지 않는다.
- 준용 관계는 민법의 정확한 조문·같은 현행 판본·직접 준용 문장으로 한정하고, 결과 검증에서도 원문에서 관계를 다시 추출한다.
- 부정·인용·다른 문장에 흩어진 통지 표현을 연결하지 않는다. 모호하면 확장을 보류한다. 공공임대의 일반적인 임대사업자 표현은 등록민간임대로 자동 확장하지 않는다.
- 첫 보완 실측에서 발송 부정과 도달 실패가 함께 차단되는 것을 확인했다. 두 번째 실행 전, 부정 조건을 통지·발송·법적 목적을 부정한 표현에만 연결하고 이미 발송한 우편의 전달 실패는 유지하도록 정정한다. 조합·정답·순위 선택·채택 기준은 유지한다.
- 기존 검토 후보 `context_both + context_reference`를 재측정 전에 고정한다. 새 결과를 보고 최종 조합·가중치·정답·슬롯·채택 기준을 바꾸지 않는다.
- 실험용 `RetrievalService` 하위 클래스로 원질문을 받아 새 BM25·KURE 검색, 주제 선택, 준용 보충, Evidence 반환을 실행한다. 저장 순위나 정답을 검색기의 입력으로 사용하지 않는다.
- 미튜닝 후보와 실험용 검색기를 235입력씩 새로 호출한다. 재조합 순위와 실검색 순위·원문 해시·출처·채널·개수를 비교하고 판례·안내도 새로 검색해 대조한다.
- 질의 캐시를 입력/검색기마다 비우고 임베딩 요청·실제 모델 호출·지연을 측정한다. 추가 호출0은 가정하지 않는다.
- 전체 실행 코드·설정·의존성 해시를 검색 전에 저장하고 종료 때 대조한다. clean 커밋 결과를 공유하며 운영 검색 코드·DB·인덱스는 바꾸지 않는다.

## 1. 목표

**새로 적재한 법령을 더 잘 찾으면서, 기존에 찾던 필수 근거를 잃지 않는 검색 방식을 정한다.**

민법의 검색어 확장은 효과가 확인됐다. 다음에는 확장어를 더 늘리기보다 잘못 발동하는 문맥과 함께 찾아야 하는 근거를 보완한다. 일반 법령은 기존 결과를 무조건 고정하는 대신 새 근거와 기존 근거의 순위 경쟁을 다룬다.

선정·후보 적재·튜닝·평가·분석은 **PATCH-027 하나**에서 이어간다. 실험마다 새 패치 번호를 만들지 않는다. 법적 정답이나 LLM 답변 품질을 개선했다고 주장하는 작업은 아니다.

## 2. 현재 확인한 사실과 비교 기준

| 기준 | 용도 | 현재 상태 |
| --- | --- | --- |
| 운영 기준선: 143조문 | 데이터 확대 전 잘 찾던 근거가 보존되는지 확인 | DEV 완전 확보 질문28/75·문맥30/75 |
| 미튜닝 후보: 204조문 | 추가 적재 효과와 튜닝 효과를 분리 | 완전 확보32/75·34/75, 기존 반환 근거 손실16입력 |
| 민법 BM25만 확장한 후보 | 다음 민법 튜닝의 출발점 | 민법 Hit3 질문20/32·문맥18/32, 신규7조문 확보, 미튜닝204조문 대비 새 반환 근거 손실0 |
| 민법 BM25+KURE 양쪽 확장한 후보 | 더 높은 검색 성능을 보인 비교 대상 | 민법 Hit3 23/32·20/32, 신규8조문 확보, 미튜닝204조문 대비 새 반환 근거 손실2입력 |

민법 후보의 수치는 일반 법령을 미튜닝204조문 결과로 고정한 비교다. 일반 법령도 양쪽 확장에서 Hit3가 질문28→32/47·문맥28→33/47로 올랐지만, 운영 기준선의 일반 TOP3 근거 손실9입력이 남았다.

주의할 구분:

- **Hit3**: TOP3에 필요한 근거가 하나 이상 있는가.
- **완전 확보**: 그 문항의 고정 필수 조문을 전부 반환했는가.
- **신규8조문 확보**: 신규 필수9조문 중8개가 해당 입력의 TOP3에 등장했다는 뜻. 모든 관련 문항이 완전 성공했다는 뜻은 아니다.
- **새 손실0**: 어떤 비교 기준 대비인지 반드시 붙인다. 미튜닝204조문 대비0이어도 운영143조문부터 남은 손실이 해결됐다는 뜻은 아니다.

## 4. 작업 순서

### 1단계 — 민법 확장의 문맥 오인 줄이기

**문제:** 수리를 알리는 문자까지 ‘의사표시 도달’로 확장해 수리비 근거가 밀렸다.

민법 BM25만 확장한 후보를 대조군으로 두고, 다음 두 대안까지 비교한다.

1. **문맥을 좁힌 BM25 확장:** 연락 수단만 보고 발동하지 않고, 무엇을 통지하는지 함께 확인한다. 일반 수리 연락과 계약 종료·갱신·보증금 반환 요구 등의 맥락을 구분한다.
2. **선택적 KURE 확장:** 같은 문맥 조건이 충분히 확인될 때만 KURE 질의에도 개념을 붙인다. 불명확하면 KURE에는 원질문을 사용한다.

같은 문장 안에서 대상·행위를 연결하고, 부정된 말·인용된 말·이전 대화의 사실을 무조건 현재 요청으로 취급하지 않는지 점검한다. 명확하게 처리할 수 없는 경우 확장을 보류한다. 법적 효력 발생 여부를 리트리버가 판정하지 않는다.

규칙 검증에는 수리 연락, 계약 종료 통지, 우편 반송, 일반 귀가, 같은 표현의 부정·인용·주체 변경을 포함한다. DEV 번호나 질문 전문을 선택 조건으로 쓰지 않는다.

**확인할 결과:** 수리비 근거 회귀가 줄었는지, 대조군의 신규7조문 확보와 기존 반환 근거가 유지되는지, KURE 확장의 추가 이득이 있는지. Hit3의20/32·18/32는 개발상 유지 목표로 삼고, 두 번째 대안의23/32·20/32는 비교값이지 보장값으로 삼지 않는다.

### 2단계 — 준용 조문을 함께 찾는 방법 검토

**문제:** 원상회복 관련 제615조는 찾지만 이를 임대차에 연결하는 제654조는 TOP3에서 빠진다.

대조군에 **원문에서 확인되는 조문 연결을 후보로 보충하는 대안1개**를 비교한다.

- 법령명·조·가지번호가 정확히 확인되는 직접 참조만 사용한다. 번호가 같다는 이유로 다른 법령을 연결하지 않는다.
- 준용 본문과 연혁 주석·단순 인용을 구분한다. 적용 판본이 다르거나 참조 대상이 없으면 연결을 확정하지 않는다.
- 참조하는 조문과 참조받는 조문을 구분해 기록한다. 최초에는 민법 내부의 직접 연결1단계만 대상으로 하고, 후보 보충은 최대2조문으로 제한한다.
- 추가 후보가 실제 질문과 관련 있는지는 다시 검색 순위로 평가한다. ‘615를 찾으면654를 무조건 반환’하는 질문별 예외나 고정 정답 규칙은 만들지 않는다.
- 후보 단계와 최종 TOP3를 각각 확인한다. 함께 필요한 두 조문을 선택하면 실제로2칸을 사용한 것으로 세며, 한 칸으로 묶어 반환 제한을 우회하지 않는다.

**확인할 결과:** 제654조가 후보에만 들어온 것인지, 제615조와 함께 최종3개 안에 들어온 것인지 구분한다. 두 근거를 넣느라 기존 필수 근거를 잃지 않는지235입력으로 확인한다. 직접 연결이 검색 관련성을 보장하지 않으면 자동 동반 반환은 채택하지 않는다.

### 3단계 — 일반 법령의 신규 근거와 기존 근거 균형 조정

**문제:** 새 절차법 근거가 올라오면서 필요한 임대차 근거가 밀린다. 반대로 기존 TOP3를 고정하면 새 법령이 TOP3에 들어올 수 없다.

미튜닝204조문을 대조군으로 두고, 일반 법령의 기존 `both`와 `blend` 방식에 **문맥을 좁힌 동일한 확장 조건**을 적용한 두 대안을 우선 비교한다. 둘 사이에서는 질의 규칙을 같게 두고 결합 방식만 비교한다.

- 확정일자 부여·열람 절차와 보증금 보호 효과처럼 다른 요청을 구분한다. 절차 단어가 있다는 이유로 보호 근거를 제거하지 않는다.
- 주택·상가·공공임대·등록민간임대의 명시적 사실을 확인한다. 혼합·불명확한 질문을 한 종류로 단정해 근거를 제외하지 않는다.
- 순위가 바뀐 입력마다 어떤 확장어가 기존 근거를 밀었는지 기록한다. 영향이 없는 문항에까지 새 예외를 추가하지 않는다.
- 기존 TOP3 고정은 회귀 원인을 확인하는 참고 대조군으로만 두고, 손실0이라는 이유로 최종안에 채택하지 않는다.

**확인할 결과:** 신규 절차 근거의 확보를 유지하면서 운영 기준선의 TOP3·TOP5 손실이 줄어드는지 확인한다. Hit3 32/47·33/47은 현재 개선 후보의 비교값으로 함께 공개한다. 전역 가중치를 반복 탐색하거나 반환 슬롯을 늘리는 방식은 이번 단계에서 제외한다.

### 4단계 — 두 채널을 합친 실제 검색 검증

앞 단계에서 남길 후보를 각각1개씩 정하고 조합·설정을 기록한 뒤 전체235입력을 새로 실행한다. 각 채널에서 좋았던 수치를 단순 합산하지 않는다.

실험 도구의 재조합 결과와 실제 리트리버의 반환 순위·원문·출처가 일치하는지 확인한다. 판례·안내는235입력 모두 기존 결과와 대조한다. 적재 사본을 사용하며 운영 DB는 채택 결정 전에 교체하지 않는다.

## 5. 평가와 채택 기준

각 실험은 **운영143조문, 미튜닝204조문, 직전 단계 대조군**을 별도로 비교한다. 결과 표에는 기준 이름을 적어 손실 기준이 섞이지 않게 한다.

| 확인 항목 | 기록 방식 |
| --- | --- |
| 검색 성공 | 일반 Hit1·3·5, 민법 Hit1·3. 질문·문맥 별도 집계 |
| 필수 근거 전체 확보 | DEV 각75문항의 완전 확보 및 근거별 Recall |
| 신규 조문 | 고유 조문 수, 해당 입력 수, 최종 반환/후보만 확보 여부 구분 |
| 회귀 | TOP3 밖으로 밀림, TOP5 밖으로 밀림, 민법 TOP3 손실을 구분. 해당 입력과 근거 목록 공개 |
| 정보 부족·범위 | 고정 정답 없는23문항·과거 판본 보류2문항, CIV35의 별도 범위1·진단5를 성공률에 임의로 합치지 않음 |
| 검색 비용 | 같은 장비의 질의 임베딩 호출 수·검색 지연·추가 후보 수. 기능 점수와 별도 보고 |

**기존 최종 채택 기준은 유지한다.**

1. 운영143조문 대비 일반 TOP3와 실제 반환 범위(일반5+민법3)의 기존 필수 근거 손실0.
2. DEV 완전 확보가 미튜닝204조문의 질문32/75·문맥34/75 이상.
3. CIV35 고정 필수 완전 확보28/29 이상·민법 Hit3 29/29 유지.
4. 판례·안내 결과 보존, 원문·출처·채널·개수 제한 유지, 실제 검색 재현 및 관련 회귀 테스트 통과.

점수 한 개만 통과해서는 채택하지 않는다. 신규 문항의 성공을 얻는 대신 다른 필수 근거를 잃는 경우도 그대로 공개한다. 단계 대조군보다 좋아진 것은 ‘개발 개선 후보’, 위 기준과 실제 통합 검증까지 통과한 것은 ‘운영 반영 후보’로 구분한다. 기준 변경이 필요하면 결과를 본 뒤 소급 적용하지 않고 이유와 새 기준을 별도 합의한다.

## 6. 실험 규모와 중단 조건

- 첫 회차는 민법 문맥2대안, 준용 연결1대안, 일반 법령 문맥·결합2대안, 최종 조합1개 이내로 제한한다. 대조군은 별도다.
- 한 실험에서 질의 확장·선택 방식·가중치를 동시에 바꾸지 않는다. 독립 비교 후 통합한다.
- 효과가 없거나 회귀가 커지면 같은 계열 실험은 원인에 근거한 수정1회까지만 추가한다. 수정 이유·규칙·기준을 다음 실행 전에 기록한다.
- 추가 수정에도 실패하면 그 방식을 보류하고 원인과 대안을 보고한다. 모델 교체·재랭커·LLM 질의 변환·DB 재구축을 자동으로 시작하지 않는다.
- 필수 근거 검토 자체에 의문이 생기면 정답 검토 역할에 근거 확인을 요청할 대상으로 분리한다. 구현자가 검색 결과에 맞춰 정답을 고치지 않는다.

## 7. 산출물과 완료 모습

PATCH-027 문서와 한 실험 목록에서 다음을 관리한다.

1. 실행 전 가설·대조군·변경 요소·후보 수·판정 기준.
2. 실행 커밋, 모델·데이터·설정 해시, 같은235입력의 검색 순위와 원문 식별자.
3. 전후 점수, 신규 확보, 기존 손실, 비용, 채택/미채택 이유.
